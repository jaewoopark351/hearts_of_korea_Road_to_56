# 한국 주 분할과 산업 건설 공간 설계

**2026-11-10 지역 공업 투자 후속.** 평안·충청·경상 사업의 주별 해금·조건·보상 또는 기존 투자 저장을 다룰 때는 [14절의 남북도별 설계와 적용 기록](#14-2026-11-10-남북도별-지역-공업-투자-설계)을 먼저 읽는다.

**2026-11-10 고속도로·지방 개발 보상 후속.** 경부·경의고속도로의 기반시설과 북부·남부·중부지방 개발의 건설 슬롯을 조정할 때는 [13절의 주별 보상표와 검증 기록](#13-2026-11-10-고속도로와-지방-개발-보상-조정-계획)을 먼저 읽는다. 소스에 반영했다.

**2026-11-08 참조 코드 후속:** 현재 15주 지도를 유지한 채 주·프로빈스 참조를 수리하거나 최신 분할의 회귀와 기존 오류를 구분할 때는 [현행 지도 기준 코드 정렬 계획](HOK_STATE_REFERENCE_ALIGNMENT_PLAN.md)을 먼저 읽는다. 코민테른 접경 목록·설명 동기화, 이전부터 있던 영토/부모 불일치, 바닐라 공유 항목과 보류 후보를 구분한다. 최초 문서화 이후 별도로 구현이 승인됐으며, 현재 적용·신규 실행과 검증 한계는 [정렬 구현 기록](incidents/2026-11-08-state-reference-alignment.md)을 따른다. 아래 주 분할 당시의 검증과 혼합하지 않는다.

작성: **2026-11-07 (Asia/Seoul)**. 후속 상태: **6도 분할 소스 적용 완료 / 1936·옵션·보상·취소·반복·슬롯 핵심 검증 완료 / 실제1939·화면·저장 재로드 미검증**. 현재 소스와 실제 검증 범위는 [구현 기록](incidents/2026-11-07-korean-state-split-implementation.md), 확정 프로빈스·수치 배분은 [기계 판독 대응표](data/HOK_KOREAN_STATE_SPLIT_MAPPING.json)를 따른다.

**2026-11-08 후속 구현:** 「국토개발종합계획」의 옛 도 단위7개 사업을 남북도별로 개편하거나 비용·보상·완료 기록을 이전할 때는 [남북도별 국토개발 사업 개편안](HOK_KOREAN_CNDP_STATE_DEVELOPMENT_PLAN.md)을 먼저 읽는다. 이후 사용자가13개 독립 사업 구현을 승인했다. 새 게임은 주별13개·각75PP/민공5/90일(강원150/5/180), 기존 저장은 구형7개를 유지하는 안으로 구현했다.1936 기간 만료·소유/부분 통제 상실 취소·재착수의 핵심 실행을 확인했고 화면·저장 재로드·1939는 미검증이다. 최신 적용·실행 범위는 위 개편안과 그 구현 기록을 따르며, 아래 주 분할 검증을 새13개 검증으로 사용하지 않는다.

한국의 장기 산업 성장 공간을 확보하기 위해 충청·전라·경상·평안·황해·함경을 남북 두 주로 나누는 안을 검토한다. 여섯 도를 모두 분할하면 한국은 현재 9주에서 15주가 된다. 권장 방향은 **기존 프로빈스와 기존 주 ID를 최대한 보존하고, 도별 분할과 지역 참조 이전을 하나의 작업 단위로 검증하는 것**이다. 중점의 배치와 선행 연결은 유지할 수 있지만, 지역 조건·보상·영토 이전·내전 구도는 별도의 의미 매핑이 필요하다.

최초 요청은 깊이 검토한 문서화만이었고 그 단계에서는 게임 코드·시험·Git 상태를 바꾸지 않았다. 이후 사용자가 이 계획의 여섯 도 전체 구현을 명시적으로 요청했다. 아래의 제안·미실행 목록은 최초 설계와 검증 계획을 보존한다. 후속 구현 승인에는 시작 산업 규모 개편, 변경 전 저장 마이그레이션, 커밋·푸시·업로드가 포함되지 않는다.

최초 설계의 증거 등급은 **CONFIRMED — 읽은 소스의 설정·참조 관계**, **UNPROVEN — 당시 미조사 경계와 미실행 결과**였다. 이후 확정·실행한 항목은 구현 기록에서 별도로 구분하며, 원래 계획의 문구만으로 검증 완료를 주장하지 않는다.

## 2 슬롯 문제와 대안

### 서로 다른 세 가지 제한

설치 원본 `common/defines/00_defines.lua:757`의 공유 슬롯 상한 설정은 **25**다. 민공·군공·조선소와 다른 공유 슬롯 건물이 같은 공간을 사용한다. 설치 원본 `common/buildings/00_buildings.txt:55–80, 226–239`에는 민공·군공·조선소 각각 **주별 유형 상한 20**도 있다. 공유 슬롯 25와 유형별 20은 다른 제한이다.

기본 해금 슬롯은 주 카테고리에 따라 정해진다. 따라서 카테고리를 올리거나 추가 슬롯을 주는 것만으로 공유 상한 25를 없앨 수 있다고 가정하지 않는다. 25는 현재 설정값이며 수정 불가능한 하드코딩으로 표현하지 않는다. 강제 효과가 상한을 넘는 경우의 엔진 처리나 UI 지원은 이번에 관측하지 않았다.

| 대안 | 해결 범위 | 주요 영향 | 판단 |
|---|---|---|---|
| 현재 9주의 카테고리·추가 슬롯 조정 | 시작 공장 배치와 기존 상한까지의 성장 공간 | 지역별 슬롯 재설계 | 시작 배치에는 유효하지만 산업 중심지의 25개 포화를 해소하지 못함 |
| 공유 상한과 필요한 건물별 상한 조정 | 기존 주에서 더 높은 밀도 허용 | 전역 설정·다른 국가·UI·다른 모드와의 상호작용 | 한국에만 공간을 늘리려는 목적과 별도로 비교할 대안 |
| 일부 산업 중심 도만 분할 | 선택한 지역의 공간·점령 단위 확대 | 분할한 도와 연결된 콘텐츠 이전 | 제한된 범위의 단계적 도입 후보 |
| 제안한 여섯 도 모두 분할 | 한국 9주→15주 | 지도와 지역 콘텐츠 전반의 이전 | 장기 확장 후보. 아래 절차로 범위와 보존 기준을 먼저 확정 |

분할 필요성은 국가 전체 공장 수와 함께 **지역별 성장 공간**으로 판정한다. 각 도에서 시작 공장·다른 공유 건물·선택 가능한 한 정치 경로의 중점 보상·목표 연도까지의 반복 투자·직접 건설 예산을 합산하고, 그 시점의 해금 슬롯과 25개 상한을 비교한다. 서로 배타적인 모든 중점 보상을 한꺼번에 더하지 않는다. 산업 거점 분산과 기존 주의 슬롯 조정으로 해결되는 도까지 자동으로 분할할 필요는 없다.

따라서 조사 우선순위는 산업·항구·지역 보상이 집중되는 도로 잡고, 여섯 도 전체안은 지역별 공간과 지도 구획의 목적을 함께 검토해 채택한다. 여섯 도라는 후보 수를 반드시 채워야 하는 개발 할당량으로 사용하지 않는다.

단순 계산으로 9주의 공유 슬롯 상한 합계는 225, 15주는 375다. 이는 모든 주가 상한까지 해금된다는 가정의 **공유 슬롯 총량**이며, 시작 슬롯·즉시 사용 가능한 공장 수·실제 생산량이 아니다. 다른 공유 건물도 공간을 사용한다. 여섯 도를 나눠 생기는 이론상 150칸을 시작 공장 150개 지급으로 해석하지 않는다.

주 수가 늘어도 카테고리를 낮게 설정하면 실질 공간은 충분히 늘지 않을 수 있다. 지역별 초기 해금 슬롯, 산업 기술에 따른 공간, 기존 중점·디시전의 추가 슬롯, 1939·1941년 성장 목표를 함께 설계한다. 주 분할도 주당 25개 상한 자체를 제거하는 방법은 아니다.

### 산업 수치와 지도 변경을 분리

사용자가 제시한 민공 28·군공 20·조선소 11의 총 59개는 산업 기준안이고, 대화에서 제시한 32·20·16의 총 68개는 별도 설계 추정이다. 어느 쪽도 이 문서로 적용하거나 2026년 경제 통계에서 계산된 확정 환산값으로 선언하지 않는다. 먼저 지도 이전으로 기존 공장·인구·자원 총량을 보존하고, 시작 산업 증가는 승인된 별도 변경으로 기록하는 방식을 권장한다.

## 4 경계와 ID를 결정하는 원칙

### 경계 기준

먼저 1936년 행정구역 복원, 현대 지명에 따른 산업권 구분, 현행 프로빈스에 맞춘 게임용 근사 경계 중 어느 기준을 사용할지 정한다. 황해도는 1954년 10월에 남북도로 분리됐으므로 황해 남북 분할까지 포함한 15주안은 1936년 행정구역의 단순 복원이 아니다. 이 부분은 대체역사적 행정·산업 구획 선택으로 명시한다. 근거는 [한국민족문화대백과사전 황해도](https://encykorea.aks.ac.kr/Article/E0065385)의 역사·내용 요약이다.

각 도의 현재 프로빈스를 지도 위에서 대조한 뒤, 하나의 프로빈스를 쪼개지 않고 두 후속 주에 배정할 수 있는지 판정한다. 현재 소스에는 경상 1030의 프로빈스 17개가 정의돼 있지만, 이것만으로 실제 남북 경계 구현 가능성이 입증되지는 않는다. 현대 지도상의 직선을 게임 프로빈스 목록으로 추정하지 않는다.

**우선안은 기존 프로빈스만 재배정하는 분할**이다. 경계 근사로 목적을 달성할 수 없다면 해당 도의 새 프로빈스 생성은 별도 지도 작업으로 명세한다. 이때 비트맵·RGB·정의·지형·인접·위치 데이터까지 범위가 넓어지므로, 이번 주 분할안에 자동으로 포함하지 않는다.

### 기존 ID와 새 ID

각 기존 ID는 두 후속 주 중 한 곳에 유지한다. 다른 한 곳에만 새 ID를 부여하며 기존 9주·쓰시마·바닐라의 ID를 전체 재번호하지 않는다. 기존 ID를 항상 북도에 남기는 일괄 규칙도 두지 않는다. 도시·자원·항구·반복 사업·영토 조건의 참조를 비교한 뒤 유지 대상을 결정한다.

경상 1030을 포항이 포함된 경북에 유지하는 안은 최근 포항 사업의 보상 대상을 보존하는 후보가 된다. 그 경우 부산 보상과 항구의 부모 scope는 경남으로 이전하되, 기존 경상 전체의 소유·통제 조건은 두 후속 주를 함께 검사하도록 보존한다. 반대로 1030을 경남에 남기면 포항 보상 대상을 옮긴다. 어느 선택도 모든 기존 참조를 자동 보존하지 못한다. 나머지 다섯 도도 같은 방식으로 판정한다. **어느 후속 주가 기존 ID를 유지할지는 아직 확정하지 않았다.**

읽기 검색에서 설치 원본의 최대 state 선언은 1081, 저장소의 최대 선언은 쓰시마 1085였다. 쓰시마는 [현행 파일](<../history/states/1085 - Tsushima.txt>)에서 province 10011과 기존 이름 키 `STATE_1088`을 사용한다. 이름 키의 숫자를 근거로 주 ID를 다시 바꾸지 않는다.

새 6개 ID는 구현 직전 목표 버전·실제 모드 순서·유효 정의를 다시 확인하고 중복·번호 공백·최대값을 검토한 뒤 확정한다. 과거 재구성 문서의 1085–1088 표나 비어 보이는 숫자를 예약 번호로 사용하지 않는다. 이전 정렬에서 ID 구멍이 발생한 경위는 [후속 정렬 구현 기록](incidents/2026-09-01-china-japan-vanilla-alignment-implementation.md)의 별도 이력으로 남아 있다.

새 ID의 배정 순서와 도별 적용 순서를 맞춰 시범 단계에도 번호 공백이 생기지 않도록 한다. 중간 단계의 전체·부분 영토 목록은 그때 실제로 생성된 후속 주만 포함한다. 최종 15주 목록을 미리 넣어 미생성 주를 참조하거나 번호를 채우기 위한 빈 주를 만들지 않는다.

### 구현 전에 고정할 대응표

도별로 기존 ID·유지할 ID·새 ID·후속 이름·프로빈스 목록·경계 기준·도시와 항구·1936 및 1939 소유 이력·카테고리·보상 이전 대상을 한 표로 고정한다. 각 기존 주의 프로빈스 집합은 두 후속 주의 합집합과 같아야 하고 두 집합의 교집합은 없어야 한다. 대체역사적 경계 선택과 불가피한 근사는 근거를 함께 남긴다.

최종 대응표는 이 문서의 후속 절 또는 `docs/data/HOK_KOREAN_STATE_SPLIT_MAPPING.json` 같은 유지할 설계 자료에 기록하고 본문에서 연결한다. 원래 값·두 후속 주의 값·합계 대조와 의미별 참조 이전 근거를 함께 남긴다. 이 경로는 향후 산출물 제안이며 이번에는 별도 데이터 파일을 만들지 않았다.

기존 프로빈스 geometry를 보존한다면 `provinces.bmp`, `definition.csv`, 고도·지형·강·해안 비트맵은 원칙적 보존 대상이다. `map/railways.txt`, `map/supply_nodes.txt`, `map/unitstacks.txt`, 전략 지역 186의 프로빈스 참조도 주 수 증가만을 이유로 바꾸지 않는다. 예를 들어 보급 노드의 13418·13424·13436은 프로빈스 ID다. 다만 실제 보급·건물 표시·주 기반 수용량은 분할 후 다시 확인해야 한다.

## 6 조건과 보상을 의미별로 이전

### 공통 분류

참조는 파일별이 아니라 **각 조건·효과 블록별**로 분류한다. 같은 중점 안에서도 영토 조건은 옛 도 전체, 보상은 특정 도시, 건설 가능성은 보상 대상 주를 뜻할 수 있다.

| 의미 | 기본 이전 원칙 |
|---|---|
| 도시·항구·자원 거점 | 해당 프로빈스가 속하는 한 후속 주에 보상을 연결 |
| 옛 도 전체의 소유·통제 | 원래 지리적 범위를 두 후속 주의 집합으로 보존 |
| 옛 도 전체의 고정 수량 보상 | 원래 총량을 정해진 후속 주들에 배분. 두 곳에 같은 묶음을 복제하지 않음 |
| 한국 전체·부분 영토 집합 | 원래 목록에 들어간 도의 후속 주만 확장. 기존 예외 유지 |
| 임의 적격 주·우선 배치 주 | 기존 적격 조건·우선순위·지급 횟수 보존. 후보 증가에 따른 선택 편향 검토 |
| 국가 전체 순회 효과 | 주별 지급·판정 횟수가 증가하는지 검토. 국가 총량과 주별 효과를 구분 |

기존 1030 소유·완전통제 조건을 경북 한 주만 검사하도록 바꾸면, 경남을 잃어도 사업을 쓸 수 있게 되는 의미 변화가 생긴다. **영토 범위 보존안에서는 두 후속 주를 함께 검사**하고, 보상은 포항이 있는 한 주에 준다. 포항 지역만 통제하면 되도록 완화하는 안은 별도 게임플레이 변경으로 명시한다. 슬롯·해안·건물 수 조건은 실제 보상을 받을 후속 주에서 검사해야 하며 이를 영토 조건과 일괄 처리하지 않는다.

## 7 산업 성장과 게임플레이 변화

### 슬롯과 보상의 합계

각 후속 주에 시작 공장, 다른 공유 건물, 중점 지급, 반복 투자, 직접 건설이 차지할 공간을 따로 계산한다. 국가 합계가 맞더라도 포항·부산·평양 등 특정 거점에 보상이 몰려 25개에 먼저 도달할 수 있다. 유형별 20개 제한도 함께 확인한다.

기존 슬롯 추가 보상은 두 후속 주에 배분해 총량을 보존하는 것을 기본으로 한다. 신규 기본 슬롯 증가는 주 분할의 의도된 변화로 별도 수치화한다. 상한 때문에 보상이 생략되는 상황을 숨기거나 효과 없는 보상을 정상 지급으로 기록하지 않는다. 슬롯이 꽉 찼을 때 사업이 차단되는지, 다른 지역으로 옮기는지, 추가 슬롯을 주는지는 원래 정책과 새 설계를 대조해 확정한다.

현재 일부 개발은 주 카테고리를 절대값으로 설정한다. 예를 들어 충청 개발은 `large_town`으로 바꾼다. 새 시작 카테고리를 더 높게 설정한 뒤 이를 유지하면 개발 완료가 기본 슬롯을 줄일 수 있다. 기존 카테고리 변경 보상과 새 초기 슬롯 설계의 충돌을 먼저 해결해야 한다.

포항·강원 반복 자원 사업은 완료 시 자원만 추가하므로 공장 슬롯 증가 사업과 구분한다. 새 주가 생긴다고 비용·기간·보상·AI를 바꾸거나 사업 두 개로 복제하지 않는다. 자원이 한쪽에 집중되면 기반시설·채굴 보정에 따른 최종 채굴량이 달라질 수 있으므로 기본 자원 총량과 실제 채굴량도 구분한다.

### 주 수 자체가 만드는 변화

주 분할은 기존 총량을 보존해도 점령·저항·해방·내전·건설·공군기지 배치·임의 주 선택의 단위를 바꾼다. ‘공장 총량 보존’을 ‘게임플레이 완전 동일’로 표현하지 않는다. 특히 국가 전체를 순회하며 주마다 보상을 주는 효과와 임의 주 추첨은 새 주 수에 영향을 받는다.

기반시설 레벨을 양쪽에 유지하면 각 지역의 초기 보정은 이어갈 수 있어도 향후 두 주를 각각 건설해야 하는 비용이 생긴다. 공군기지 수용량을 양쪽에 통째로 복제하면 총량이 늘어난다. 이런 차이를 도별 배분표에 기록해 슬롯 확장에 수반되는 변화와 별도 밸런스 변경을 구분한다.

기존 프로빈스만 재배정하는 안은 **중상 난도의 지도·콘텐츠 통합 작업**으로 평가한다. 주 파일 작성보다 참조의 의미 판정과 실제 경로 검증의 부담이 크다. 새 프로빈스 생성까지 필요하면 지도 비트맵과 연결 관계를 다루는 고위험 작업이 추가된다. 경계 조사 전에는 파일 수·작업 시간을 확정 견적으로 제시하지 않는다.

## 10 세이브와 외부 콘텐츠 정책

기존 주 ID를 한쪽에 남겨도 추가 주와 프로빈스 소속이 바뀌므로 기존 저장 호환을 보장하지 않는다. **기본 구현 후보는 새 게임용 지도 변경**으로 안내하고, 이를 기존 저장도 계속 쓸 수 있다는 의미로 설명하지 않는다. 기존 저장 지원을 요구하면 대표 변경 전 저장의 로드·진행·재저장·재로드와 필요한 마이그레이션을 별도 범위로 설계한다. 새 저장 재로드 성공은 변경 전 저장 호환 증거가 아니다.

한국 주를 참조하는 번역·호환 모드·다른 국가 콘텐츠도 확인한다. 새 이름 키와 기존 이름 키의 override를 구분하고, 현지화만 바뀌었다고 영토 조건까지 이전된 것으로 보지 않는다. state ID 기반 하위 모드에는 적용 버전과 변경 대응표가 필요하다.
