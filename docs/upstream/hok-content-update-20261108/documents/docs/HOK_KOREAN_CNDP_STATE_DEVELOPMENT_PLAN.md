## 4 비용과 병행 실행 — 확정 전 예시

기존150·5·180을 남북에 그대로 복제하면 옛 도 하나의 전체 개발 부담이 정치력300과 민공1,800일이 된다. 민공일은 **점유 공장 수×사업 일수**이며 실제 건설 생산량의 동등성을 뜻하지 않는다.

| 비교 | 현재 광역 사업 | 남북에 그대로 복제 | 부담 보존 예시 |
|---|---:|---:|---:|
| 옛 도 하나의 사업 수 | 1 | 2 | 2 |
| 개별 사업 정치력 | 150 | 150 | **75** |
| 개별 사업 민공 점유·기간 | 5개·180일 | 5개·180일 | **5개·90일** |
| 옛 도 전체 정치력 | 150 | 300 | 150 |
| 옛 도 전체 민공일 | 900 | 1,800 | 900 |
| 강원 포함 전체 정치력 | 1,050 | 1,950 | 1,050 |
| 강원 포함 전체 민공일 | 6,300 | 11,700 | 6,300 |

부담 보존 예시에서는 강원150·5·180을 그대로 둔다. 남북 두 사업을 동시에 진행하면90일 동안 민공10개, 순서대로 진행하면180일 동안 민공5개가 필요하다. 정치력과 민공일이 같아도 **완료 시점·한쪽만 선택하는 비용·병행 가능성은 달라진다.** 현재 가용 민공 최소6 조건을 유지할지도 명시적으로 결정해야 한다.

75·5·90은 시행값이나 최종 밸런스 결정이 아니다. 확정할 때는 각 주가 실제 받는 등급·슬롯·자원·승점과 기회비용을 함께 비교한다. 비용만 반으로 바꾸고 원래 보상을 양쪽에 전부 복제하는 안으로 해석하지 않는다. 사업 보상 자체를 강화하려면 기존 예산 보존과 구분하여 강화 목표를 기록한다.

## 5 보상 설계 기준

### 등급·슬롯

1. 원래 도별 환산 예산은 전라2·경상2·충청2·황해2·평안4·함경3, 강원3이다. 이 합을 비교 기준으로 두고 **각 주의 목표 카테고리와 추가 슬롯을 함께** 정한다. 예컨대 함경3을 두 주에 같은 정수 보상으로 복제할 수는 없다.
2. 목표 카테고리보다 낮을 때만 올리고 이미 상위 등급이면 유지하는 정책을 권장한다. 상위 주에 예상 순증을 보장한다며 차액 슬롯을 자동 보상하는 것은 별도 강화이므로 확정 없이 추가하지 않는다.
3. 카테고리의 슬롯 증분을 임의의 추가 슬롯으로 바꿔도 기술 보정 후 완전히 같다고 가정하지 않는다. 최종 배분표에는 시작 등급·목표 등급·추가 슬롯·기술 보정 전 환산값·상한을 구분한다.
4. 공유25·유형별20 상한은 유지하는 기준이다. 슬롯만 주는 사업이 실질 공간을 늘리지 못하면 비용만 받고 끝나지 않도록 차단·대체 정책이 필요하다. 자원·승점도 남아 있는 사업은 부분 보상을 허용할지와 그 표시를 따로 결정한다.
5. 각 주별 최종 등급·슬롯 수치는 미확정이다. 두 주를 모두 기존 목표 등급으로 올리면 총보상이 커지는 도가 있으므로 자동 복제하지 않는다.

### 자원·승점

기존 coal+5와 VP+11의 지급 대장을 별도로 보존한다. 아래는 현행 지급 위치이며 변경하려면 이유와 원래 총량을 함께 기록한다.

- 석탄: 전북1082 +1, 평남527 +1, 강원1029 +3. 시작 석탄·크롬 배치를 바꾸거나 모든 남북도 사업에 자원을 복제하지 않는다.
- 승점: 군산13429·목포10110·포항7121·마산12060·울산13435·청주13446·조치원7204·사리원11915·안주9790·동해1148·나진6944에 각각+1이다.
- 특히 **청주·사리원의 VP+1은 이미 현행 충청·황해 개발의 완료 효과**다. 독립 사업안에서는 각각 충북·황북 사업에 연결하는 것을 우선한다. 새 사업을 만든다는 이유로 같은 승점을 두 번 지급하지 않는다.
- 국토개발은 현재 직접 공장을 지급하지 않는다. 공장 지급을 추가하는 안은 별도 강화로 분류한다.

**state 카테고리의 city/large_town은 주의 슬롯 등급이고 province의 urban/hills 지형은 별개다.** 승점 추가와 카테고리 상향을 모든 프로빈스의 도시 지형 변경으로 설명하지 않는다. 도시 지형·도시 모델·초기 승점을 수정하려면 별도 지도 범위와 검증을 정한다.

## 6 착수·취소·완료의 범위

주별 독립 사업에서는 표시명, 대상, 소유·통제, 부지 판단, 진행 유지, 완료 보상, 지도 강조가 같은 한 주를 가리키도록 한다.

- 국가 자격·중점 완료·건설III 등 현행 기본 자격을 출발점으로 둔다. `tag = KOR`를 원태그 전체로 확대하는 변경은 자동으로 섞지 않는다.
- 해당 주의 **자국 소유·완전통제**를 요구하고, 다른 쪽 도는 요구하지 않는 방향을 권장한다. 옛 두 주 통제 AND의 해제와 소유·완전통제 추가는 각각 의도한 행동 변경이며 기존 조건과 동등하다고 하지 않는다.
- 대상 주 상실·부분 통제·항복 같은 진행 중 조건과 완료 직전 판정을 일치시킨다. 현행에 없는 취소·재검사를 추가하는 정책으로 명시한다.
- 취소 때 개발 보상을 주지 않고 민공 점유를 해제하는 것을 기준으로 검토한다. 정치력 환불 여부·금액은 민공 반환과 따로 확정한다. 이번 문서로 환불 기능을 적용하거나 보장하지 않는다.
- 완료 보상은 주별1회로 관리한다. 취소 후 재착수를 허용할지는 별도 선택이다. 현행 `fire_only_once`의 소비 시점을 확인하지 않고 ‘취소하면 자동 재시도 가능’이라고 가정하지 않는다.
- 병행 실행 범위와 AI의 선택·비용 판단을 함께 정한다. 현재7개 사업에는 개별 `ai_will_do`가 없으므로 임의의 가중치가 기존값이었다고 기록하지 않는다.

## 7 기존 저장과 완료 기록

**새 게임의13개 설계와 현재 진행 중인 저장의 전환은 분리한다.** 기존 ID를 재사용해도 이미 실행된 옛 보상과 진행 중 사업의 완료 효과가 자동으로 호환되는 것은 아니다. 새 게임 기준을 우선하며 기존 저장 전환은 방법·승인이 정해지고 실제 확인되기 전까지 지원한다고 안내하지 않는다.

| 이전 상태 | 후속 설계에서 필요한 처리 |
|---|---|
| 옛 사업 미착수 | 새 사업·자격·비용을 적용할 수 있는지 버전과 진행 기록으로 식별 |
| 옛 사업 진행 중 | 원래 지불 비용·민공 점유·남은 기간·기대 보상을 보존하는 경로를 우선 검토. 새 비용을 다시 청구하거나 남은 시간을 초기화하지 않음 |
| 옛 사업 완료 | 등급·슬롯·자원·VP의 기지급 내역과 새 사업의 잔여 보상을 분리 |
| 식별 불가능·기록 불충분 | 완료 상태를 추측해 일괄 변환하지 않음. 기존 저장 전환을 보류하고 새 게임 적용 범위를 명시 |

예를 들어 옛 충청 개발은 충남 등급·슬롯과 **충북 청주 승점까지 이미 지급**한다. 신규 충북 사업을 그대로 열면 VP가 중복될 수 있다. 반대로 남북을 모두 완료 처리하면 실제 받지 않은 신규 슬롯까지 소진될 수 있다.

평안처럼 기존 슬롯 증가가 한쪽에 집중된 경우에는 기존 혜택을 회수하지 않으면서 새 양쪽 보상도 전부 주고 옛 총예산까지 유지할 수 있다고 약속하지 않는다. 잔여 보상·추가 강화·새 게임 전용 중 어떤 정책을 택할지 기록한다. 비용 차액의 자동 환불이나 카테고리 소급 하향도 이번 제안에 포함하지 않는다.

완료·버전 기록은 저장에 남는 범위와 재로드 시 반복 여부를 확인해야 한다. 기존 ID를 주별 이름으로 바꾸면 옛 광역 진행 사업도 좁은 이름으로 보일 수 있으므로 표시·설명도 검토한다. 실제 이전 방법은 미구현·미검증이다.
