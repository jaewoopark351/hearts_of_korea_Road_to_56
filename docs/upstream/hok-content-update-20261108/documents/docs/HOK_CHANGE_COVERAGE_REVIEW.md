# 변경 영향 범위와 누락 방지 절차

현지화·표식/변수 표시·주/프로빈스 참조를 검토하거나 변경할 때 사용하는 공통 절차다. 목적은 변경과 연결된 사용처를 확인하고, 확인하지 못한 범위를 다음 작업에서도 알아볼 수 있게 남기는 것이다. 이 문서는 전체 모드의 누락이 해소됐다는 판정이나 새 작업의 승인이 아니다.

## 적용과 자료의 역할

- 작업을 시작할 때 [AGENTS.md](../AGENTS.md)의 최신 요청·운영 모드·외부 산출물 규칙을 먼저 적용한다. 검토 전용은 응답에서만 보고하고, 문서 전용은 승인된 문서만 수정한다. 스킬을 읽었다는 이유로 검사 스크립트·게임·진단·정리를 실행하지 않는다.
- 표시 내용이나 현지화 사용처를 다룰 때 [현지화 검토 스킬](../.agents/skills/hok-localisation-review/SKILL.md)을 읽는다. 이름과 설명 외의 요구조건·효과·취소·선택지·해금 안내를 포함한다.
- 주·프로빈스의 대상이나 지역 범위를 다룰 때 [주 참조 검토 스킬](../.agents/skills/hok-state-reference-review/SKILL.md)을 읽는다. 지도 파일을 바꾸지 않는 코드 정렬에도 적용한다. 지역 설명과 대상 코드가 함께 바뀌면 두 스킬을 함께 적용한다.
- 실제 오류 로그를 검토하거나 원인을 귀속할 때만 [로그 검토 스킬](../.agents/skills/hok-log-review/SKILL.md)을 추가로 읽는다. 기존 로그 스킬의 역할은 유지한다.

`AGENTS.md`는 호출 조건과 공통 의무, 각 `SKILL.md`는 분야별 절차, `docs/`의 명세·대장은 의도한 대상과 확인 결과를 맡는다. 실제 ID 대응표·원문·검증 수치를 여러 스킬에 복제하지 않는다. 자동 스킬 선택만 기대하지 않고 AGENTS의 조건부 필수 읽기를 따른다.

## 1. 작업 기준과 조사 범위를 정한다

요청의 목표·금지 사항, 실제 작업 소스·브랜치/HEAD·기존 변경, 영향받는 기능과 ID를 확인한다. 로드 동작이나 런타임을 판단할 때는 정확한 게임 버전·물리 모드 경로·로드 순서·언어·관련 DLC도 구분한다. 새 게임/기존 저장, 한국어/활성 영문 번역처럼 서로 다른 조건을 같은 결과로 묶지 않는다.

조사 단위는 파일 개수보다 기능과 분기다. 변경 키·이전/현재 지리 ID에서 직접 사용처와 공유 호출부를 따라가며, 관련성이 있는 대체 경로·상속 코드까지 넓힌다. 동적 키·매개변수·지역 그룹은 확장된 사용 문맥을 확인한다. 검색 결과가 없다는 이유로 호출이 없다고 단정하지 않는다.

범위는 작업에 비례시킨다. 공통 안내 한 키의 문구 축약은 그 키의 참조와 언어별 덮어쓰기·문자열 보존을 확인하면 된다. 주 분할 이관은 옛/새 ID와 실제 프로빈스 소속, 지역 목록, 호출 국가·사건·분기를 함께 다룬다. 모든 사소한 문구 수정에 전체 모드 감사나 장기 실행을 요구하지 않는다.

## 2. 예상 의미와 현재 참조를 대조한다

각 기능에 대해 먼저 예상 결과를 정하고 현재 코드를 읽는다. 현재 코드가 가리키는 ID를 그대로 기대값으로 삼아 자기 자신과 비교하지 않는다. 이름·주석만으로 대상 지역을 확정하지 말고 현재 지도·명세·기존 원본·호출 문맥의 근거를 함께 확인한다.

- 현지화는 **사용자에게 보여야 할 정보 / 의도적으로 숨길 내부 처리 / 다른 안내로 이미 전달하는 정보**를 구분한다. 미정의 내부 변수나 선택적인 `_desc` 부재를 모두 결함으로 세지 않는다.
- 주 참조는 **대상 종류 / 실제 부모 주 / 의도한 지역 범위 / 조건과 실제 효과**를 구분한다. 존재하는 숫자 ID도 다른 지역일 수 있다. 영토 이전·통제 변경·코어·고정 건물 보상은 각각 따로 판단한다.
- 공통 helper 한 곳을 수정해도 호출별 scope·매개변수·대체 분기가 다르면 같은 검증 결과로 합치지 않는다. 동일하다고 묶는 경우 그 근거와 포함 ID를 남긴다.

## 3. 발견 항목의 처리 여부를 모두 남긴다

| 처리 상태 | 필요한 내용 |
|---|---|
| 수정 | 입증된 불일치와 필요한 수리. 제안/적용 상태를 구분하고 적용했다면 실제 반영 위치를 명시. 검증 결과는 별도 기록. |
| 의도적 유지 | 정상 동작·원래 의도·기존 저장 분기 등 유지 근거. 미확인을 정상으로 대신 표시하지 않음. |
| 제외 | 이번 작업에 포함하지 않는 이유와, 결함/정상/미확인 중 알려진 사실. 제외가 무결성 보증은 아님. |
| 미확인 | 부족한 근거, 남은 판단과 다음에 필요한 관측. 추측으로 대상을 바꾸거나 표시를 숨기지 않음. |

기존 관련 명세나 사건 기록에 대장을 갱신한다. 새 문서가 필요한 경우에만 만들며, 검토 전용에서는 파일을 새로 만들지 않고 같은 내용을 응답으로 보고한다. 과거 결과를 현재 소스에서 재검증한 것처럼 고치지 말고 날짜·소스 기준·후속 결과를 구분한다.

다음 양식을 필요한 열만 사용해 채운다. 행은 기능·사용처·의미가 다른 분기 단위로 작성한다.

| 기능·ID | 파일·호출부·분기 | 예상 표시·대상·규칙 | 현재 참조와 근거 | 처리 상태·이유 | 확인 단계·증거 | 남은 항목 |
|---|---|---|---|---|---|---|
| 작성 대상 | 실제 위치 | 근거가 있는 기대값 | 읽기/관측 사실 | 수정·유지·제외·미확인 | 아래 단계와 출처 | 필요한 후속 확인 또는 없음의 근거 |

공통 키 수, 사용처 수, 결정/사건 수, 검색 행 수와 검사 항목 수를 서로 더하지 않는다. 고유 키 하나가 13곳에서 쓰이면 키 1개와 사용처 13곳으로 따로 보고한다.

## 4. 검증 단계와 필요한 범위를 구분한다

| 단계 | 입증하는 범위와 한계 |
|---|---|
| 소스 | 참조·scope·문자열·인코딩·분기·의도와의 대응. 등록·실제 표시·효과 실행을 대신하지 않음. |
| 로드·UI | 실제 활성 파일과 해당 언어/상태에서의 표시·치환·색상·접근 가능 여부. 효과 지급을 대신하지 않음. |
| 실제 효과 | 기록한 조건에서 실행된 대상·비용·보상·취소 등. 강제 효과와 정상 진행을 구분. |
| 저장 | 비교한 값·표식·날짜·타이머의 보존 범위. 새 저장 왕복과 과거 저장 호환, 값 보존과 실제 기간 경과를 구분. |

필수 확인은 변경 위험과 요청 범위에 맞춰 정한다. 공통 함수와 13개 설정의 소스 확인을 한 화면 관측과 구분하고, 실행 분류가 다른 대표 경로에는 가능/차단 상태를 비교한다. 지역 조건을 바꿨다면 한 후속 주 미보유·부분 통제 같은 관련 경계를, 저장 상태를 바꿨다면 해당 영속 값을 다룬다. 런타임이 승인된 경우 전체 재시작과 실제 로드 구성을 확인하며 핫 리로드를 최종 증거로 쓰지 않는다.

문구만 바꾸는 작업에는 문자열·토큰·인코딩·언어 대응 확인을 우선한다. 실제 화면을 다시 확인하지 않았다면 그 사실을 적고 이전 스크린샷을 새 문구의 확인으로 재사용하지 않는다. 멀티플레이·다른 DLC·장기 실행은 그 호환성을 주장하거나 이번 변경에 필요할 때 정하며 모든 작업의 자동 필수 조건으로 만들지 않는다.

## 5. 완료 판단과 다음 작업으로의 인계

- 범위에 포함한 사용처가 모두 대장에 들어 있고 처리 근거가 있어야 한다. 중요한 호출·분기를 조사하지 못했다면 미확인으로 남긴다.
- 필요한 검증의 실제 결과와 근거를 기록한다. 준비된 검사·종료 코드·조용한 로그만으로 통과를 선언하지 않는다. 실패한 원본 결과를 지우지 말고 후속 통제와 귀속을 별도로 남긴다.
- 필수 항목이 남았다면 **구현 반영 / 검증 대기**, 의도가 미해결이면 **판단 대기**처럼 상태를 제한한다. 범위 밖 미검증과 이번 작업의 미완료를 구분한다.
- 결론은 확인한 기능·소스·조건에 한정한다. 조사한 파일 수만으로 전체 모드의 누락 0이나 모든 저장의 호환성을 선언하지 않는다.
- 자동 검사가 나중에 도입돼도 ID/키 존재와 소속 확인은 후보를 거르는 수단이다. 지역 의도·최종 표시·게임 동작 판정을 대신하지 않으며 이 지침 자체는 도구 개발·실행을 승인하지 않는다.
