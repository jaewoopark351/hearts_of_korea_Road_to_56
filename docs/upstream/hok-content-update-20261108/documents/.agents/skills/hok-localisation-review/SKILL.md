# HOK 현지화 검토

키 존재 여부와 플레이어에게 전달되는 의미를 함께 확인한다. 현지화 누락, 자동 표시 항목 누락, 정상 내부 비표시를 같은 결함으로 계산하지 않는다.

## 범위와 먼저 읽을 자료

- 최신 요청에서 읽기 검토·문서 전용·구현·진단 중 허용된 모드를 먼저 정한다. 검토·문서 요청은 코드 수정, 게임플레이 검사·진단 실행, 게임 조작이나 설정 변경을 허용하지 않는다.
- 현지화를 다룰 때 [AGENTS.md](../../../AGENTS.md)의 8절과 편집 규칙, [두 언어 채널 계약](../../../docs/incidents/2026-09-01-localisation-contract.md)을 먼저 읽는다. 과거 버전·키 수·미실행 기록을 현재 판정으로 옮기지 않는다.
- 변경 범위와 누락 없는 항목 처리를 정할 때 [변경 영향 검토 대장](../../../docs/HOK_CHANGE_COVERAGE_REVIEW.md)을 읽고 사용한다. 이 스킬은 전체 변경 검토 중 현지화 부분을 맡는다.
- 표식·변수 노출을 조사할 때 [표시 감사](../../../docs/audits/2026-11-08-continuation-localisation-display-review.md)를, 이전 수리와 비교할 때 [구현·실제 관측 기록](../../../docs/incidents/2026-11-08-localisation-display-implementation.md)을 읽는다. 최초 후보와 후속 확정 결과를 구분한다.
- 실행 로그를 읽거나 원인을 귀속할 때는 먼저 [HOK 로그 검토 스킬](../hok-log-review/SKILL.md)을 적용한다.
- 실제 활성 번역 사본을 찾고, 그 파일을 수정하기 전에는 해당 저장소의 `AGENTS.md`를 읽는다. 이 스킬 자체가 번역 저장소 편집을 승인하지 않는다.
- 승인된 증거 사본·진단 출력이 필요하면 먼저 `C:/hoi/test/<task-or-run-id>/`를 정한다. 읽기 검토만 할 때는 helper·보고서 파일을 새로 만들지 않는다.

## 변경의 표시 영향 목록

변경 파일·ID에서 시작해 공용 코드와 역호출자를 필요한 만큼 추적한다. 접두어 검색 결과만으로 범위를 닫지 않는다.

| 확인할 면 | 추적할 실제 사용 문맥 |
|---|---|
| 이름·설명 | 중점·국민정신·결정·범주·사건·선택지의 명시 키와 해당 데이터베이스가 요구하는 암시 키 |
| 조건 | 선행·가용·차단·취소 조건, 공유 트리거가 펼쳐지는 툴팁, 긍정·부정과 AND/OR/NOT |
| 효과 | 직접 변수 증감, 사용자 지정 툴팁, 사건 immediate·선택지의 실제 표시, 공용 효과의 긴 목록 |
| 해금 | 중점이 실제로 여는 결정·범주의 이름과 해금 안내, 별도로 남는 사용 조건 |
| 동적 참조 | scripted localisation 반환값, 파생 키, 매개변수 치환, scope·대상 이름·현재 값 |
| 공유 참조 | 바뀐 공통 안내·트리거·효과·변수·표식을 쓰는 다른 결정·사건·중점·GUI |

- 각 후보에 ID/키, 파일·행, 호출 경로, 표시되는 화면, 정의의 물리 파일, 처리 판정을 남긴다. 같은 키의 사용 횟수와 고유 결함 수는 별도로 센다.
- 모든 ID에 `_desc`가 필수라고 가정하지 않는다. 실제 소비자가 없는 선택적 설명, 빈 본문, 매개변수를 근거 없이 누락으로 세지 않는다.
- 정규식·키 집합 대조는 후보 수집이다. 파생·매개변수 키는 호출 시 실제 토큰과 문맥을 확인하고, 구조를 해석하지 못한 항목은 미확인으로 남긴다.
- 한 곳을 고친 뒤 다른 공용 호출자·신규 콘텐츠가 같은 표시를 다시 만들지 않는지 확인한다. 관련 없는 전역 파일까지 수리 범위를 확대하지 않는다.

## 내부 표식·변수의 판정

각 사용 지점에서 다음 세 경우를 구분한다. 이름 정의가 없다는 사실만으로 첫째 경우라고 결론 내리지 않는다.

| 경우 | 처리 방향 |
|---|---|
| 플레이어의 판단에 필요한 상태·수치 | 의미 있는 이름이나 정확한 조건·효과 툴팁을 사용한다. 저장 ID는 유지한다. |
| 이미 사용자 지정 안내로 설명되는 내부 조건 | 감싼 내용과 실제 화면을 확인한다. 원시 키 번역을 중복 추가하지 않는다. |
| 엔진이 원래 표시하지 않는 집계·초기화·단순 설정 | 확인된 비표시와 내부 용도를 기록하고 불필요한 번역·wrapper를 넣지 않는다. |

- 원문 ID 노출과 조건·효과 항목 전체의 부재는 다른 현상이다. 변수 이름만 번역하면 자동 변수 조건·효과도 나타난다고 가정하지 않는다.
- AI·이벤트 자격·대상 필터·단순 flag 설정만 보고 UI 결함을 확정하지 않는다. 필요하면 실제 소비 화면을 찾는다.
- 표시를 숨기는 코드가 필요하면 승인 범위와 현행 엔진의 같은 문맥·scope를 먼저 확인한다. 필요한 공개 의미·수치는 남기고 실제 조건을 삭제하거나 완화하지 않는다.
- ID, 변수 값·범위·초기화, flag 위치·수명, 비용·보상·AI·예약·효과 순서·완료 이력을 표시 수리 때문에 바꾸지 않는다.

## 실제 정의와 언어 채널

- 브랜치·HEAD·기존 변경, 게임 언어와 필요한 대상 버전, launcher의 활성 모드 순서·물리 경로를 확인한다. 저장소 파일이 곧 현재 로드된 파일은 아니다.
- 정확한 키·대소문자·정의를 본체 두 채널, 활성 번역, 필요한 의존/바닐라 소비자에서 대조한다. 같은 파일명 덮어쓰기, 중복 키, `replace/`와 locale header도 확인한다.
- 본체 `_l_korean`과 `_l_english`는 현재 계약대로 한국어 본문을 같은 상대 경로에 유지한다. 본체 English 파일을 임의로 영어화하지 않는다.
- 실제 영어는 활성 번역의 동명 파일을 확인한다. 그 저장소 계약에 따른 en-GB 문구·토큰·범위를 검토하고, 본체 변경이 낡은 번역에 가려지지 않게 한다.
- 양 채널 키 집합이 같아도 양쪽 모두 누락됐을 수 있다. 호출자의 필요한 키 목록과 대조한다.

## 쓰기와 문구 검토

- 승인된 키·값만 좁게 수정한다. HOI4 현지화에 일반 YAML formatter를 적용하지 않는다.
- UTF-8 BOM, 기존 CRLF/줄 끝·경로·헤더·키를 보존한다. paired 파일의 동일 기여 주석은 헤더 바로 뒤에 두고 기존 주석도 남긴다.
- `$KEY$`, `$RIGHT$`, 변수·대상 치환, 색상·아이콘 토큰, `\n`, 따옴표 escape의 정확한 토큰과 연결을 보존한다.
- 쓴 직후 명시적 UTF-8로 다시 읽어 실제 한글·Unicode 내용까지 확인한다. BOM 바이트만으로 정상 저장을 판정하지 않으며 콘솔의 잘못된 디코딩과 파일 손상을 구분한다.
- 긍정 상태명에 엔진의 `NOT`이 붙을 때 의미가 뒤집히는지, 가용·취소 양쪽의 문장이 맞는지 확인한다. 부정 이름을 넣어 이중 부정을 만들지 않는다.
- 숫자 조건은 임계값·현재 값·엄격 비교/이상·이하를, 효과는 증감 부호·수량·좋음/나쁨 색상을 확인한다. 비리 증가를 좋은 초록색으로 표시하지 않는다.
- 이름 추가나 문법상 적법성만으로 치환·색상·범위가 맞다고 가정하지 않는다. 새 metadata 구문은 현행 바닐라의 같은 명령·문맥을 근거로 삼는다.
- 설명은 배경·목적을 전달하고 자동 UI의 비용·기간·보상을 불필요하게 반복하지 않는다. 자동 UI가 설명하지 못하는 환불·재사용·취소 제한은 짧고 정확하게 남긴다.
- 사건 본문·선택지와 펼쳐진 툴팁을 함께 본다. 긴 공용 효과나 안내가 선택지를 화면 밖으로 밀지 않는지 확인하고, 줄 수를 줄이려고 규칙·조건·필요 수치를 숨기지 않는다.

## 범위에 맞는 검증과 마감

- 검증 규모는 변경에 맞춘다. 승인된 단순 문구 축약은 변경 키·참조·토큰·인코딩·의미 대조부터 하며 게임 실행을 자동으로 추가하지 않는다.
- 새 표시 경로·조건/효과 metadata·wrapper 변경은 그 문맥의 확인 필요성을 판단한다. 실행이 허용되면 최종 런타임 판정은 전체 프로세스 재시작과 해당 언어·화면으로 한다.
- 실제 UI를 보지 못했다면 정적 확인까지만 기록한다. 현재 실행이 수정 전 소스로 시작됐다면 수정 후 화면 증거로 쓰지 않는다.
- 필요한 경우 가능/불가능·완료/미완료·가용/취소·숫자 경계와 각 선택지를 나눈다. 합성 seed·강제 효과는 정상 진행의 증거가 아니다.
- 정적 키/바이트 확인, 실제 UI, 실제 효과, 저장 비교를 별도 결과로 기록한다. 조용한 로그나 올바른 이름만으로 다른 층도 통과 처리하지 않는다.
- 항목별 처리 판정(`수정`—제안/적용 구분·`의도적 유지`·`제외`·`미확인`)과 검증 상태(`확인`·`실패`·`미검증`)를 따로 적는다. 누락·미검증을 PASS로 채우거나 한 층의 성공을 전체 검증 통과로 표시하지 않는다.
- 저장·동작 비교에서 차이가 나면 원래 실패를 남긴다. 별도 통제로 표시 변경 없이도 재현됐는지 확인한 결과와 정확한 엔진 원인 판정을 구분한다.
- 완료 보고에는 변경 키·영향 화면·실제 활성 파일, 수행한 확인, 제외/미검증·기존 오류를 적는다. 좁은 확인을 전체 번역·모든 게임 상태의 정상 보증으로 확대하지 않는다.
- 실행·진단을 했다면 외부 증거 위치와 임시 설정·소유 프로세스·일회성 파일 정리 결과까지 프로젝트 규칙에 따라 기록한다. 문서 링크는 검사·게임·정리의 추가 승인이 아니다.
