# HOK 주·프로빈스 참조 검토

## 운영 모드와 필요한 자료

- 먼저 최신 요청의 운영 모드를 정하고 [프로젝트 규칙](../../../AGENTS.md)을 적용한다. 이 스킬을 읽었다는 사실은 수정·시험·게임 실행을 승인하지 않는다.
- 검토 전용이면 읽고 응답으로 보고한다. 문서 전용이면 승인된 문서만 편집한다. 새 대장·도구·진단 파일 생성도 현재 승인 범위를 따른다.
- 구현이 승인되어도 코드 참조 정렬은 지도 수정 승인이 아니다. 승인 범위가 참조 정렬이면 현재 지도와 ID를 보존한다. 지도 정의 자체의 결함은 별도 판단 대상으로 남긴다.
- 조사 범위와 후보 처리 내역을 정할 때 [변경 범위·누락 검토 지침](../../../docs/HOK_CHANGE_COVERAGE_REVIEW.md)의 공용 대장·템플릿을 읽는다. 이를 별도 양식으로 중복 관리하지 않는다.
- 현재 지도와 과거 참조를 대응시키거나 최근 분할 회귀와 기존 결함을 구분할 때 [현행 지도 참조 정렬 계획](../../../docs/HOK_STATE_REFERENCE_ALIGNMENT_PLAN.md)을 읽는다. 과거 조사와 최신 적용·검증 상태를 구분한다.
- 한국 북·남 후속 주의 구성·이관 의도를 판단할 때 [한국 주 분할 계획](../../../docs/HOK_KOREAN_STATE_SPLIT_PLAN.md)과 그 문서가 지정한 최신 대응표를 읽는다.
- 더 이전 중국·만주·일본 지도 이관을 판단할 때 [맵 재구성 설계](../../../docs/HOK_MAP_RECONSTRUCTION_PLAN.md)와 [중국·일본 정렬 정책](../../../docs/CHINA_JAPAN_VANILLA_ALIGNMENT_POLICY.md)을 읽는다.
- 런타임 로그를 읽거나 원인을 귀속할 때 [로그 검토 스킬](../hok-log-review/SKILL.md)을 먼저 읽는다.

## 기준과 대상의 종류 확인

1. 현재 작업 소스·기존 변경, 대상 게임 버전, 실제 활성 모드와 번역 경로를 확인한다. 설치 원본·Workshop은 읽기 전용 비교 자료다.
2. 각 숫자가 state, province, strategic region, 표시명 키 중 무엇인지 명령 문맥으로 판별한다. 존재하는 숫자라는 사실만으로 올바른 참조라고 판단하지 않는다.
3. 현행 주 정의에서 province의 부모 주를 확인하고 필요한 land/sea/coastal 속성·전략 지역·보급/철도 연결을 대조한다. 건물·승점·수도 명령의 기대 입력 종류도 확인한다.
4. 파일명, 주석, 실제 표시명과 현재 지리를 구분한다. state·province·현지화 키에 같은 숫자를 쓰도록 일괄 정렬하지 않는다.

## 사용처와 호출 경로 추적

- 변경 ID와 이전 ID, 후속 주 ID, 관련 지역명·목록·별칭을 함께 검색한다. 단순 숫자 일치 후보는 주변 명령을 읽어 관련성을 판정한다.
- 직접 수정 파일만 보지 않는다. 중점·결정·사건·이력·AI·scripted trigger/effect·상수·관련 표시 문구의 사용처와 호출자를 추적한다.
- 저장소에서 재정의하지 않은 바닐라/DLC·의존 모드의 상속 코드도 관련 호출 경로에 포함한다. 실제 파일 우선순위와 등록 방식, DLC 대체 경로를 확인한다.
- 동적 scope, scripted parameter, 변수·event target·iterator로 선택되는 대상은 고정 ID 검색으로 끝내지 않는다. 호출 인수와 ROOT/THIS/PREV/FROM의 의미를 필요한 단계까지 추적한다.
- 동적 참조나 문자열 조합 자체를 오류로 세지 않는다. 대상 집합을 설명할 근거가 부족하면 `미확인`으로 남기고 이를 구분할 관측을 적는다.
- 모든 옛 참조를 없애는 것을 목표로 삼지 않는다. 의도된 단일 주 보상, 기존 저장 분기와 다른 기능의 같은 숫자는 별도로 판단한다.

## 기능별 대상 대응

공용 대장에 기능 ID·경로와 아래 단계별 의도 대상·실제 대상을 대응시킨다. 적용되지 않는 단계는 이유와 함께 표시한다.

| 단계 | 확인할 연결 |
|---|---|
| 진입·유지 | visible/available, 착수·유지 조건, 취소·제거, bypass의 대상 범위 |
| 표시·조회 | highlight, 이름·설명, 건물 수준·빈 슬롯 등 질의의 실제 대상 |
| 지급·변경 | 보상 위치·수량, transfer·controller 변경·core·claim의 개별 대상 |
| 후속·대안 | 사건 수락/거절, 일반 이전·내전·종속국, 국가 존재/부재, DLC·fallback 경로 |

- 같은 지역을 뜻하는 조건·우회·강조·효과 목록의 차이를 모두 설명한다. 목록 길이가 같다는 사실만으로 일치 판정하지 않는다.
- 소유, 통제, 완전 통제, 코어는 별개다. 일반 이전과 내전의 동적 생성국 분배도 분리한다. 조건만 넓히고 지급 경로를 남기지 않는다.
- 슬롯 부족·무작위 수혜주·대체 건설·수도 선택 등 실제 fallback의 범위도 확인한다. 효과를 둘러싼 중괄호만으로 scope를 단정하지 않는다.

## 의도와 보존 계약

- 대상 집합은 원래 기능의 지리적 범위·과거 경계·현재 소유/코어·설명·호출 관계로 판단한다. 현재 국가 코어나 지역명 하나를 근거로 무제한 확대하지 않는다.
- 영토 이전과 코어 부여를 각각 결정한다. 소유국과 코어국을 같다고 가정하거나 다른 경로의 코어 효과를 자동 복사하지 않는다.
- 참조 정렬에서는 고정 보상 총량·효과 순서·비용·기간·AI·정치 분기와 기존 ID를 보존한다. 분할 후속 주마다 같은 보상을 복제하지 않는다.
- 지도와 직접 보상 수치가 같아도 영토 범위 변경은 착수 난도·산업·인력 등에 영향을 줄 수 있다. 동작·밸런스가 완전히 같다고 쓰지 않는다.
- 의도나 실행 처리가 불명확하면 관측할 질문을 남긴다. 조건 삭제, `always = yes`, 임의 대상 교체로 검토를 통과시키지 않는다.

## 후보별 처리와 검증

발견 후보마다 위치·기능·근거와 다음 중 하나를 기록한다. 반복 위치와 고유 기능 수를 구분하며 검색 행 수를 통과 수로 쓰지 않는다.

- `수정`: 필요한 수리와 근거, 제안·적용 상태. 승인되지 않은 변경은 적용하지 않고 제안으로 남긴다.
- `의도적 유지`: 현재 참조가 필요한 정책·저장 분기·단일 수혜주 등의 근거.
- `제외`: 다른 ID 종류·무관한 기능·오탐 등 조사 대상이 아닌 이유.
- `미확인`: 미해결 의도·동적 대상·엔진 처리와 이를 구분할 추가 관측.

검증은 현재 승인과 변경 위험에 맞춘다.

- 정적 검토는 각 영향 참조의 종류·소속·단계/분기 대응과 보존 계약을 확인한다. 부모 불일치가 곧 효과 무시를 증명하지는 않는다.
- 실행이 승인되면 서로 다른 동작 유형별로 정상 경로와 중요한 차단 경로를 확인한다. 새 후속 주 누락, 외국 점령, 종속국·내전·fallback 등 변경과 관련된 경우를 선택한다.
- 같은 구조를 대표 사례로 묶으면 동등성 근거와 미실행 범위를 남긴다. 검증 전 국가 존재·독립 여부·소유/통제·기존 건물 수준 등 사전조건부터 확인한다.
- 실제 대상·수량·실행 순서와 필요한 표시를 관측한다. 원본에도 같은 코드가 있다는 사실을 원본 단독 재현이나 HOK 무관성의 증거로 대신하지 않는다.
- 등록·파싱, 효과 실행, UI, 정상 진행, 새 저장 왕복과 기존 저장 호환을 구분한다. 조용한 로그·성공한 실행 하나로 전체 완료를 선언하지 않는다.
- 실행하지 못한 경우 `미실행`과 이유를 보고한다. 검토·문서 작업을 시험·게임 실행으로 확장하지 않는다.
