## A1 — 기존 훈장 4종의 해군 연동

`common/unit_medals/hok_medal_default.txt`의 기존 ID, 국가 조건, 그림·프레임, 정치력 비용 30과 육군 `unit_modifiers`를 보존한다. 각 훈장에 `ship_modifiers`를 추가하고, 기존 사단장 경험치 100 지급을 `officer_xp = 100`으로 옮긴다. 이전 `one_time_effect` 경험치 지급은 제거하므로 두 경로를 동시에 쓰지 않는다.

| 기존 훈장 | 기존 육군 효과 — 유지 | 해군 효과 — 추가 |
|---|---|---|
| `hwarang_mugong_hunjang` | 사기 +5%, 조직력 +5% | `naval_morale_factor = 0.05`, `navy_org_factor = 0.05` |
| `chungmu_mugong_hunjang` | 보급 소비 -10% | `naval_supply_consumption_factor = -0.1` |
| `eulji_mugong_hunjang` | 공격력 +5% | `naval_damage_factor = 0.05` |
| `taeguk_mugong_hunjang` | 경험치 손실 -20% | `experience_gain_navy_unit_factor = 0.2` |

설치본 `common/unit_medals/00_default.txt:25–26`은 `ship_modifiers`가 없으면 함정에 수여할 수 없고, 함정 수여 시 `one_time_effect`가 실행되지 않는다고 명시한다. 독일 466–549행과 영국 718–795행은 양 군종 modifier와 `officer_xp`의 현행 구조를 확인하는 예제다.

구체적인 네 효과의 직접 공여자는 같은 파일의 미국 훈장 553–633행이다. 미국의 기존 육군 효과가 한국 네 정의와 각각 정확히 일치하므로, 조직력·사기, 보급, 함선 피해, 함정 경험치 획득의 해군 대응값도 그대로 사용했다. 영국·독일의 다른 역할 보너스를 임의로 섞거나 기존 육군 수치를 조정하지 않았다. 이 변경은 기존 육군 경험치가 고장 났다는 판정을 전제로 하지 않는다.

### 실제 해전·수여·진급 관측

실제 DLC 36개를 인식한 `bd1a` 실행에서 1936.1.29.3의 실제 해전을 거친 잠수함 ROKS SSM-1/2/3/5/6의 수여 가능 이력을 확인했다. 태스크포스 2171의 `last_combat_date`, 해상 프로빈스 4465 및 다섯 함선의 `history_queue` 날짜·위치가 일치하고 `medal_count=yes`가 직렬화됐다. 이 실행의 외부 진단 define은 판정 확률 1/1, 최소 교전 시간 0, 수여 대기 0, 수송선 교전 허용으로 제한했다. 실제 해전이나 훈장·경험치를 강제로 생성하지 않았지만, 원본의 48시간·1/24·수송선 제외 조건에서의 자연 획득은 입증하지 않는다.

### 진단 모듈 없는 운영 구성의 실제 함장 저장 재로드

전체 프로세스를 재시작한 `PID21700`, 체크섬 `032c`에서 **Korean Language와 저장소 모드 두 개만** 사용하고 외부 진단 모듈 없이 위 진급 후 저장을 실제 UI로 불러왔다. 1936.2.4.14 일시정지를 유지하여 `real-dlc/runs/final-clean-production/captain-mio-reloaded-resaved-Feb4-14.hoi4`로 재저장했다. 독립 비교는 네 훈장 ID·함정 이력, SSM-1/2/3의 함장 경험치 101.1256, 제독 Chul Kim `12633/type73`의 경험치 101.1256·숙련도 1·태극훈장 `inherit=yes` 유지를 확인했다. ### 관측된 함장 UI 번역 누락 수리

실제 수여·진급 화면에서 노출된 원본 함장 키 13개만 `localisation/{english,korean}/HOK_KOR_naval_captains_l_*.yml`에 보완했다. 필수 Korean Language와 기존 프로젝트에 정의가 없고 설치본에 정확한 키가 존재함을 확인했다. 함장 제목·함선 기본 직함·해전 이력·수여 설명·진급 이력·경험치·진급 확인·숙련도 손실·잠수함 함장 특성명 및 `UNIT_LEADER_NEW_LEADER_CAPTAIN`의 “함장 보기”를 다룬다. 기존 유효 번역·일반 부대 UI·비용·수치·특성 조건은 바꾸지 않는다.

두 파일은 UTF-8 BOM, 즉시 기여자 주석, 동일 한국어 본문을 유지하고 원본 매개변수·서식·개행을 보존한다. 독립 정적 확인은 **81 PASS / 0 FAIL**이며 외부 `validation/naval-captain-fallback-13-static.json`에 보존했다. 최종 `032c` 운영 구성의 전체 재시작·실제 재로드 후 SSM-6 패널에서 함장 Dohyun Gang과 “함장” 제목, 한국어 해전 이력·훈장 수여 툴팁(`ASSIGN_CAPTAIN_MEDAL_TOOLTIP`), 네 훈장의 이름·효과·기본 비용 30 표시를 확인했다. 화면은 외부 `runtime-ui/final-clean-captain-title-history.jpg`, `final-clean-captain-award-tooltip.jpg`, `final-clean-four-medal-effects-list.jpg`에 보존했다. 진급 확인 문구의 모든 키·특성 분기까지 실제 UI로 확인한 것은 아니므로 13개 전체 표시 통과로 합산하지 않는다. 진급 전에 이미 저장된 이력의 `army_names`에는 `SHIP_OFFICER_TITLE_SHIP_DEFAULT Chul Kim` 같은 원시 접두어가 문자열로 남아 있으므로, 번역 추가가 그 기존 저장 문자열까지 다시 쓴다고 약속하지 않는다.

## C3 — 현해탄 군항 급습

### 의도와 기존 콘텐츠 연결

대규모 일본 함대와 정면으로 교전하기 어려운 한국 해군이 현해탄을 건너 적 군항을 한 번 타격한다. 기존 `KOR_jeju_naval_base` 설명은 일본의 사세보 견제를 이미 언급한다. 실제 표적은 현재 지도에 해군기지가 존재하는 **나가사키 프로빈스 9950, 나가사키 주 528**로 한정한다. 사세보 연구시설의 위치와 나가사키 항구를 혼동하지 않는다.

`KOR_organization_rokmc` 완료로 범주와 작전이 공개된다. 이 중점은 원래 `marines` 기술과 훈련된 해병 사단 3개를 제공하므로 새 부대나 기술 지급을 추가하지 않는다. 중점의 기존 선택·배타·보상을 유지하고 `Thunder at Our Gates` 보유 시에만 `HOK_KOR_unlock_nagasaki_port_raid_tt` 안내를 표시한다. 실제 공개는 습격의 `has_completed_focus` 조건이 담당한다. 별도 전역 플래그는 만들지 않는다.

| 항목 | 구현 |
|---|---|
| 범주 ID | `HOK_KOR_naval_commando_raids` |
| 작전 ID | `HOK_KOR_nagasaki_port_raid` |
| 국가 | 정확한 `tag = KOR`; 한국 계열 내전 국가에 자동 부여하지 않음 |
| DLC | `Thunder at Our Gates` |
| 범주 정보원·세력 영향력 | `intel_source = naval`, 성공 시 영향력 50 — 원본 해군 특공 범주값 |
| 공개 | 해병대 창설 중점 완료; 범주·작전 양쪽에서 조건 확인 |
| 준비 | 일본이 주 528을 소유·지배하고 프로빈스 9950을 통제하며 같은 세력이 아님; `marines` 기술 |
| 표적 | `target_type = { province = 9950 }`; 표적 상대국 `FROM`은 정확한 `JAP` |
| 출격 | 실제 상대국 `FROM`과 전쟁 중이며 일본의 주 소유·지배, 프로빈스 9950 통제와 해군기지 존재를 재확인 |
| 출발지 | `starting_point = { types = { naval_base } allow_faction_buildings = yes }`; 자국·세력 영토의 해군기지 |
| 투입 | 해병 대대가 최소 3개인 사단 |
| 준비 장비·지휘력 | `essential_equipment = { convoy = 40 }`, `command_power = 40` |
| 기간 | 준비 120일, 원본의 해상 이동 속도 배수 4 |
| 재사용 | `fire_only_once = yes`; 표적 1개인 고유 작전으로 반복 피해 제한 |

수송선은 필수 장비 수량이다. 집결·반납·실제 장비 손실과 지휘력 배정·해제는 엔진에서 따로 확인해야 하며, 본문은 수송선이 항상 40척 소모되거나 전량 반환된다고 약속하지 않는다.

### 실제 접근 불가 재현과 출발지 수리

처음 실제 UI에서는 범주와 정확한 나가사키 9950 표적이 보였지만 “목표에 접근 불가”로 생성 화면이 열리지 않았다. 일본 소유·통제·실제 항만, 전쟁, DLC, 기술, 해병·수송선·지휘력 조건을 갖춘 별도 새 게임에서 출발지 계약과 표적 계약을 분리했다. `PID12784`, 1936.1.1.12의 같은 상태에서 다음 네 항목을 비교했다.

| 항목 | 출발지 | 표적 | 실제 UI 접근 |
|---|---|---|---|
| 운영본 비교군 | `building_types = { naval_base }` | 고정 9950 | 빨간색, 접근 불가 |
| A | `types = { naval_base }` | 고정 9950 | 녹색, 생성 화면 접근 가능 |
| B | `building_types = { naval_base }` | 해군기지 건물 | 빨간색, 접근 불가 |
| C | `types = { naval_base }` | 해군기지 건물 | 녹색, 생성 화면 접근 가능 |

B/C는 528주 안의 건물 표적을 쓰는 외부 진단 정의이며 비교는 실제 9950 표시에서 수행했다. A의 생성 화면에는 실제 적격 해병 사단 4개가 나열됐다. 복제 작전을 준비하거나 출격하지 않았다. 화면은 외부 `runtime-ui/guard-AB-source-types-discriminator-Jan1-12.jpg`와 `guard-AB-A-eligible-marine-units-Jan1-12.jpg`, 고정 소스는 `real-dlc/runs/guard-c2-edge-raid-AB/`에 보존했다.

이 재현은 표적을 고정 9950으로 유지해도 **출발지 키 하나를 `types`로 바꾸면 접근이 회복됨**을 입증한다. 따라서 고정 프로빈스 표적을 건물 표적으로 바꾸지 않았다. 설치본 인도네시아·호주 해군 습격(`common/raids/naval_commando_raids.txt:211,1315`)이 같은 `types`를 사용한다. 시암의 `building_types` 예제만으로는 현재 운영본의 해군 경로 접근이 보장되지 않았으며, 엔진 내부의 세부 경로 알고리즘까지 추정하지 않는다.

게임을 종료한 뒤 운영 소스의 해당 키와 인접 기여자 주석만 수정했다. ### 운영 정의의 실제 집결·120일 준비·출격·제한적 성공

전체 재시작한 `PID12008`, 체크섬 `1137`에서 운영 소스 57개를 고정했다. 습격 파일은 위 수정본 SHA-256 `121BCF44…636C8BA9` 그대로이며 A/B 복제 작전은 없다. 외부 준비 모듈은 기존 해병 중점·실제 장비와 별도 시험 사단·대일전을 준비했지만 습격 생성·준비·결과를 강제하지 않았다. 실제 한국 작전 UI에서 부산 4056 해군기지, 거리 838km, 나가사키 9950, 사단 `2774/type51`을 선택해 생성했다.

1936.1.1.15의 생성 직전·직후 저장에서 지휘력 **80→40**을 확인했다. 같은 순간 수송선 재고는 265로 같았으므로 생성 즉시 재고 40척이 삭제됐다고 해석하지 않는다. 이후 실제 UI에서 **40/40 수송선 집결**, 준비 진행 26→41→55→70→86%, 준비 완료를 관측했다. 준비 완료 저장의 엔진 `prep_time=2880`은 정확히 **120일**이다. 생성부터 1936.5.10.24 저장까지 경과한 시간은 3129시간, **130일 9시간**이며 집결과 이미 출격 가능했던 2일을 포함한다. 이 전체 경과를 120일 준비 자체와 혼동하거나, 반올림된 출격 가능 일수로 정확한 집결 시간을 역산하지 않는다.

같은 1936.5.10.24에 수동 출격 버튼을 눌렀고 저장된 단계가 `PREPARED→IN_PROGRESS`로 바뀌었다. `unit=2774/type51`, `source=4056`, `target=9950`과 수송선 40이 유지됐고 `used_types`에 운영 작전 ID 및 표적 재사용 대기 기록이 추가됐다. 복제 작전이나 강제 출격 효과를 호출하지 않았다. 이 기록은 한 번의 실제 출격을 입증하며, 재사용 버튼 차단과 수송선·지휘력의 최종 반환은 별도 확인 대상이다.

### 결과 저장의 실제 UI 재로드와 원문 차이

위 1936.5.19.15 결과 저장을 실제 UI에서 다시 불러오고 시간을 진행하지 않은 채 같은 시각에 재저장했다. 재로드 후 결과 창에도 운영 작전의 완료·제한적 성공이 유지됐다. 화면은 외부 `runtime-ui/production-raid-result-after-actual-reload-May19-15.jpg`, 재저장은 같은 실행 디렉터리의 `raid-postresult-reloaded-resaved-May19-15.hoi4`, SHA-256 `226708A79A9D2CE1F22633578CB2C503DD877300A1D2C12DB7815BFA485A82E1`이다.

독립 비교 `validation/raid-postresult-reload-persistence.json`은 같은 시험 게임·시각에서 한국의 전체 `raid_manager`, 투입 사단의 추출된 결과·이력·함장 상태, 9950 항만 건물 기록, 표적 함선 8척의 전체 기록·위치, 일본 함선 194척 전체의 전력·위치가 유지됨을 확인했다. 따라서 이 새 시험 저장의 **제한적 성공 결과에 한정한 유지**는 확인했다. 준비·진행 중 저장이나 구현 이전 저장의 호환성까지 입증한 것은 아니다.

원문 전체가 같지는 않다. 사단 2774의 이동 경로 관련 `previous=4086`이 재저장에서 생략됐고, 비표적 함선 **186척의 `organisation` 값이 변경**됐다. 함선 조직력 변화의 원인은 **미확인(UNPROVEN)**이며 정상화로 단정하거나 습격 피해로 귀속하지 않는다. 다른 함선의 전력·위치와 표적 8척의 전체 기록이 유지됐다는 좁은 결과와 이 미해결 차이를 함께 기록한다. 원문 완전 동일 비교는 통과하지 않았으므로 재로드 전체가 무변화·무결함이라고 표시하지 않는다.

### 결과와 범위

| 결과 | 표적 해군기지 | 해당 항구의 적 함선 | 투입 사단 |
|---|---:|---:|---|
| 실패 | 피해 없음 | 피해 없음 | 현재 조직력 65%, 현재 전력 60% 손실 |
| 제한적 성공 | 1단계 피해 | 조직력·전력 각각 25% 비율 피해 | 같은 손실 |
| 성공 | 2단계 피해 | 조직력·전력 각각 50% 비율 피해 | 같은 손실 |
| 대성공 | 3단계 피해 | 조직력·전력 각각 75% 비율 피해 | 같은 손실 |

모든 결과에서 투입 사단에 `raid_add_unit_experience = 0.1`과 습격 이력을 적용한다. 제한적 성공 이상은 사단장 경험치 50도 지급한다. 실패에 사단 전체 삭제 명령을 넣지 않는다. 공격자 사단의 `raid_damage_units`는 설치본 습격 문서에서 현재 조직력·전력에 적용하는 비율로 설명한다. 방어 함선의 일반 `damage_units`는 설치본 효과 문서의 비율 피해 정의를 따르되, 현재치와 최대치 중 정확한 분모는 실제 전후 수치를 관측하기 전까지 확정하지 않는다.

결과 효과는 습격 인스턴스에서 실행된다. `damage_units`는 `province = var:target_province`, `army = no`, `navy = yes`와 국가 조건 `has_war_with = KOR`를 사용하여 해당 항구의 적 함선으로 제한한다. `var:target_state`로 주 범위를 얻은 뒤 `damage_building`의 `province = var:ROOT.target_province`로 표적 해군기지만 손상한다. 주변 육군·다른 항구·조선소·해군 연구시설은 피해 대상에 넣지 않는다.

숨김·준비·출격과 세 성공 결과의 피해 적용 직전에는 프로빈스 9950 자체에 해군기지가 남아 있는지도 검사한다. 다른 항구가 같은 주에 건설됐다는 이유로 빈 표적을 허용하지 않는다. 세 성공 결과에서는 일본과 한국의 전쟁 및 일본의 표적 주 소유·지배와 프로빈스 9950 통제를 다시 확인한다. 평화·주 변경·표적 항구의 부분 점령 이후에는 표적 피해를 적용하지 않는다. 이 보호 조건은 공격자 사단의 원정 손실·경험치 처리와 구분한다. 숨김·가용·출격·결과를 같은 검사 하나로 간주하지 않는다.

### 확률과 AI

확률식은 `SIA_pacific_island_raid`의 `success_factors`를 유지한다. 성공 기초값 0.05에 부대 경험, 조직력, 전력, 정찰, 제공권, 해군 정보가 기여한다. 별도 대성공·실패 확률식을 새로 만들지 않는다. 엔진 기본값을 포함한 실제 확률과 준비 중 변화는 UI에서 확인해야 한다.

AI는 원본의 기초 가중치 1과 표적 주 정박 함선 보유 시 ×5, 주력함 보유 시 ×2를 유지한다. 기존 `ships_in_state_ports`는 주 단위 평가지만 실제 피해는 프로빈스 9950으로 제한된다. 장기 AI의 준비·선택·장비 부담·출격 시점은 실행 검증 대상이다.

## 자산과 현지화

그림은 Paradox Interactive의 설치본 HOI4 모드용 바닐라 자산을 변경 없이 내부에 복사했다. 오픈소스·새로 제작한 그림·AI 생성물이라고 표기하지 않는다. 원 저작권과 제3자 권리가 이전됐다고 주장하지 않으며, 기존 게임용 모드 자산 재사용의 범위다. 원본 설치·Workshop 파일은 수정하지 않았다.

원본 경로는 위 설치본 아래 상대경로다. 각 출력의 SHA-256은 대응 원본과 동일하다. 프레임·크기·알파·파일 형식을 변환하지 않았다.

| 용도 | 원본 → 프로젝트 내부 출력 | 크기·프레임 | SHA-256 |
|---|---|---|---|
| 범주·부대 | `gfx/interface/military_raids/map_icons/raid_unit_icon_naval_commando_raids.dds` → `gfx/interface/military_raids/HOK_KOR/naval_commando.dds` | 32×32, 1프레임 | `6758c13768d4fe9ef56274c6e5c1fe9e1404342ea9112a1c56a776eacf5e2c90` |

`interface/HOK_KOR_raids.gfx`는 세 출력만 사용한다. 범주 그림은 엔진이 요구하는 `GFX_raid_category_small_HOK_KOR_naval_commando_raids` 자동 조회 이름을 사용한다. 나머지는 `GFX_HOK_KOR_raid_*`로 구분한다. 사운드 `raid_launch_marine`와 기존 수송선 모델 `westerngfx_traderoute_convoy`는 원본 해군 특공 구조를 따른다.

`localisation/korean/HOK_KOR_raids_l_korean.yml` 및 `localisation/english/HOK_KOR_raids_l_english.yml`은 UTF-8 BOM을 사용한다. 기존 프로젝트의 한국어 표시 계약에 맞춰 영어 fallback 파일에도 같은 한국어 문구를 둔다. 두 헤더 바로 다음의 기여자 주석을 동일하게 유지한다. 명칭·서술·준비/출격·비용·1회성·결과와 원정 손실을 명시하며, 외부 그림 fallback이나 전역 현지화 키 덮어쓰기를 사용하지 않는다.

## 검증과 남은 범위

초기 소스 검토는 원본과 새 소스, 국소 Git diff, 그림 경로·헤더·해시를 확인했다. 기존 훈장 육군 블록은 변경하지 않았고 이전 경험치 지급 블록과 새 `officer_xp`를 겹치게 남기지 않았다. 이후 실제 게임 UI와 저장 차이, 별도 정적·역변환 확인을 위 기록처럼 구분해 추가했다. Git 변경·게시 작업은 수행하지 않았다.

실제 확인된 범위는 A1 네 훈장 수여·정치력·함장 경험치·제독 진급과 진단 모듈 없는 운영 구성 재로드 유지, C3 운영 정의의 전체 재시작·표적과 부대 선택·지휘력 배정·40/40 집결·120일 준비·수동 출격·제한적 성공 한 건 및 결과 저장의 UI 재로드 후 위 항목 유지다. 재로드에서 발견한 제독 메타데이터·비표적 함선 조직력·사단 이동 원문 차이도 별도로 남긴다. 정적 검사 수, 실제 UI 관측, 저장 차이를 합쳐 하나의 통과 수로 계산하지 않는다.

남은 범위는 다음과 같다.

1. 진급 확인·특성 분기 등 미관측 함장 번역 경로, 함선 보너스 수치·육군 경험치 지급의 별도 확인. 함장 제목·해전 이력·수여 툴팁·네 훈장 목록 표시는 최종 운영 UI에서 확인했다. A1 시험 저장의 한정된 재로드 유지는 완료됐으며 제독 메타데이터 차이를 원문 동일로 처리하지 않는다.
2. C3 실패·성공·대성공 세 결과와 종료 직전·직후 저장을 통한 순간 손실·경험치, 주변 항구·연구시설 보호.
3. DLC 없음·중점 미완료·다른 국가의 비공개, 전쟁 전 차단, 준비 중 평화·표적 부분 점령·통제 변경 및 전쟁 종료 시 보호.
4. 실제 재사용 UI 차단, 수송선·지휘력 반환, 준비·진행 중 저장의 재로드, 비표적 함선 조직력 변경 원인.
5. 기존 저장 호환, 장기 AI 선택·준비·출격, 전체 확률 분포와 멀티플레이.

정적 조건이나 강제 효과 관측을 실제 UI·정상 출격·저장·멀티플레이 검증으로 확대하지 않는다. 반대로 이미 수행한 실제 집결·120일 준비·출격·제한적 성공과 결과 저장의 한정된 재로드 유지는 미검증 항목으로 되돌리지 않는다. 완료된 한 결과와 남은 세 결과·조건 변형·미해결 원문 차이를 구분한다.
