## 범위와 시작 상태

설치 원본은 HOI4 `1.19.3.0.c01a` / Steam build `25205862`다. 원작자 Workshop `2898629778`은 읽기 전용 참고로 사용했다. 활성 후속 descriptor·업로드 ID·의존성·버전 선언을 바꾸지 않았다. 테스트·로그·원문·프로필 백업·임시 도구는 `C:/hoi/test/feature-integration-20261031/`에 둔다.

## 기준 실행과 환경 제한

1. 기존 사용자 로그·설정·모드 선택 파일을 `before/` 아래에 먼저 보존했다. 실제 선택은 RT56·RT56 한국어·별도 RT56 호환판 3개다. 일반판 저장소의 기존 실행 증거로 사용하지 않았다.
2. `-userdir`와 `--userdir` 격리 탐색은 원래 RT56 구성을 불러왔다. 두 실행은 일반판 검증에 포함하지 않는다. 기존 사용자 설정·활성 목록을 직접 변경하지 않았다.
3. 설치 exe와 필요한 실행 파일을 외부 테스트 경로에 복사하고, 원본 콘텐츠를 참조하는 디렉터리 링크와 외부 사본의 `launcher-settings.json`을 사용했다. 링크 자체가 쓰기 방지를 강제하는 것은 아니며, 작업에서는 원본에 쓰기를 수행하지 않았다. **설치 원본의 파일을 변경하지 않았다.** exe SHA-256은 원본·사본 모두 `7dc947be34970da1e1c787bcddbe7f62b610ff258aebf8f06aa8b348f3a031d5`다.
4. 외부 사본은 `Korean Language → 현재 일반판 저장소`를 실제 로드했다. 수정 전 PID `22580`, 체크섬 `9278`, 1936년 1월 1일 12시 일시정지 새 게임의 로그를 `baseline-repository-paused/`에 보존했다. 구형 교리의 invalid database object 오류를 직접 재현했다.
5. **이 외부 실행 사본의 활성 DLC는 0개다.** 원래 설치 exe는 같은 설치에서 DLC 36개를 인식한다. 원인은 분리 확인하지 않았으며 라이선스나 DLC 자체의 결함으로 단정하지 않는다. 외부 사본의 결과로 함장·AAT·특별 프로젝트·해군 습격의 DLC 보유 실행을 검증했다고 주장하지 않는다.
6. 원래 exe에 외부 작업 디렉터리만 지정한 추가 탐색도 RT56 구성을 로드했다. 해당 결과도 제외한다. 원래 설정·플레이셋의 임시 전환은 AGENTS.md의 명시적 허가·백업 규칙에 따라 별도로 확인 요청한 상태다.

기준 게임을 일시정지한 뒤 소스 편집 중 발생한 자동 hot reload 로그는 최종 파싱·동작 통과 근거로 사용하지 않는다. 최종 확인은 새 프로세스와 새 게임을 구분하여 기록한다.

초기 33개 정적 검사 통과는 이 등록 실패를 잡지 못했다. 수정 뒤 해당 검사는 42개로 보강됐으며 통합 보존·모듈 검사도 통과했다. 최종 엔진 등록 결과는 아래 후속 재시작으로 별도 확인한다. 외부 진단 fixture의 같은 종류 공통 매개변수 검사도 리터럴 네 블록으로 풀어, 진단 자체의 등록 실패를 게임 코드 결함과 혼동하지 않도록 했다.

## 소스 재검토에서 보완한 세력 규칙

설치본 `common/defines/00_defines.lua:4685`의 NCNS 기본값은 `faction_template_generic`이다. 그 정의의 `default_rules`에 있는 이웃 가입·공격전쟁 중 가입 금지·공격전쟁에 따른 추방 규칙은 새 템플릿에 자동 상속되지 않는다. 네 한국 템플릿에 해당 세 규칙을 직접 유지했다. 공용 템플릿의 인력 기반 지도권을 산업 기반으로 바꾸는 것은 명세에 명시한 C4 신규 설계로 유지한다. 기존 사건의 가입 효과·수락/거절 확률·순서는 변경하지 않았다.

네 템플릿의 `visible = { always = no }`는 공용·미국의 설치본 사례에 맞춰 비공개 의도를 명시한 것이다. 문서는 빈 visible도 비공개라고 설명하므로, 생략 상태에서 실제로 전역 후보가 노출됐다고 주장하지 않는다. 외부 모듈 검사는 이 규칙 보존과 명시적 비공개를 검사하도록 197개에서 213개로 보강했다.

### 일일 호출 범위와 비용

구분 가능한 문자열로 관측한 24시간 분산 주기에서 `on_daily`는 91개 국가에 각각 한 번, 경기 525의 지배국 분기는 한국에 한 번 들어갔다. 모두 ROOT=THIS였으며 한국 분기는 1936.1.1.24였다. 비교용 `on_daily_KOR`도 한국 한 번이지만 이 후크는 외부 fixture에만 있다. production은 관리 플래그와 경기 지배국 검사 뒤에 고정된 두 주·한국 조건을 검사하는 기존 범용 분기를 유지한다. 한국이 소멸해도 현 지배국이 정리를 수행하도록 설계했으며 그 소멸 시나리오 자체는 아직 재현하지 않았다.

초기 `[HOK][FI][CADENCE]` 표식은 엔진에서 제거됐으므로 단순 문자열 검색의 미검출을 호출 부재로 해석할 수 없었다. 이 진단 검색 오류를 바로잡고 괄호 없는 표식으로 다시 관측했다. `validation/daily-cadence-observation.json`에 최종 91+1+1 로그와 근거를 기록한다. 무거운 조건을 국가 수만큼 반복 검사하지 않는다는 분기 구조를 확인했으나 성능 벤치마크를 수행한 것은 아니다.
