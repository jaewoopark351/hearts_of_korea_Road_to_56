# 정치 노선 선택 후 중점 배치 압축 계획

> 작성일: 2026-09-22. 상태: **사용자 구현 승인 후 코드·정적 검사·새 게임 로드 확인, 동적 배치·실제 화면 미검증**. 먼저 요구사항만 문서화한 뒤 별도 코드 수정 요청에 따라 구현했다. 상세 근거와 검증 한계는 [적용 기록](incidents/2026-09-22-korean-political-compaction.md)에 남긴다. 커밋·푸시는 하지 않았다.

## 1. 기준 상태와 확인 범위

- 현재 기준은 한국 중점 362개, 절대 기준점 7개·상대 배치 355개, 전체 기본 범위 x0~204 / y0~24다. 브랜치는 `feat/korean-focus-expansion-ai`, 기반 커밋은 `691ffa3`이며 기존 F1 군수계약·F2 참모업무 미커밋 작업을 포함한다.
- 적용 직전 `common/national_focus/korea.txt` SHA-256은 `8a721a8739834bac5a0ed30f3d3335ced9ceaf4bc63439b1db8bfe2c14299aa8`, 적용 후는 `e65e15f6b101d624e5838e15969eb3a6471ef72a5313dc3a6a53f80359795fc4`다. [현재 좌표 명세](data/HOK_KOREAN_SECOND_WAVE_COORDINATES.json)는 기본 좌표와 조건부 최종 위치를 분리한다.
- 사용자는 정치 노선 완료 후 다른 가지가 숨겨지는 동작은 정상이라고 확인했다. 이번 대상은 **남은 정치 가지가 가까이 이동하지 않아 빈 공간과 긴 진입 연결선이 남는 문제**다.
- 이전 엔진 검사 기준은 HOI4 1.19.3이다. [압축 배치 기록](incidents/2026-09-21-korean-focus-compact.md)의 초기 화면 검사 및 [F2 검증 기록](incidents/2026-09-22-korean-fascist-staff.md)은 이 계획의 동적 이동 검증을 대신하지 않는다.

## 2. 적용 전 이동하지 않았던 이유

2026-09-21 압축 작업은 기존 직접 `offset` 네 블록의 이동량을 모두 `(0,0)`으로 바꿨다. 다른 가지의 숨김 조건은 유지하면서 남은 구역을 고정한 의도적인 동작 변경이었다. 공산 진입 중점에는 직접 `offset`이 없었다. 따라서 이번 적용 전에는 가지가 숨겨져도 이동에 의한 빈 공간 축소가 일어나지 않았다.

|---|---|---|---|
| 공화국 공통 진입 | `KOR_future_of_the_republic` | (127,0) | 조건 유지·이동 (0,0) |
| 공산주의 진입 | `KOR_long_live_the_dictatorship_of_the_proletariat` | (84,2) | 없음 |

절대좌표 사용 자체가 원인은 아니다. 예를 들어 공화국 진입과 파시즘 진입의 가로 거리는 40칸이다. 같은 최종 위치를 상대좌표로 표현하기만 해서는 이 거리나 연결선 길이가 줄지 않는다.

## 3. 확정한 표시 동작

- 공산·민주·파시·비동맹 네 경로 모두, **HIDE 규칙에서 해당 분기 중점을 완료한 뒤** 숨겨진 가지의 공간을 활용해 선택한 정치 구역을 가까이 모은다. 클릭·진행 시작이나 현재 집권 이념만으로 이동시키지 않는다.
- 기존 `allow_branch` 숨김 조건을 보존한다. SHOW 규칙 및 HIDE의 노선 확정 전 상태는 현재 기본 배치를 유지한다. 숨김과 이동을 서로 다른 기능으로 설계·기록한다.
- 공산·민주·파시 선택 상태에서는 표시되는 공화국 공통 진입점도 배치에 포함해 긴 진입 간격을 줄인다. 이미 가까운 민주 진입 간격을 억지로 좁힐 필요는 없으며, 공통 진입점의 이동 조건·이동량은 각 노선에 맞춰 따로 정한다. 부모와 자식에 같은 이동량을 주어 기존 긴 간격을 그대로 남기는 방식으로 끝내지 않는다.
- 비동맹 선택 상태에서는 기존 조건대로 숨겨지는 공화국 진입점을 다시 표시하지 않는다. 왕정 진입점과 그 하위 구역을 대상으로 압축하며 입헌군주·전제군주·환제국 후속 가지까지 포함한다.
- 각 정치 구역 내부의 병렬 정책 묶음과 합류 구조는 유지한다. 공산 확장 28개, 파시즘 F1·F2, 민주 추가분 등 기존 상대 배치 자손도 실제 기준점 체계에 따라 함께 처리한다. 첫 60개 중 공통 산업·군사 추가분까지 민주 구역으로 취급하지 않는다.
- 공통 산업·교육·육해공군·만주 구역은 기본 위치를 유지한다. 정치 중점과의 기존 연결은 보존하고 이동 후 연결선과 인접 공간을 확인한다. 아이콘의 가지별 색상은 바꾸지 않는다.

## 4. 적용한 이동 명세

326개 시절의 이동량을 복원하지 않고 현재 362개 배치의 이름판·아이콘·연결 통로와 고정 구역을 기준으로 산정했다. 모든 이동의 y값은 0이다.

| HIDE 완료 노선 | 정치 구역 x 이동 | 진입점 최종 좌표 | 공화국 진입 x 이동·최종 좌표 | 정치 구역 최종 x 범위 |
|---|---:|---|---|---|
| 공산 | −5 | (79,2) | −48 → (79,0) | 68~95 |
| 민주 | −35 | (92,2) | −35 → (92,0) | 73~123 |
| 파시 | −84 | (83,2) | −44 → (83,0) | 74~89 |
| 비동맹 | −101 | (85,0) | 기존 조건대로 숨김 | 75~103 |

- 공화국 진입의 이동 0 블록 하나를 노선별 세 블록으로 바꾸고 공산 진입에 하나를 추가했다. 민주·파시·왕정의 기존 이동 조건은 보존하고 x값만 바꿨다. 직접 `offset`은 총 7개이며 적용 대상은 독립된 절대 기준점 5개다.
- 공화국 세 조건은 `HIDE + 해당 노선 완료 + 다른 세 정치 노선 미완료`로 상호배타다. 콘솔 등으로 배타 노선을 둘 이상 완료한 비정상 상태에서는 공화국 진입의 추가 이동을 적용하지 않는다. 복수 이동의 합산·우선순위에 의존하지 않는다.
- 각 정치 기준점의 상대 배치 자손은 같은 이동을 한 번 받는 구조다. 자손에 `offset`을 복제하지 않는다. 공화국 진입과 정치 진입은 서로 독립된 절대 기준점이므로 각자의 이동을 설정했다.
- 기본 좌표·상대 기준·선언 순서는 362개 모두 보존했다. 공통 산업·군사·만주 133개는 고정하며, 이동 후 구역 내부 모양과 병렬 정책 연결도 유지한다. 사용자가 수용한 재벌 길들이기 → 군수조달 실무정비의 선행조건은 바꾸지 않았다.
- 파시 이동 −85 초안에는 군수계약 원가심사의 연결선과 항공전훈 연구반 이름판이 접할 정적 후보가 있어 −84로 한 칸 완화했다. 최종 네 상태에서 고정 구역과의 새 사각형·연결선 간섭 후보는 0개다. 이는 세 직각 연결 모델과 수직 통로 검사 결과이며 엔진 화면 검증은 아니다.
- 설치본 일본·오스트리아·체코의 복수 `offset`과 상대 자손 구조를 참고했다. 기존 다섯 진입 중점 완료 보상에 있는 `mark_focus_tree_layout_dirty`는 그대로 사용한다. 별도 이벤트·상시 갱신은 추가하지 않았다.
- ID·보상·기간·진행 조건·국민정신·결정·AI·숨김 조건은 그대로 유지했다. 좌표 JSON의 `nodes.after.base_absolute`는 기존 기본 좌표를 유지하며 `conditional_layout`에 이동 조건과 상태별 기준점 최종 좌표를 기록한다.

## 5. 구현 후 검증 계획

| 상태 | 확인 대상 |
|---|---|
| SHOW 초기·각 노선 완료 | 현재 기본 배치 보존, 새 이동 미적용 |
| HIDE 초기·공화국 진입만 완료·분기 진행 중 | 기존 숨김 시점 보존, 정치 노선 압축의 조기 적용 없음 |
| HIDE 공산·민주·파시 각각 완료 | 선택 가지와 공통 진입점의 최종 거리, 다른 가지 숨김, 자손의 이중 이동 없음 |
| HIDE 비동맹 진입 완료 및 입헌·전제·환제국 진행 | 왕정 구역 압축, 기존 분기 표시·진행 조건, 후속 가지 접근 |
| 저장 후 재로드·관련 세이브 | 같은 조건의 표시·위치 재현, 기준점 숨김 뒤에도 하위 중점 접근 |

정적 검사는 현재 기본 배치와 게임플레이 정의 보존, 참조·순환·선언 순서, 상태별 최종 좌표·범위·접촉 후보를 확인한다. 정적 모델만으로 실제 연결선·숨김·클릭 영역이 정상이라고 판정하지 않는다.

실제 화면 검증은 적용 후 전체 프로세스를 재시작하고, 버전·DLC·플레이세트·로드 경로·해상도·GUI 배율을 기록한 상태에서 수행한다. 각 상태의 전후 화면, 실제 아이콘·이름판·연결선·패널·바로가기·스크롤 접근을 확인하고 정상 완료와 강제 완료 진단을 구분한다. 사용자 세이브와 진행 중 세션을 보존하며 미실행 항목은 미검증으로 남긴다.

코드에서 읽은 조건으로 SHOW/HIDE 각 10개 상태를 계산했고, 기본 정의 보존·선언 순서·분기 완료 시점·공통 진입 정렬·배타 완료 예외를 포함한 정적 검사 **79개 통과 / 0개 실패**를 기록했다. 표의 실제 화면·정상 진행·왕정 세부 노선·저장 재로드 검증은 아직 완료되지 않았다. 정적 검사나 별도 새 게임 로드 성공을 동적 화면 검증으로 확대하지 않는다.
