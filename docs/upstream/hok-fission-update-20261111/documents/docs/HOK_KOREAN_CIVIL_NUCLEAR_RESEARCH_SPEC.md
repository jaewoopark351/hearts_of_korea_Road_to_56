### 보상의 의미와 경계

첫 보상 `1.00`은 국가의 핵 분야 **공용 혁신 진행도 100%**다. 특정 민간 프로젝트의 완성도 100%, 자동 착수·완료 또는 일반 핵 기술 획득을 뜻하지 않는다. 기존 「무궁화 꽃이 피었습니다」의 `0.75`와 합친 총 지급량은 **1.75, 즉175% 분량**이며, 다른 획득·소비가 있으므로 현재 잔액이 언제나175%라고 약속하지 않는다. 첫 중점 하나의 보상을1.75로 만들거나 이를 둘째 중점의 소비 비용으로 사용하지 않았다.

둘째는 숨은 기술 `commercial_nuclear_reactor_tech`를 직접 지급해 `commercial_nuclear_reactor` 건설을 해금한다. 원본 민간 원자로 프로젝트도 국가 완료 효과에서 같은 기술을 `set_technology`로 지급한다. 신규 효과는 기술 지급만 수행하며 다음 상태를 함께 부여하지 않는다.

- `sp_commercial_nuclear_reactor` 또는 선행 `sp_nuclear_reactor`의 완료 기록.
- 일반 원자로 기술, 완성된 민간 원자로 건물, 기존 일반/중수로의 자동 전환.
- 핵 실험시설, 과학자 모집·배정·수준 증가, 도상록의 일회 성장 플래그.
- 후속 원자력 함선 등 다른 프로젝트의 선행 완료 상태.

따라서 `complete_special_project`를 호출하지 않는다. 그 효과는 기술 지급과 계약이 다르고 국가 범위 완료 시 시설·과학자 효과의 적용도 별개다. 기술 지급으로 프로젝트 완료 플래그까지 생긴다고 추정하지 않는다. 실제 기술 취득 후 건설에는 유효한 주·슬롯 등 원본 조건이 적용된다.

원본 민간 프로젝트는 일반 원자로 프로젝트 완료·건설IV(`construction4`)·Götterdämmerung을 요구한다. 새 중점은 사용자가 지정한 핵 연구·선행 중점·DLC와 장기 투자를 조건으로 한 **한국 전용 대체 획득 경로**다. 일반 원자로·건설IV를 새 중점에 추가 요구하거나 원본 프로젝트 정의를 덮어쓰지 않았다. 첫 중점에는 별도 DLC 조건이나 임의의 대체 보상을 추가하지 않았다. GDR 제외 실행의 첫 표시·둘째 조건은 아래에서 관측했지만 미보유 라이선스와 첫 보상 실행까지 검증한 것은 아니다.

### 기술 기보유·진행 중 취득

둘째 bypass는 민간 원자로 **기술 보유 여부**만 검사한다. 일반 핵 연구 완료·혁신 잔액·건물 유무만으로 통과시키지 않는다. 첫 중점의 보상을 소급 지급·회수하거나 기존 연구소 보상을 다시 주는 코드도 없다.

감산 제거 전 진단 없는 두 모드 `1b1c`에서 기술 보유를 명시적으로 준비한 두 합성 입력을 각각 실제 UI로 로드·시간 진행했다. 둘째 미선택 상태와 둘째 활성 상태 모두 기술 보유를 사유로 한 **통과 팝업**을 관측했으며 저장은 둘째 완료ID1회·활성 해제를 기록했다. `clean-preowned-bypass-assessment.json`과 `clean-midactive-bypass-assessment.json`은 각각 **19/0**이다. 두 입력은 서울대·첫 완료와 핵 연구·민간 기술을 이미 보유한 별도 제어 상태이며 정상 연구나 연속 실행 중 기술 획득의 증거가 아니다.

기술 수준·획득일, 핵 혁신·프로젝트·원래 과학자·시설 program 상태는 유지됐다. 관측한 focus 본문에는 별도 bypass boolean이나 완료 시각이 없으므로 통과 사유는 실제 UI와 함께 판단한다. 값의 보존만으로 멱등적인 `set_technology`의 실행 횟수까지 입증하지 않는다. 별도 실제 실행 중 기술 지급은 Nov29.09→17시에도 중점 활성 상태를 관측했으므로 **같은 틱 즉시 통과**라고 주장하지 않는다. 선행 미완료·DLC 조건과의 우선순위와 연속 실행의 평가 시점은 미확정이며 별도 일일 감시·강제 완료 on_action은 추가하지 않았다.

당시 구현은 둘째 정수 비용35(기본245일)에 필수 첫 완료의 원본 `reduce_focus_completion_cost`를 적용해 **둘째만5일 감산**했다. 첫 핵1.00 보상을 유지하고 실험 준비를 다음 투자 기간에 반영했다. 첫 완료 후 실제 저장에 감산5가 생겼고 UI는240일을 표시했다. 이 효과의 `cost=5`는5일이며 중점 선언의 비용5주와 혼동하지 않는다. 원본 문서는 `documentation/effects_documentation.md:5709–5722`다. 당시 기본35+240=275는 설계상 일일 진행량이며 총275×24시간을 실측했다는 뜻이 아니다. 이 감산은 후속 사용자 요청으로 현재 소스에서 제거했다.

감산 제거 전에는 첫 완료 전 잠긴 둘째가 기본245일, 필수 첫 완료 후에는240일로 표시됐다.

### 소수 후보 당시의 첫 보상·제어 시작 기록

외부 실행 준비는 서울대 부모만 완료했고, 신규 첫 중점은 실제 UI로 선택하여 정상 진행했다. 첫 수동 선택 보고 시각은1936.1.1.12이며 `first-active-before-reward-Jan1-17.hoi4`에는 첫 중점 활성·진행도1이 기록됐다. 수동 팝업 확인과 완료 후 저장은1936.3.29.9에 이뤄졌고 일회 관측 로그가 처음 완료를 본 시각은1936.2.4.02다. 이 지연된 저장이나 일일 관측을 정확한 완료 순간으로 취급하지 않으며, 시작 저장에 이미 진행도1이 있어 비축0의 정확한35일 경과를 증명했다고 주장하지 않는다.

같은 실행의 두 저장에서 핵 `program_status/breakthrough` 원시값은 **0→10000**, 나머지 육군·해군·항공 분야는 각각0으로 같았다. 첫 중점은 정확히 한 번 완료됐고 둘째는 미완료였다. 이 제어된 `value=1.00` 보상의 실제 직렬화 차이를 확인했으며 검증되지 않은 `has_breakthrough_points` 역치 로그나 보편적인 원시단위 환산을 수치 근거로 사용하지 않는다. 첫 보상 판정은 `validation/first-normal-reward-assessment.json`의 **9 PASS / 0 FAIL**이다.

독립적인 `validation/research-state-immutable-baseline.json`의 **37 PASS / 0 FAIL**은 첫 보상 전·후와 둘째 시작 시점의 원래 과학자 역할·수준, KOR 시설 program 목록, 등록 프로젝트·완료 상태의 보존 및 단계별 지정 기술 상태를 확인한 기준선이다. 둘째 시작 전 별도로 준비한 핵 연구 기술까지 처음부터 동일했다고 주장하지 않는다. 둘째 완료나 모든 실제 프로빈스 건물의 보존 증거도 아니다. 소스 보존의 **503/0**, 자산의 **28/0**과 합산하지 않는다.

완료 후 유휴 저장에는 비축 진행도10이 있어 둘째 기간 시험에 그대로 쓰지 않았다. 승인된 외부 합성 사본에서 관측된 `countries/KOR/focus/progress` 한 값만 **10→0**으로 바꾸고, 그 외 바이트 동일을 확인했다. 이후 실제 로드·핵 연구 기술 준비 결정·둘째 UI 선택을 수행했다. 핵 연구 기술은 정상 연구가 아니라 시험 조건으로 준비했으며, 비축0도 자연 획득 상태라고 부르지 않는다. 둘째 시작 저장 `second-start-zero-bank-Mar29-09.hoi4`의 SHA-256은 `480AF033049055B0C63CC2582798AD3BFA786D34E1F1D068D51E00A70AE99E16`이다. 이 시험이 위240/240 미완료를 드러냈으며 새 정수 비용 전략의 완료 증거로 재사용하지 않는다.

전용 AI 생성 그림 두 개와 일반·광택 sprite를 등록했다. 핵분열은 원자·실험 장치의 밝은 회색·은색, 민간 투자는 냉각탑·원자로의 중립 회색·동색이다. `interface/HOK_KOR_civil_nuclear_research.gfx`는 `GFX_HOK_KOR_focus_fission_chain_reaction_experiments`와 `GFX_HOK_KOR_focus_civilian_nuclear_investment` 및 각각의 `_shine`을 정의한다. 100×88 알파 DDS·마스크·바닐라 광택 사본은 `gfx/interface/goals/HOK_KOR/civil_nuclear_research/` 안에 있다.

[그림 출처·가공 기록](HOK_KOREAN_CIVIL_NUCLEAR_ICON_CREDITS.md), [매니페스트](data/HOK_KOREAN_CIVIL_NUCLEAR_ICON_MANIFEST.json), [실제 크기 미리보기](assets/civil-nuclear-research/actual-size-preview.png)에 생성 도구·공개되지 않은 모델명·전문 프롬프트·선정 원본·기계적 축소·현재 버전의 원본 광택 출처·해시를 구분해 기록했다. 자산 소스 확인28/0은 실제 잠김·활성·완료·광택 화면의 증거가 아니다.

## 감산 제거 전 실행 검증 결과와 한계

당시 소스ECA의 보존 검사는 **506/0**이며 과거 소수 후보503/0과 구분한다. `ff98`에서 첫 감산5·핵 보상, 둘째 정상 선택·진행239·240번째 일일 진행의 기술 지급·실제 건설 대기열을 확인했다. 감산 제거 후245일의 실행 검증으로 재사용하지 않는다. 실제5760시간이나 첫 정확35×24시간을 입증하지 않는다. 이전 소수 후보의 기간 실패·완료ID 손실 원인 미확인도 남긴다.

임시 진단을 제외한 **Korean Language → 저장소, 모드2개·DLC36개**의 전체 재시작·메인 메뉴 도달을 확인했다. UI 확대 재확인과 system.log의 체크섬은 모두 **`1b1c`**다. `validation/clean-two-mods-1b10-log-assessment.json` **9/0**은 메인 메뉴 시점에 현재 버전 기준선 대비 error.log45행의 정규화 추가0·제거0, text.log 추가0·제거0을 기록한다. `clean-two-mods-1b10`은 최초 화면 판독을 따른 보관 폴더 식별자이며 체크섬 충돌이 아니다.

이후 시험 저장들을 로드한 최종 로그는 **45→74행, 정규화 추가29행·제거0행**이다. 제거한 진단의 저장 내 이벤트/결정 참조, 저장 decision 파싱·중복, 파일 이름 변경 errno2와 합성 기보유 입력에서도 재현된 기존 `hours` 토큰 오류를 원문대로 별도 보존했다. 명명된 신규 생산 중점 오류는 없지만 전체 과정을 새 오류0이나 저장 파싱 무오류라고 쓰지 않는다. `validation/clean-two-mods-final-before-dlcoff-log-assessment.json`을 따른다. 위24/0·각19/0은 열거한 상태의 확인이며 이 한계를 지우지 않는다.

`hours=2147483643`은 수정하지 않은 첫 완료·비축0 저장에도 있던 MON/state819의 국경 전투 `removed_unit`(unit2563/type51) 필드다. 진단 활성 상태의 비축0 로드에서도 오류가 있었고 기보유 합성 입력에서는 기술 기록9행 삽입만큼 줄 주소만 이동했다. 기술 삽입·진단 제거가 이 필드를 만든 원인은 아니며, 원래 writer/loader의 최초 원인은 **UNPROVEN**이다. 제거된 duration 이벤트 참조 오류와 별도로 기록한다.

별도 전체 재시작에 `-debug -exclude_dlc=Gotterdammerung -start_tag=KOR`를 사용해 진단 없는 새1936.1.1.12 한국을 로드했다. 실제 둘째 tooltip에서 **핵 연구 미완료와 GDR 조건이 모두 빨간X**였고 첫 선행도 미완료였다. 화면은 `runtime-ui/clean-fresh-KOR-GDR-excluded-tooltip.jpg`다. 시작 로그는 여전히 DLC36개와 GDR을 열거하지만 실제 `has_dlc` 조건은 거짓이었다. 이를 DLC35개 실행이나 GDR 소유권이 없는 환경과 동일하다고 확대하지 않는다.

핵 연구1을 준비한 저장은 누락 GDR·제거된 진단 모드 경고로 로드 자체가 차단되어 **DLC 조건 하나만의 시작 차단**을 확인하지 못했다(`clean-GDR-excluded-prepared-save-blocked.jpg`). 새 게임 로그는 `validation/clean-fresh-KOR-exclude-GDR-log-assessment.json`에서 기준45→51행, 추가6행·제거0행과 text.log0/0을 기록했다. 추가 행은 land cruiser 애니메이션4개·mesh1개·장비 GFX1개이며 근본 원인을 이번 중점 작업에서 조사하지 않았다. 불러온 시험 저장의 파싱 오류는 이 새 게임 로그에 섞지 않았다.
