## 3. 가져올 콘텐츠와 범위 밖의 작업

### 3.1 최신 원본에서 선택할 한국 업데이트

[원본 2차 확장 기록](../../../hearts_of_korea/docs/HOK_KOREAN_SECOND_WAVE_PLAN.md)의 실제 적용 소스가 기준이다. 미구현 후보 목록이나 과거 378개 단계의 수치를 최종 목표로 삼지 않는다.

| 분야 | 추가 중점 | 통합할 주요 내용 |
|---|---:|---|
| 공산 | 28 | 지도자별 경제정책, 후속 내정·기술보급, 병렬 접근과 공유 사업 슬롯 |
| 파시즘 | 24 | 조달, 참모, 동원, 점령행정, 삼군 조정, 재건예산과 기존 선택 조건 |
| 입헌군주 | 14 | 책임내각·민생·공익·연락 제도 |
| 전제군주 | 14 | 중앙·지방 행정, 구휼, 군제·관료 전문화 |
| 환제국 | 14 | 형성 후 운영, 연락·재건·복귀와 최신 가지 배치 |
| 만주 | 20 | 지역 제도 I/II·기간제 집중 사업과 영토/정부 조건 |
| 공통 산업·군사 | 20 | 수출·원료 회수·기동·해군·공군 후속 |
| 합계 | **134** | **국민정신 63개, 기간제 사업 18개, 별도 주 동적 변동치 12개** 포함 |

새 콘텐츠만 덧붙이면 끝나는 업데이트가 아니다. 기존 중점의 상대좌표 기준 선언 순서 수정, 정치 분기 SHOW/HIDE 이동과 배치 변경도 검토 후 이식한다. 기존 326개 ID는 보존하되, 원본에서 의도적으로 바꾼 배치·연결은 변경 전후 계약으로 기록한다. 기존 326개 전체가 바이트 동일해야 한다는 검사를 새 구현에 그대로 적용하지 않는다.

새 파일의 국민정신·결정·동적 변동치·한영 localisation·GFX를 소비 중점과 함께 연결한다. 기존 역사 AI 파일에 신규 134개를 자동으로 추가하지 않는다. 원본의 신규 `ai_will_do`, 정치·전시 선택, 사업 AI 조건을 유지하고, 기존 민주 역사 계획과 실제 선택 경쟁을 따로 검증한다.

현재 선택안의 신규 runtime 파일은 텍스트 57개(게임플레이·현지화 41개, GFX 16개)와 HOK DDS 231개, 합계 **288개**다. 여기에 기존 `common/national_focus/korea.txt` 병합이 필요하다. 기존 세 확장 국민정신 파일은 주석 차이와 실제 gameplay 차이를 구분하고, 같은 내용의 파일을 불필요하게 덮어쓰지 않는다. 이 수는 현재 조사한 allowlist이며, 후속 참조·충돌 감사에서 근거 있는 추가가 발견되면 계획과 원장을 함께 갱신한다.

### 3.2 이번 업데이트로 가져오지 않을 것

- donor 전체 `common`, `history`, `events`, `map`, `interface` 폴더의 일괄 복사.
- 일반 일본·중국 콘텐츠, 세계 지도·주 역사·OOB·공용 시스템의 별도 업데이트. 한국 경로에 실제 필요한 새 연결이 발견되면 해당 정의만 추가 검토한다.
- 임의의 RT56 맞춤 보상 강화·너프, 중점 수 채우기, 새 AI 경로 설계, 새 이미지 제작이나 기존 이미지 전면 재색칠.
- 원본에서 아직 선택·구현하지 않은 보병장비 한정 생산량 또는 생산비 대안 등 미결 설계.
- 호환판의 국가사·MAN 수선·지도·음성·기존 사용자 변경을 이번 중점 업데이트에 편승해 정리하는 작업.
- descriptor 의존성·Workshop ID·launcher playset 변경, 기존 세이브 마이그레이션, 외부 게시. 실행 구성 변경은 후속 runtime 작업의 승인 범위에서만 다룬다.

## 4. 통합 방식과 보존 계약

### 4.1 고정 입력 위에 한국 변경만 겹친다

현재 생성 체계는 donor 전체를 최신 HEAD로 따라가지 않는다. `source_snapshot.py`와 `hok_source_lock.json`은 과거 donor 기반과 한국 20개 파일을 고정하고, `hok_icon_lock.json`은 당시 미커밋 60/29 이미지 세트를 별도 기록한다. 이 구조를 유지하면서 **선택 파일의 최신 커밋 기반 overlay**를 추가·갱신하는 방식을 제안한다.

1. 기존 호환판 출력과 고정 입력을 보존하고, 파일별 원본 commit/blob·checkout bytes·SHA-256을 기록한다.
2. 선택 소스는 `be5fb40`의 한국 관련 파일 allowlist다. 전체 base commit을 최신으로 바꾸어 무관한 파일이 들어오게 하지 않는다.
3. 과거 미커밋 artwork 출처는 역사 기록으로 유지한다. 최신 커밋에서 선택한 새 자산은 Git 기반 출처로 구분한다.
4. 기존 base, 새 donor, 현재 호환판, RT56 소유 정의를 비교한다. 파일 전체가 HOK 소유인지와 공유 정의를 함께 포함하는지를 구분한다.
5. 검토된 변환만 생성기에 반영한다. 입력 해시가 바뀌면 실패하고, 현재 출력이 검토한 이전 해시와 다르면 덮어쓰지 않는다.
6. 새 파일이 생성·manifest·pruning·검사 모두에서 같은 allowlist를 사용하도록 맞춘다. 생성기 없이 runtime 파일만 수동 복사하지 않는다.

기존 `korea.txt`의 파일 분류는 RT56 동일 경로의 한국 트리를 대체하는 **OVERRIDE**를 유지하고, 내부 작업 방법은 기존 고정 donor·최신 donor·현재 포트의 차이를 검토하는 병합이다. 병합 절차를 쓴다는 이유만으로 원장 분류를 임의로 `THREE_WAY_MERGE`로 바꾸지 않는다. 새 HOK 파일의 `ADD`와 DDS의 `ASSET_COPY`는 전체 충돌 감사 전 잠정 분류다.

### 4.3 만주 새 지역 효과: 구현 전 확정할 핵심 병합

[만주·공통 명세](../../../hearts_of_korea/docs/HOK_KOREAN_REGIONAL_COMMON_FOLLOWUP_SPEC.md)는 M1/M2/M4를 원본 주 `328`, M3를 `328·714·717`에 적용한다. donor와 호환판에는 이 세 state 파일이 없고, 원본 환경의 vanilla와 RT56의 같은 ID는 실제 province 구성이 다르다. 이번 읽기 비교에서 328의 vanilla 목록은 39개, RT56 목록은 16개이며, 714는 28개 대 4개, 717은 30개 대 21개다. RT56 신규 province도 섞여 있어 같은 숫자 유지가 같은 지리 보존을 뜻하지 않는다.

**제안하는 처리:** 원본 정책의 물리적 대상 지역을 기준으로 RT56 대응 주 집합을 도출한 뒤, 정책별로 명시적인 대응표를 확정한다. 이를 위해 province 중첩, 행정 중심지, 현재 host 경계, 정책의 지리적 설명과 경제 효과를 함께 검토한다. 주 단위 modifier는 일부 province에만 적용할 수 있다고 가정하지 않으며, 부분 중첩 주의 포함·제외에는 근거를 남긴다.

| 정책 | 원본 범위 | 대응표에서 함께 고정할 것 |
|---|---|---|
| M1 공공서비스 | 328 | 진입·완료 보상·소유/통제·강조·복구 대상 |
| M2 공동체 지원 | 328 | 위 대상 및 민주정부 조건·정부 상실 정리 |
| M3 원료 회수 | 328·714·717 | 다지역 전체 가용 조건, 한 곳 상실 시 사업 전체 취소, 나머지 유효 영구 효과 보존 |
| M4 도시 운영 | 328 | 기존 추방/신도시 경로와 지역 제도·사업 대상 |

원본 `328`만 그대로 쓰는 방법은 RT56 분할 뒤 적용 지역이 줄 수 있다. 반대로 네 사업을 모두 기존 만주 15개 주에 확대하면 보상과 요구 영토가 달라진다. 어느 쪽도 자동 선택하지 않는다. 구체적인 대응 ID 목록은 이 문서에서 아직 확정하지 않았으며, 구현 초기에 근거와 함께 기록할 병합 결정이다. 자료로 해소되는 통상적인 대응은 그 근거로 결정하고, 정책의 수혜 범위를 실질적으로 재설계해야 할 때만 사용자 선택을 요청한다.

결정된 집합은 focus 조건·완료 보상, decision 가용·취소·종료·재착수·지도 강조, dynamic modifier 수명, localisation 설명과 검사에 일관되게 사용한다. 기존 전체 만주 획득 경로의 15개 주 목록 자체는 바꾸지 않는다.

신규 환제국 H1–H4에도 원본 만주 8개 주 중 적격 거점 하나 이상을 요구하는 OR 조건이 있다. 이는 M1–M4의 모든 대상 지역 소유 조건과 다르다. 원본 거점 각각의 RT56 대응 및 원본의 “하나 이상” 조건을 보존할 해석을 별도로 기록하고, 전체 15개 주 소유를 요구하는 AND로 바꾸거나 분할주 하나만으로 원본 전체 주 조건을 자동 충족시킨다고 가정하지 않는다. H 거점 상실은 중점 착수·진행을 막지만 이미 얻은 환제국 국민정신을 제거하는 조건은 아니다. 그 정신의 실제 제거 조건을 보존하고, M 지역 제도의 영토·정부 상실 제거 규칙을 H에 공통 적용하지 않는다.

### 4.4 배치와 연결

- 최신 원본의 460개 상대좌표·선언 순서·연결을 출발점으로 삼고, 호환판 기존 보상·ID 변환과 분리하여 검토한다.
- 같은 ID를 가진 원본 중점과 호환판 중점의 차이를 효과/조건/배치/이미지로 나누어 기록한다. 공백·주석을 제외한 허용 차이는 명시적인 목록으로 관리한다.
- `relative_position_id`의 정의가 소비자보다 먼저 나오는지, 기준 연결이 순환하지 않는지와 전체 좌표를 확인한다. 배치 기준이 실제 선행조건과 같다고 가정하지 않는다.
- 정치 경로 완료 전·후, SHOW/HIDE, 숨겨진 기준 중점, 서로 배타인 경로별 조건부 이동을 확인한다. 신규 134개만 보고 기존 중점·이름판·연결선 충돌을 놓치지 않는다.
- 환제국 H1의 최신 오른쪽 배치는 원본 기록상 직전 UI 결과와 소스가 다르다. 과거 스크린샷을 최신 배치 검증으로 재사용하지 않는다.

## 5. 그림과 출처의 이식 방식

### 5.1 HOK 그림은 원본 파일 그대로 가져온다

신규 DDS 인벤토리는 **232개**다. 그중 HOK 중점 134·국민정신 63·주 수정치 12·결정/범주 22개, 합계 **231개**를 로컬 runtime 자산으로 복사하는 안이다. 남은 1개는 원본이 별도로 복사한 vanilla 광택 오버레이다. 이 구분은 이미지 수와 최종 선택 복사 수의 차이를 설명한다.

HOK 그림은 format·dimensions·alpha·frame layout·파일명 대소문자를 보존하고 DDS를 재변환하지 않는다. 16개 신규 GFX registry의 `HOK_KOR_` 이름과 소비자를 추적해 정확한 경로로 연결한다. 국민정신 폴더의 75개 새 그림에는 **국민정신 63개와 주 수정치 12개가 함께 있음**을 구분한다. 국민정신 75개라고 세지 않는다.

결정 이미지는 전용 32×32, 범주는 51×40 파일을 선택한다. 중점 100×88 이미지를 결정에 직접 재사용하지 않는다. 이 규격은 donor의 1.19.3 관측값이므로 RT56 UI에서 행·제목·설명과 함께 검수한다.

### 5.2 공용 광택은 기존 host fallback 유지 제안

현재 포트는 `gfx/interface/goals/shine_overlay.dds`를 vanilla 공용 자산으로 사용한다. 이 배치에서는 원본의 `gfx/interface/goals/HOK_KOR/shine_overlay.dds`를 복사하지 않고 기존 예외를 유지하는 안을 제안한다. 두 파일의 현재 SHA-256은 동일한 `BB416649358C73D34AACD46BAD61BC44211FAC8111627B56E25F385AD98F4448`이다.

- 신규 registry의 오버레이 참조만 기존 공용 상대경로로 변환한다. HOK 마스크와 아이콘 본체는 로컬 경로를 유지한다.
- 기존 60개 shine registry는 원본과의 차이가 이 경로·주석뿐인지 확인하고 현재 포트 bytes를 유지한다.
- 실제 공급자는 vanilla이며, RT56·언어 모드가 같은 경로를 가리는지 확인한다. 파일 분류의 `USE_RT56` 표기를 쓰더라도 실제 공급자가 RT56라고 오기하지 않는다.
- 외부 fallback을 유지하므로 전체 그림 연결이 완전히 자급된다고 표현하지 않는다. 향후 로컬 오버레이 복사는 별도 범위 검토 사항이다.

### 5.3 출처와 문서

모듈별 크레딧·이미지 manifest·필요한 palette 및 최종 좌표 자료를 선택 보존한다. Ultimate HOI4 GFX의 고정 리비전·재사용 근거, 원작 HOK의 왕관·태극 소재, donor 합성·가공, 호환판 선택·경로 변환 기여를 각각 구분한다. vanilla 오버레이를 공개 팩의 사용 허가에 포함시키지 않는다.

이번 목표는 이미 만들어진 원본 자산의 이식이다. AGENTS의 AI 제작 허용 지침이 새 그림 생성이나 기존 그림 교체를 요구하는 것은 아니다. 원본의 검수 문서는 그 소스와 실행을 설명하는 자료로 보존하고, 포트 검수 기록은 별도로 작성한다.

## 6. 구현 배치와 산출물

아래 배치는 작업 순서이며 Git 브랜치 생성·커밋·병합 지시가 아니다. 하나의 `korea.txt`를 임의로 분리하거나 중복 등록하지 않는다. 모듈별 검토·검증을 하더라도 생성기는 그 단계의 허용된 입력과 참조가 완결된 파일을 출력해야 한다.

P4의 각 정책 묶음에서는 원본 수치·기간·선행·선택·AI를 이식한다. 3–5개 정도의 묶음은 검토 단위이며 134개 전체 목표를 일부만 처리하고 완료라고 보고할 근거가 아니다. 만주 병합 검토와 독립적인 그림·명세 정리는 병행할 수 있지만, 미확정 지역 효과를 추측하여 적용하지 않는다.

## 7. 보류 사항과 완료 판정

| 항목 | 현재 상태 | 다음에 필요한 근거 |
|---|---|---|
| 신규 만주 지역·환제국 거점 대응 | **미확정** | source province·정책 의도·RT56 경계 비교, M의 지역 효과 집합과 H의 거점 OR 조건을 별도 확정 |
| 신규 정의의 충돌 | **전체 감사 미실시** | 경로·논리 ID·localisation·sprite를 포트/원본/RT56/vanilla/언어 계층과 비교 |
| 최신 host 전체 입력 | **descriptor/manifest 관찰만 완료** | 관련 고정 파일의 해시 및 구현 도중 source drift 확인 |
| 기존 aggregate 불일치 | **과거 아이콘 이식 때 19 PASS / 0 WARNING / 1 ERROR 기록** | 현재 구현 전 기준 검사로 재확인. KOR history를 임의 수정하거나 실패 gate를 약화하지 않음 |
| localisation 계약 | **기존 ADR-0003 Pending Runtime** | 동일 언어 구성의 R1/C1 대조와 최신 11쌍의 가시성 확인 |
| 실제 AI·장기 진행·저장 | **새 134개 RT56 증거 없음** | 별도 실행·새 게임 저장/재로드 및 시나리오별 관찰 |

후속 구현 완료는 모든 선택 파일의 출처·분류가 기록되고, 생성 재현과 신규·회귀 정적 계약이 충족되며, 요구된 runtime 사례가 관찰됐을 때 주장한다. 이전 20 PASS, donor의 강제 보상 검사, 문서의 계획 표를 새 460개 포트의 통과로 바꾸지 않는다. 기존 독립 불일치가 남으면 그 원인·영향·처리 범위를 기록하고 **전체 검사 통과 또는 릴리스 준비 완료라고 보고하지 않는다**.

기존 HOK/호환판 세이브 호환은 이번 이식의 기본 보장이 아니다. 신규 게임 전용 정책을 유지한다. 기존 세이브 지원은 대표 저장의 진행·재저장·재로드와 별도 마이그레이션 판단이 있어야 한다. 멀티플레이와 DLC 조합도 실제로 검사한 범위만 보고한다.

이번 문서화의 완료 기준은 구체적인 이식 범위·보존 계약·순서·미결 판단·검증 방법이 연결된 세 문서와 인덱스다. 이 완료는 콘텐츠 이식 완료, 게임 호환성 보증, 커밋 또는 Workshop 게시를 뜻하지 않는다.
