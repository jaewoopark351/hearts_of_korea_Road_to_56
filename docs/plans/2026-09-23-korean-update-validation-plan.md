# 2026-09-23 한국 2차 업데이트 이식 검증 계획

상태: **구현 전 검증 계약**. 이후 콘텐츠·정적 검사를 구현했다. 실제 검사 결과와 남은 게임 검증은 [구현 기록](../implementation/2026-09-23-korean-second-wave-port.md)을 따른다. 아래 미래형 표현은 계약 작성 당시의 계획이다.

이 문서는 원본의 추가 중점 134개·국민정신 63개와 연결 콘텐츠·이미지를 현재 326개 중점의 RT56 호환판에 이식할 때 사용할 검증 계약이다. 향후 구현·진단·실행 작업을 설계하며, 문서 작성 자체는 해당 작업을 실행할 권한이나 통과 결과가 아니다. 정의 수 460개는 모든 정치·배타 경로를 한 게임에서 완료한다는 뜻이 아니다.

범위와 통합 결정은 [전체 이식 계획](2026-09-23-korean-second-wave-port-plan.md), 실제 파일·자산 묶음은 [파일별 이식 목록](2026-09-23-korean-update-file-inventory.md)을 함께 따른다.

근거는 [저장소 지침](../../AGENTS.md), [기존 포트 구현](../implementation/2026-09-22-korean-focus-update-port.md), [부분 동원 보상](../implementation/2026-09-22-independent-party-reward.md), [기존 이미지 이식](../implementation/2026-09-22-korean-icon-port.md), 원본의 [2차 확장 계획](../../../hearts_of_korea/docs/HOK_KOREAN_SECOND_WAVE_PLAN.md)이다. 원본 문서의 PASS 수·UI 관측·실행 체크섬을 포트 결과에 합산하지 않는다.

## 1. 검증 기준선과 증거의 구분

구현과 실행 직전에 아래 항목을 새로 기록한다. 현재 관찰값은 실행할 대상의 지원 선언이 아니다.

| 항목 | 필요한 기록과 판정 |
|---|---|
| 호환판 | branch·commit·작업 트리 변경, 이식 전 runtime 해시, 적용한 모듈과 생성기 개정 |
| donor | 실제 사용한 commit/blob/checkout 방식·파일별 SHA-256. 이번 조사 대상은 `be5fb40dbd8de33e5adbf65e808bcb0e8c283560`이며 후속 변경은 별도 검토 |
| RT56 | manifest·갱신 시각·관련 파일 SHA-256을 작업 전후 확인. 이번 관찰 manifest는 `7475007536894105204`, descriptor SHA-256은 `5B323861ABD63E31CB896277E3EA58BA4BCD9FCEEDA957B50792065E42E03F61` |
| 엔진 | 실제 실행 HOI4 버전/build/checksum, OS, 활성 DLC, 언어, GUI 배율·해상도 |
| 실행 환경 | playset 이름, 선언 의존성, 배열에 기록된 순서, 실제 물리적 `.mod` 경로, 유효 정의가 어느 파일에서 왔는지 확인한 근거 |
| 자료 보존 | 실행 전 로그를 작업별 증거 디렉터리에 보존하고 각 실행의 시작·종료 시각, 조건 준비 방법, 로그 해시·UI 관측을 연결 |

2026-09-23 문서 조사 중 읽힌 최신 `system.log`는 14:29:53 시작의 HOI4 `1.19.3.0.c01a (c5c7)`다. 현재 launcher 목록은 donor `3793992662`를 포함한 Workshop 모드 13개이며 RT56 `820260968` 및 호환판 `3796816200` 항목이 없다. 이는 사용자 혼합 구성으로, 아래 R0/R1/C0/C1 결과가 아니다. `disabled_dlcs`가 비어 있다는 사실도 실제 활성 DLC 목록·라이선스 검증을 대신하지 않는다. 이번 문서화에서 playset·설정·사용자 데이터는 변경하지 않는다.

과거 포트 기록은 두 층으로 보존한다. 2026-09-22 기존 중점 이식은 제한된 C1/R0/C0 진행·fixture 결과가 있고, 이후 부분 동원·아이콘 반영 기록의 aggregate는 **19 PASS / 0 WARNING / 1 ERROR**였다. 오류는 KOR history의 기존 MtG 분기 전쟁 지지도 `0.1`과 생성기 기대 `0.05`의 불일치다. 이를 새 업데이트 결함으로 분류하거나, 자동으로 되돌리거나, assertion을 완화하지 않는다. 별도 변경 소유권·처리 결정을 기록한 뒤 해당 gate를 다시 검증해야 한다. 9월 6일의 음악 오류·새 게임 크래시와 9월 22일의 제한된 후속 관측은 각각 당시 기록이며 현재 상태로 단정하지 않는다.

모든 결과 행은 `NOT RUN`, `PASS`, `FAIL`, `BLOCKED`, `SKIP`과 증거 경로를 갖는다. 사실·원인 해석에는 `CONFIRMED`, `STRONGLY_SUPPORTED`, `UNPROVEN`, `DISPROVEN`을 별도로 사용한다. SKIP을 PASS로 합치거나 강제 완료를 정상 진행으로 표현하지 않는다.

### 기존 포트 회귀 계약

- [ADR-0002](../decisions/0002-map-id-migration.md)의 province `13414–13447 → 13535–13568`와 state 매핑 전체를 유지한다. 신규 파일의 트리거·효과·목록·지도 강조·취소에서 같은 지리 대상을 사용한다. 숫자 검색만으로 관계없는 수치까지 치환하지 않는다.
- 기존 만주 8개 주와 RT56 분할주 `941–947`의 총 15개 처리, 승전·만슐루스·국뽕·분리주의·대일 강화의 소유/통제·이전·코어·주둔군 계약을 유지한다. MAN 소멸/독립/일본 종속 상태별로 기존 강화 결정과 조건부 휴전·합병을 대조한다.
- 신규 H 경로의 원본 8개 만주 거점 조건과 M1/M2/M4의 원본 `328`, M3의 `328·714·717`은 **지리별 병합 결정이 선행**한다. RT56 분할주 중 실제 해당 지역의 목록을 확정하고 정책별 착수·유지·제거·재착수·툴팁을 같은 집합으로 검사한다. 모든 M 사업에 15개 주를 일괄 넣는 방식은 승인된 해석이 아니다. H의 “적격 거점 하나 이상”과 M의 “모든 대상 지역 소유·통제”를 구분하며, H 거점 상실 후 착수·진행 차단과 기존 환제국 국민정신의 유지를 각각 확인한다. M 지역 효과 제거 규칙을 H 정신에 적용하지 않는다.
- `KOR_independent_party_in_power`는 민간경제·초기 동원에서만 부분 동원으로 올리고, 기존 부분 동원·전쟁경제·총동원·기타 경제법은 그대로 둔다. 기존 보상 순서·내용을 보존하며 최신 donor에 같은 보상이 들어 있을 때 이중 삽입하지 않는다.
- MAN 캐릭터의 KOR 소유·모집 guard 및 `is_hired_as_advisor` 검사를 유지한다. 한국 인물을 모집하지 않은 상태, 모집/고용한 상태를 나누고 기존 dynamic idea 오류를 다시 만들지 않는다.
- 기존 60개 확장의 지역 사업 90일·공동개발 180일 반복, 시민교육 525·919·1145 보상과 부지 검사, 협정 수락/거절·쌍방 관계 제거를 계속 검사한다. 기존 이미지 60/29개·단일 음성 registry·KOR 고유 항공기 ID·폐기된 수송기 기술 제거도 회귀 범위다.

검사기는 기대값을 수정한 production에서 그대로 추출하여 자기 자신을 통과시키면 안 된다. 승인 명세·고정 donor와 호스트 지리 계약에서 독립 기대값을 만든다. 의미 파서는 순서 있는 반복 키를 보존하며 제한된 evaluator가 지원하지 않는 구문은 무조건 통과시키지 않는다.

향후 최소 실패 유도 사례는 다음 결함을 **생산 파일에 쓰지 않는 검사 입력**에 주입하여 실제로 거부하는지 확인한다: AND 부모 하나 누락, 원본 state ID 잔존, M3 일부 지역 상실 시 잔여 기간제 효과, 공유 대기 플래그 오타, 취소 PP 환급 추가, 하위 정신 중복 잔류, MAN guard 제거, 전쟁경제 하향, local DDS 누락/대소문자 불일치, localisation 한쪽 키 누락, 상대 기준 순환·정치 offset 중복 상속. 이는 새로운 검사 보완이 필요한 동작 결함 사례이며 단순 행 수 맞추기와 다르다.

입력·생성기 확장이 구현된 뒤 저장소 루트에서 실행할 기존 CLI는 아래와 같다. **이번에는 실행하지 않았다.** 생성·복사 옵션은 이 검증 목록에 섞지 않으며 새 CLI 옵션이 이미 존재한다고 가정하지 않는다.

```text
python tools/source_snapshot.py --check
python tools/build_korean_focus_update.py --check
python tools/check_korean_focus_update.py --check
python tools/check_korean_focus_update.py --self-test
python tools/build_integration_manifest.py --check
python tools/prune_non_korean_content.py --check
python tools/validate_port.py
```

기존 `--self-test`의 검출 사례는 신규 기능 전체를 다루지 않는다. 구현 후 해당 사례를 확장한 결과와 aggregate를 기록한다. aggregate에 포함된 검사를 변화 없이 반복할 필요는 없다. Python 경로는 환경에서 확인하며 도구 실행을 위해 임의 설치하지 않는다.

## 3. 실행 행렬과 시작 조건

| 구성 | 활성 모드 | 목적 |
|---|---|---|
| R0 | RT56 | 같은 엔진/DLC의 호스트 기준 오류·일반 국가 진행 |
| R1 | RT56 + 선택 localisation 1종 | 번역층 고유 영향·키 교체 확인 |
| C0 | RT56 + 호환판 | 번역 없는 포트 로드·한국/비한국 새 게임·게임플레이 |
| C1 | RT56 + 동일 localisation + 호환판 | 실제 지원할 언어 구성·UI·게임플레이 |

두 번역 모드를 섞은 결과로 어느 하나를 지원한다고 결론 내리지 않는다. [언어 계약 ADR](../decisions/0003-localisation-contract.md)에 따라 후보별 R1/C1을 같은 조건으로 짝지어 검증한다. V0는 엔진 문법·기본 동작과 호스트 차이를 분리할 필요가 있을 때만 추가한다. C0/C1에는 HOK donor를 넣지 않는다.

실행 승인 후에도 사용 중인 게임·세이브를 시험 대상으로 삼지 않는다. 외부 launcher·사용자 데이터 변경은 별도 승인 범위를 확인한다. 실행마다 전체 프로세스를 종료하고 재시작하여 모드 물리 경로·로그를 확인한다. hot reload·같은 프로세스 재로드는 최종 재시작 검증의 대체가 아니다. 시험 환경 인자가 무시되어 다른 playset이 로드되면 해당 결과를 제외하고 원인을 기록한다.

우선 동일 기준선에서 GER와 KOR의 1936 새 게임을 일시정지 지도 진입 → +1/+7/+30일 순서로 확인한다. KOR 정치·지도·기술·OOB·이미지와 일반 JAP/CHI의 RT56 콘텐츠를 비교한다. 기존 포트 실패와 신규 delta 실패를 구별하고 가장 이른 오류부터 분리한다. 전체 로그 줄 수보다 같은 원인별 정규화 오류·발생 시점·빈도와 재현 조건을 비교한다. 1939를 지원한다고 주장하려면 별도 해당 bookmark 검증이 필요하다.

## 4. 신규 정책과 수명의 실행 계약

전체 134개 중점·63개 정신·12개 주 효과의 등록·즉시 보상은 별도 진단에서 전수 확인한다. 정상 경로로 동시에 달성할 수 없는 선택은 독립 새 게임/준비 상태를 사용한다. 효과 강제 호출의 준비 조건과 실제 UI·일일 엔진 갱신 결과를 분리한다.

### 18개 사업과 12개 주 효과

각 사업마다 해금 → 표시 → 착수 가능 → UI 비용 지불 → 활성 → 자연 종료 또는 취소 → 공통 대기 → 재착수의 전 과정을 기록한다. 자동 `remove_trigger` 검증에는 날짜 진행이 필요하다. 제거 효과를 직접 실행하는 검사는 그 대체가 아니다.

- 정책별 실제 PP·민공 점유를 확인한다. 공산 첫 4개 중 두 사업은 PP 150·민공 0, 다른 두 사업은 PP 75·민공 2라는 차이를 보존한다. 만주 4개는 PP 150·민공 0이다. 비용이 없는 민공 수량 게이트를 다시 추가하지 않는다.
- 각 공유 슬롯 그룹의 동시 하나·90일 활성·완료/취소 뒤 90일 대기를 각각 검증한다. 공산 경제정책 그룹과 후속 내정/기술 8개 그룹처럼 별도 슬롯을 허용한 경우까지 전역 하나로 묶지 않는다. 실제 그룹별 구성은 소스 계약표에서 확정한다.
- 시작 직후·종료 직전·종료 직후·대기 만료 직전/직후를 관측하고 회차별 비용·효과를 기록한다. 사업 반복으로 일회 중점의 PP·경험치·공장이 재지급되지 않아야 한다. 90일의 표시와 실제 엔진 경계 시각을 모두 남긴다.
- 정부·지도자·내전·항복·태그·소유·통제 조건을 각 사업의 실제 계약대로 하나씩 잃게 하여 취소·민공 점유 해제·기간제 제거·대기 시작을 확인한다. PP 환급이 없는 사업은 UI 차감 후 취소에서 환급 부재를 확인한다. 다른 계약에 일괄 무환급을 강요하지 않는다.
- M3는 대상 하나만 잃어도 전체 사업 기간제를 제거하되, 여전히 유효한 한국 소유 주의 영구 제도는 유지한다. 지역 재확보만으로 제도를 복원하지 않으며, 대기 후 이미 해금한 사업을 다시 시작할 때 의도한 II 복구를 확인한다. 원본의 단일 지역 결과를 RT56 분할주 전체에 확대하지 않는다.
- 연구 보너스는 tooltip뿐 아니라 적격 연구에서 실제 소모와 횟수·분야·배율을 확인한다. 정치력의 일일 고정 증가·소비재 계수·안정도 간접 효과는 별도 측정하고 불명확한 집계 차이를 production 수치/허용 오차 수정으로 숨기지 않는다.

## 5. 화면·언어·그림 검수

모든 신규 HOK-owned payload와 전용 마스크/오버레이를 로컬 exact-case 상대경로로 추적한다. DDS 크기·포맷·alpha·frame·hash와 source credit를 전수 검사하고 기존 60/29 이미지의 불필요한 재압축·재색칠을 막는다. 공유 vanilla `shine_overlay.dds` 등 유지하는 호스트 참조는 공급자를 기록하며 그림 체인이 전부 독립이라고 주장하지 않는다.

UI에서는 신규 중점 134개·정신 63개·주 효과 12개·18개 결정 및 해당 범주의 식별 가능한 그림을 모두 확인한다. 중점의 잠금·가용·진행·완료/광택, 정신 I→II와 기간제, 결정 최초/활성/대기/재착수를 나누어 본다. 동일 렌더링 방식의 상태 조합은 표본을 쓸 수 있지만 다른 registry·마스크·프레임 방식은 각각 검증한다. 표본 상태 검사를 모든 그림의 모든 상태 통과로 기록하지 않는다.

배치는 SHOW/HIDE, 정치 선택 전후, 공산 양 지도자·파시·입헌·전제·환제국·만주 배타 경로의 실제 조건부 이동을 관측한다. 각 가지의 명판·아이콘·연결선·배타선과 인접 가지, 지속적 중점 패널, 바로가기 착지·스크롤·클릭을 함께 검사한다. 최신 H1 오른쪽 배치도 별도 대상이다. 원본에서 이 최신 위치의 실제 화면 검수가 미완료였으므로 과거 위치의 관측을 재사용하지 않는다. 기준 해상도/GUI 배율에서 전체 검사하고 다른 지원 배율은 긴 이름·끝단 가지·패널 경계 등 위험 영역을 우선 확인한다.

현지화는 Korean/English 쌍의 UTF-8 BOM·헤더·키·서식 토큰·변수·효과 설명과 실제 C1 표시를 대조한다. English 채널에 한국어 본문을 사용하는 기존 계약을 새 영어 번역으로 표현하지 않는다. 번역층의 `replace_path`와 중복 키로 포트 문구가 사라지는지 R1/C1을 비교하고, 없어진 키를 임의로 삭제하여 로그만 줄이지 않는다.

## 6. 정상 진행·AI·DLC·저장

초기 module 검증은 대표 중점의 정상 35일 완료와 중요 차단 경로로 시작한다. 최종 이식 완료를 주장할 때는 모든 정책 모듈의 정상 UI 진입·병렬 양 순서·AND 합류·배타 선택을 실제 가능한 경로별로 확인한다. 전수 즉시 보상 검사가 정상 진행 전수 검사를 대신하지 않는다. 시험하지 못한 ID·분기는 이름을 남기고 `BLOCKED/NOT RUN`으로 구분한다.

AI는 기존 민주 역사 106개+지원 3개 계획과 RT56 전략을 보존하면서 각 신규 이념의 진입·가중치·사업 비용을 검사한다. 사람의 강제 완료와 별도로 역사/비역사 또는 명시 정치 규칙을 나눠 관찰하고, 첫 선택·주요 보상 도달일·사업 재착수·조건 상실 후 선택 중단·오류 성장량을 기록한다. PP 150 미만 같은 실제 비용 제약과 전시/평시 가중치를 확인한다. 30일 smoke로 장기 AI 일정을 검증했다고 주장하지 않는다.

실제 활성 DLC 목록과 대상 코드의 `has_dlc`/기술·교리·MIO 참조를 연결해 AAT/BBA/MTG 등 관련 보유·미보유 분기와 대체 보상을 검사한다. 설치되지 않은 DLC 분기는 미검증으로 남기고 범용 지원을 선언하지 않는다. 전체 DLC 조합의 무차별 실행 대신 실제 분기마다 최소 충족·미충족 구성을 선정한다.

저장은 새 게임에서 중점 진행 중·사업 활성 중·공통 대기 중·I/II/주 효과 제거 뒤를 포함한다. 수동 저장 파일이 실제 존재하고 정상 이름인지 확인한 뒤 프로세스를 종료·재시작하여 로드하고 다시 날짜를 진행한다. 기존 기록의 autosave rename 문제는 별도 환경/호스트 비교 대상이며 저장 성공으로 보정하지 않는다. 새 저장 round trip은 변경 전 저장 호환성이 아니다. 지도 ID 이전의 신규 게임 전용 정책을 유지하며, 기존 저장 지원을 추가하려면 대표 이전 저장으로 advance→재저장→재로드와 필요 migration의 단회·멱등성을 별도로 증명한다. 멀티플레이는 동기화·OOS 자료 없이 지원 검증 완료로 기록하지 않는다.

## 7. 완료·차단 판정과 결과 기록

문서화 완료와 코드 반영·정적 통과·실제 플레이 검증·릴리즈 준비를 서로 다른 상태로 관리한다. 후속 구현 완료 보고에는 고정 입력, 선택/제외 파일, 기존 326개 대비 변경, 보존한 포트 보정, 모든 gate 결과와 남은 제한을 적는다.

필수 gate가 실패하면 해당 단계는 완료가 아니다. 기준선 drift, 잘못된 물리 모드 로드, donor 동시 활성, 미해결 주 범위/참조/출처 충돌, 기존 KOR history 생성 불일치, 게임/UI 접근 장애는 구체적 증거와 다음 조치를 남긴다. 관계없는 조사·문서는 계속할 수 있으나 정적 실패를 PASS로 바꾸거나 실행 불가를 구현 성공과 합쳐 보고하지 않는다. 기존 history의 균형 변경은 별도 결정 없이는 이번 이식에 편입하지 않는다.

결과 기록의 최소 단위는 다음과 같다.

| 필드 | 내용 |
|---|---|
| 사례 | module/ID·긍정/차단 조건·기대 상태와 수치 |
| 소스 | 포트 변경 상태·입력 hash·RT56 manifest·엔진/DLC |
| 실행 | R0/R1/C0/C1, 물리 경로, 시작/종료 시각·게임 날짜, 진단 유무 |
| 관측 | 비용·보상 전후 값, UI 이미지, 관련 로그·저장 해시 |
| 판정 | PASS/FAIL/BLOCKED/SKIP/NOT RUN, 확인된 범위·잔여 한계 |

이 계획 작성 중 runtime·도구·자산·descriptor·launcher·원본을 수정하지 않았고 생성기·validator·게임·커밋·푸시·게시를 실행하지 않았다.
