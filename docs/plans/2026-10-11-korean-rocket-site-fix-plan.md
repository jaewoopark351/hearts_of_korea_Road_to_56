# 한반도 미사일 기지 중복 배치 수정 계획

최초 계획은 미사일 기지가 두 곳씩 잡힌다는 제보를 대상으로, 당시 호환판의 함경 `918`과 충청 `1145`에 남아 있던 `rocket_site_spawn` 위치를 HoK 기준 한 곳으로 정리하는 범위였다. 함경은 누락된 HoK 위치를 복원하고 RT56 위치 두 행을 제외하며, 충청은 이미 있는 HoK 위치를 유지하고 RT56 위치 한 행을 제외하도록 계획했다.

**현재 상태(2026-10-11 후속 구현 승인): 제한된 배치 구현과 정적 검증을 완료했으며, 수정 후 실제 UI 검증은 대기 중이다.** 최초 요청은 문서화 전용이었다. 아래 기준선, 수정 전 hash·위치 표와 최초 계획은 당시 기록으로 보존하며, 실제 변경과 검사 결과는 [후속 구현 기록](../implementation/2026-10-11-korean-rocket-site-fix.md)으로 구분한다. 위치 행 수의 정적 검증을 화면의 단일 표시·선택이나 발사 동작 검증으로 전용하지 않는다.

## 2026-10-11 후속 구현 상태

같은 날 사용자의 명시적인 후속 구현 승인으로 함경의 HoK 위치 한 행을 복원하고 RT56 위치 세 행을 제외했다. 충청의 기존 HoK 위치는 유지했다. 생성기를 통해 지도 산출물과 통합 원장을 갱신했으며, 다른 시설과 한국 밖 배치는 보존했다.

`--buildings-only`는 철도 외의 기존 입력 pin을 검증하고, 호환판 철도 SHA-256 `D424E72B580B35C836B0881D6D6C18744B5C747C1652BD25D3E555D65FFED89E`를 포함한 다른 지도 산출물 17개의 바이트 보존을 요구한다. 전체 지도·철도 생성의 기존 railway 입력 pin gate는 그대로 유지한다. 현재 RT56의 Java 철도 변경을 이번 미사일 수정에 채택하거나 최신 호스트 전체 병합 완료로 기록하지 않는다.

- 외부 회귀 검사: **34 PASS**.
- 독립적인 과거 출력 정규화 검사: 의도적인 변형 **12개 모두 거부**.
- aggregate: 작업 전 **16 PASS / 0 WARNING / 5 ERROR**, 작업 후 **17 PASS / 0 WARNING / 5 ERROR**. 두 결과의 오류는 같은 기존 5건으로, host source drift 4건과 descriptor 바이트 pin 1건이다. 전체 clean 결과를 주장하지 않는다.
- 수정 후 새 프로세스의 실제 기지 건설, HoK 위치의 단일 표시·선택, 수준·발사 동작 및 정상 진행은 **UNPROVEN / 대기**다. 상세 정적 증거와 실행 한계는 [구현 기록](../implementation/2026-10-11-korean-rocket-site-fix.md)에 분리한다.

## 범위와 우선순위

- 최초 사용자 요청일: 2026-10-11, Asia/Seoul. 당시 요청은 **문서화만** 승인했으며 구현, 검사 실행, 게임 실행, Git 변경과 게시를 포함하지 않았다. 같은 날 후속 구현 승인과 현재 상태는 위에 별도로 기록한다.
- 사용자가 정한 위치 충돌 기준: **한반도에서는 HoK를 우선하고 한반도 밖에서는 RT56을 우선한다.** 이 계획은 두 본토 주의 미사일 위치에만 적용한다.
- 실제 수정 대상으로 제안하는 주는 함경 `918`과 충청 `1145`다. 제주·쓰시마의 우선권 범위를 여기서 새로 정하지 않으며, 두 섬을 포함한 나머지 지역의 현행 배치는 보존한다.
- 기지 수준, 건설비·시간, 생산·발사 능력, 기술·DLC 조건, history, 주·프로빈스 ID와 지형은 유지한다.
- 공군기지, 항구, 보급시설, 연구시설, 요새, 공장, 연료 저장고와 원자로는 이번 대상에서 제외한다. 이전 검토에서 찾은 복수 위치만으로 이 시설들의 실제 오류를 확정하지 않는다.

이 결정은 [ADR-0004 한국 콘텐츠 우선](../decisions/0004-hok-korean-content-priority.md)의 한국 지도 보존 원칙을 두 미사일 위치에 적용한다. [10월 1일 공군기지 수정](../implementation/2026-10-01-korean-airbase-site-fix.md)은 미사일 중복을 명시적으로 제외했으며, 그때의 UI 검증을 이번 미사일 검증으로 전용하지 않는다.

| 대상 | HoK 원본 행과 출처 | 계획상 최종 행 | 현재 지형 소속 |

`CONFIRMED`: donor의 두 대상 주에는 각각 한 미사일 위치가 있다. 생성기의 기존 좌표 해석 방식으로 현재 bitmap 픽셀과 주의 프로빈스 목록을 대조했을 때 두 HoK 위치 모두 예상 주의 육지에 있다. 함경 위치는 `map/definition.csv:6923`과 `history/states/918-Hamgyong.txt:49`, 충청 위치는 `map/definition.csv:13564`와 `history/states/1145-Chungcheong.txt:5`에서 확인할 수 있다. 좌표를 육지에 대응시킨 사실은 실제 렌더링·클릭 결과의 검증을 대신하지 않는다.

함경의 HoK 행은 vanilla `map/buildings.txt:54151`과 동일하다. 기존 donor-versus-vanilla 차집합이 이 행을 제외해 구현 전 포트에는 HoK 함경 위치가 없었다. 따라서 현재 RT56 두 좌표 중 하나를 임의로 남기는 대신, 위 HoK 행을 한 번 복원해야 사용자 우선순위에 맞는다. 충청의 HoK 행은 이미 출력에 있으므로 다시 추가하지 않는다.

주 이전은 [ADR-0002](../decisions/0002-map-id-migration.md)의 `1028 → 918`, `1031 → 1145`를 그대로 사용한다. 새 ID를 만들지 않는다. donor 강원 `1029`의 별도 복수 미사일 행은 이번 두 주와 다르며 현재 포트 강원 `1144`에는 한 위치가 있으므로 함께 복원하거나 정리하지 않는다.

## 구현 시 적용할 최소 변경

[통합 원장](../audits/2026-09-06-production-file-classification.csv)의 `map/buildings.txt` 분류 `BINARY_MERGE / GENERATED`를 유지한다. 아래는 최초 문서화 당시 제안한 구현 범위다. 후속 승인으로 실제 적용한 변경과 검증 결과는 위 상태 및 별도 구현 기록에서 구분한다.

1. `tools/build_rt56_map.py`에서 정확한 RT56 원본 세 행과 HoK 기준 두 행을 대상으로 하는 제한된 선택 규칙을 추가한다. 각 source 행의 유일성, 주 이전, 현재 지형 소속이 달라지면 중단한다.
2. 함경의 RT56 원본 `527;rocket_site_spawn;4784.00;12.82;1312.00;5.72;0`과 `918;rocket_site_spawn;4827.00;9.65;1341.00;1.39;0`, 충청의 `919;rocket_site_spawn;4788.00;9.70;1254.00;2.71;0`만 재분류 결과에서 제외한다. 주 ID만으로 넓게 삭제하지 않는다.
3. vanilla와 같은 HoK 함경 행을 정확히 한 번 복원하고 기존 HoK 충청 행을 한 번 유지한다. 기존 HoK 추가 21행, 항구 복원 7행, 공군·미사일 필수 위치 복원 3행과 공군기지 선택 규칙은 보존한다.
4. 본토 8개 주 `525`, `527`, `917`, `918`, `919`, `920`, `1144`, `1145`의 `rocket_site_spawn`을 주당 정확히 한 행으로 검사한다. 0행과 2행 이상을 실패로 구분한다. 섬과 한반도 밖에는 이 새로운 중복 정리 규칙을 확장하지 않는다.
5. 생성기를 통해 `map/buildings.txt`를 재생성하고, 통합 manifest의 병합 설명과 생성 원장의 해당 출력 hash·근거를 갱신한다. 산출물이나 원장을 직접 편집하지 않는다.

계획 작성 당시 71,892행에서 RT56 세 행을 제외하고 HoK 한 행을 복원하므로 계획상 최종 행 수는 **71,890행**이었다. 이는 예정 산술 결과이며 생성·검증 결과가 아니다. 미래 출력 SHA-256을 미리 고정하거나 통과 결과로 기록하지 않는다.

## 후속 검증과 완료 조건

아래는 최초 문서화 당시 정한 후속 검증 순서다. 후속 승인 뒤 완료한 정적 검사와 대기 중인 실행 검증은 위 상태 및 별도 구현 기록에서 구분한다.

1. 대상 HOI4 build, 플레이세트, 번역 모드, DLC, donor 비활성 여부와 모든 지도 입력 pin을 다시 기록한다. 전체 지도·철도 생성은 기존 철도 source drift의 별도 merge review를 요구하며 과거 hash를 임의 갱신하지 않는다. 미사일 위치만의 생성은 위 `--buildings-only` 보존 조건을 적용한다.
2. 수정 전 새 프로세스의 `C0` 또는 `C1`에서 함경·충청의 기지 위치와 소속 주를 확인한다. 기지가 실제로 존재하는 상태에서 두 좌표의 표시·클릭 결과를 기록하고, 제보가 다른 주나 물리 모드 사본을 가리키면 먼저 대상 범위를 재평가한다.
3. 생성기의 재현 검사와 범위 검사를 수행한다. 본토 주당 미사일 위치 한 행, 대상 HoK 좌표·소속, 수정 전 대비 세 행 제외·한 행 복원, 나머지 행의 바이트·순서 보존을 확인한다. 기존 공군기지 한 곳 검사와 항구 coverage도 유지한다.
4. 다른 생성 지도 파일, 모든 한반도 밖 배치와 기존 건설 수준·능력 정의의 바이트가 유지되는지 확인한다. `tools/validate_port.py` 결과는 대상 gate와 기존 무관한 source drift 실패를 구분해 기록한다.
5. 수정 후 완전 재시작한 새 게임에서 두 주의 기지가 HoK 좌표 한 곳에서 표시·선택되고, 수준·건설·발사 동작이 기존과 같은지 확인한다. 건설 전후와 한 단계 이상을 구분하고, 관련 로그는 가능한 RT56-only control과 비교한다. 강제 효과를 사용한 진단과 정상 진행 결과를 별도로 기록한다.
6. 기존 지도 migration의 신규 게임 정책을 유지한다. 이전 세이브, 장기 진행, 다른 DLC·bookmark, multiplayer는 실제 검증 없이 지원 완료를 주장하지 않는다.

후속 검사·재현의 증거 사본은 저장소 지침에 따라 `C:/hoi/test/<task-or-run-id>/`에 보관한다. 최초 문서 작성 요청은 그 경로에 쓰기, 시험 파일 생성 또는 게임·launcher 조작을 승인하지 않았다. 후속 승인 뒤 수행한 작업은 별도 구현 기록으로 구분한다.

완료 판정에는 수정 전 증상과 두 주의 연결, HoK 위치 선택, 생성 재현, 수정 후 단일 표시·선택 및 동작 보존의 증거가 필요하다. 위치 행 수만 줄였다는 이유로 해결 완료로 바꾸지 않는다.

## 최초 문서화 결과 (후속 구현 전)

- 새 수정 계획과 문서 인덱스만 작성했다.
- 파일·해시·현재 로그와 위치 소속을 읽기 전용으로 조사했다. 생성기, validator, 테스트와 게임을 실행하지 않았다.
- 실제 구현, 지도 재생성, 통합 원장 갱신, 수정 전후 UI 재현은 대기 상태다.
- Git commit, push와 Workshop 변경은 하지 않았다.
