# 2026-11-07 한국 주 분할과 연결 콘텐츠의 RT56 이식 계획

작성 기준: 2026-11-07, Asia/Seoul. **최초 문서화 당시 — 문서화만 완료 / 호환판 구현·검증 미착수.** 최초 요청은 전체 구현 방법의 문서화였다. 아래 설계와 최초 수행 범위를 당시 기록으로 보존한다.

**후속 구현 승인:** 이후 사용자가 이 계획 전체의 구현을 명시적으로 요청했고, 실제 프로필의 설정·모드 선택·시험 등록을 백업 후 임시 전환하고 시험 뒤 복원하는 범위도 별도로 승인했다. 반영 파일과 실제 결과는 [구현·검증 기록](../implementation/2026-11-07-korean-state-split-port.md), 최종 ID·영토 정책은 [ADR-0006](../decisions/0006-korean-state-split-integration.md)을 따른다. 이 후속 승인은 커밋·푸시·패키징·업로드를 포함하지 않는다. 최초 계획의 미래형 문구를 구현 완료 증거로 사용하지 않는다.

이식 단위는 **한국 9주→15주 분할과 그 주를 소비하는 콘텐츠 전체**다. 신규 주 파일 6개만 가져오는 방식으로 구현하지 않는다. 기존 프로빈스·지형과 RT56 세계를 유지하면서 주 경계, 조건, 보상, 영토 이전, AI, 배치와 현지화를 함께 이전한다. 기존 저장은 지원 대상으로 삼지 않는다.

### 2.1. 기존 검증 부채와 이번 증거를 구별

최근 [호환판 이식 기록](../implementation/2026-11-07-hok-resource-prospecting-port.md)의 전체 검사는 **17 PASS / 0 WARNING / 11 ERROR**다. 같은 11개 오류가 당시 변경 전에도 있었고, 역사적 vanilla·RT56 입력 지문과 descriptor 검사 문제가 포함된다. 이는 이번에 다시 실행한 결과도, 새 분할로 생긴 결함도 아니다.

후속 구현은 변경에 관계된 현 RT56·vanilla 입력을 새 기준선으로 검토하고, 과거 계층의 잠금은 보존해야 한다. 단순히 과거 해시를 새 해시로 바꾸거나 실패 검사를 생략해서 통과시키지 않는다. 과거 입력 재현과 현재 호스트 통합 검증을 별도 계층으로 두고, 각 기존 오류의 처리·잔여 영향을 기록한다. 지도·공유 파일을 안전하게 재생성할 수 없는 상태에서는 해당 구현 단계를 진행하지 않는다.

### 2.2. 원본에서 확인한 것과 남은 검증

원본 구현 기록은 핵심 1936·두 게임 옵션·강제 중점 보상·부분 영토 상실 취소·반복 사업·슬롯 검증을 보고한다. 실제 1939 시작, 지도/중점/디시전 화면, 정상 선행·연구를 거친 진행, 고유한 새 저장의 완전 종료·재로드는 원본에서도 미검증이다. 장기 AI 경고 3건의 원인·분할 귀속도 미확정이다. 이번에는 해당 기록을 읽었으며 원본 시험을 재실행하거나 그 결과를 RT56 실행 증거로 전환하지 않았다.

## 3. 주·프로빈스·이름 키의 대응 설계

### 3.1. 기존 ID 유지와 신규 ID 배정

| 기존 donor → 현재 호환판 | 유지할 호환 ID와 후속 지역 | 신규 donor 주 → 호환판 기호 |
|---|---|---|
| `1030 → 920` | `920` 경상북도 | `1086 → NEW_KOR_GYEONGSANGNAM` 경상남도 |

기호는 설계 표기이며 실제 ID·파일명·예약이 아니다. donor 신규 ID `1086–1091`은 설치 RT56의 Burgenland·Chatham Island·American Samoa·Niue·Uttarakhand·Gandaki와 전부 충돌한다. 구현 직전 유효 state 선언과 실제 대상 모드 전체를 읽어 새 번호를 확정한다. 비어 보이는 최대값 다음 번호를 미래에도 안전하다고 가정하지 않으며 RT56 ID를 재번호하지 않는다.

경기 `525`, 강원 `1144`, 제주 `1146`, 쓰시마 `1147`, 나가사키 `528`과 기존 비분할 경계는 보존한다. 한국 9→15주 집계는 쓰시마·나가사키를 포함하지 않는다. 기존 호환 파일명도 필요 없이 바꾸지 않는다. 부분 적용 단계에는 실제로 생성한 신규 주만 집합에 포함하고, ID 공백을 채우기 위한 빈 주를 만들지 않는다.

프로빈스는 기존 `13414–13447 → 13535–13568` 대응을 유지한다. 새 프로빈스·RGB·비트맵·해안선은 만들지 않는다. 각 부모의 프로빈스 합집합을 두 자식에 정확히 한 번 배정하고, 분할 외 주의 소속은 바꾸지 않는다. 철도·보급·전략지역·unitstack은 현 호환판 바이트 보존을 기본으로 하되, 주 변경으로 영향받는 실제 참조를 별도로 확인한다.

### 3.2. 이름 키를 숫자 scope와 분리

신규 12개 표시 키 `HOK_KOR_STATE_<donor ID>`는 숫자 scope와 독립된 HOK 논리 키로 보존하는 안을 채택한다. 예를 들어 호환판 경북 `920`의 `name`은 `HOK_KOR_STATE_1030`을 사용할 수 있다. 숫자 접미사가 런타임 state ID와 같아야 하는 것은 아니다. 이름 키와 숫자 scope는 별도 대응표에 기록하고 정확한 허용 키에만 변환을 적용한다.

- donor의 전역 `STATE_1086–1091` 별칭을 수입하여 RT56 외국 주 이름을 가리지 않는다.
- 기존 호환 `STATE_527/917/918/919/920/1145` 등 키와 기존 소비자를 보존한다. 각 툴팁이 옛 도 전체를 뜻하는지 한 후속 주를 뜻하는지 검토해 문구를 결정한다.
- 쓰시마 donor `1085`가 과거 `STATE_1088`을 쓰는 예외를 전남 donor `1088`과 혼동하지 않는다. **현재 호환판 `1147-Tsushima.txt`의 `name="STATE_1088"`과 한영 이름 파일의 `STATE_1147` 정의가 불일치한다.** 이는 이번 읽기에서 확인한 기존 소스 불일치이며, 실제 화면 결과는 미확인이다. 새 전남 변환이 이 이름을 바꾸지 않도록 명시적으로 보호한다. `name="STATE_1147"`로 맞추는 좁은 수선 후보는 분할 원본 변경과 구별하여 출처·소비자·표시 검토 후 결정한다. 이 문서화로 수선하지 않는다.
- donor의 영문 헤더에도 한국어가 들어 있으므로, 호환판 영어 파일은 실제 영어로 번역한다. 기존 산업 투자 3개 설명은 전체 파일을 교체하지 않고 지급 주와 양쪽 영토 상실 규칙만 갱신한다. BOM·헤더·키·기여 주석을 보존한다.

### 7.2. 지도와 건물의 필수 보존 조건

원본 기록의 건물 변경은 기존 209행 재부모화와 표시 앵커 172행 추가다. 이 수를 호환판에 복사할 행 수로 고정하지 않는다. RT56 기반 실제 행 집합과 합성 지도에서 좌표·프로빈스·건물 종류·부모 주를 대조하여 필요한 행만 선택한다. 표시 앵커는 건물 수 지급이 아니다.

- 각 후속 주의 `state_victory_points` 배열은 **그 자식의 실제 VP 프로빈스 집합**으로 재생성한다. 옛 부모 배열 전체를 양쪽에 넣지 않는다.
- 기존 항구 spawn 7행 복원, 공군기지 선택, 함경·충청 미사일 위치와 buildings-only 철도 보존 규칙을 새 소속에 맞게 재검토한다. 복원 행의 부모 ID를 옛 주로 고정하지 않는다.
- `KOREAN_MAINLAND_STATES` 같은 옛 8개 본토 집합과 주별 기지 유일성·필수 종류 기대값을 새 14개 본토에 맞게 검토한다. 빈 자식에도 기존 건물 예산이나 로켓 보너스를 자동 부여하지 않는다. 필요한 표시 위치와 실물 건물 수를 구별한다.
- 추가 해안 누락 spawn 0, 정확한 부모 소속·해안 판정·sea link·좌표 투영, 공군/로켓/항구·승점 위치를 확인한다. 기존 비해안 앵커 문제는 아래 별도 항목으로 남긴다.
- 전체 지도 재생성은 현재 RT56 입력 재검토가 선행돼야 한다. 분할로 바뀌지 않는 지도 출력은 분할 직전 허용 바이트 보존을 확인하고, 필요한 현재 host 리베이스는 별도 diff·근거로 구별한다. 범위 한정 생성/검사는 과거 지문 실패를 숨기는 우회로 사용하지 않는다.

## 10. 보관·복구·중단 기준

후속 구현·시험의 helper, 백업, 로그 사본, 보고서, 스크린샷, 시험 저장 사본은 시작 전에 선정할 `C:\hoi\test\hok-rt56-state-split-<run-id>\` 아래에 둔다. 이는 제안 경로 형식이며 이번에는 디렉터리를 만들지 않았다. 실제 도구의 출력·임시·백업 목적지를 실행 전에 확인하고 저장소나 업로드 경로로 향하면 외부로 설정한다. 게임 생성 로그·저장 원본은 실제 user-data에 남기고 증거 사본과 구별한다. 유지 관리용 source snapshot·대응표와 시험 산출물도 구별한다.

설정·모드 선택 변경은 문서화 범위 밖이다. 후속 시험이 승인되면 원래 설정과 모드 선택을 외부에 정확히 백업하고 donor 비활성·실제 로드 경로를 확인한 뒤 임시 전환한다. 고유 시험 저장을 사용하며 끝난 뒤 시험 소유 프로세스 종료·Steam 실행 상태·원래 설정/선택 복구를 확인한다. 기존 저장이나 무관한 앱·자료는 건드리지 않는다.

현재 저장소 `tools/__pycache__/`에는 기존 캐시 **21개·1,088,888바이트(약 1.04 MiB)**가 남아 있다. 정리 대기 항목으로 기록하며 이번 문서화에서는 이동·삭제하지 않는다. 외부 활성 source cache는 정리 대상 테스트 출력이 아니다.

| 상황 | 처리 |
|---|---|
| 입력·host 지문 또는 사용자 작업 트리가 작업 도중 바뀜 | 새 기준선과 diff를 보존하고 해당 단계 중단. 잠금을 느슨하게 하지 않음 |

| 비한국 RT56 파일·세계 ID·기하가 의도 없이 변경됨 | 범위 위반으로 판정. 생성 출력을 원본 위에 수작업으로 덮어 숨기지 않음 |
| 실행 실패·원인 미확정 신규 오류 | 대조 로그·단계별 소스 지문으로 최초 실패를 식별. 분할 수를 줄여 격리하되 이를 최종 콘텐츠 삭제로 확정하지 않음 |
| 되돌려야 함 | 외부의 검증된 분할 전 사본·해시와 명시적 출력 목록으로 이번 변경만 복구. 새로 만든 허용 파일만 대상으로 하고 기존 사용자 변경은 보존. Git reset/clean·기존 저장 덮어쓰기 사용 금지 |

원본의 기존 새만금 충청 보상 지정, 비해안 `13419` 항구 요새, 일본 요새 `1003`의 범위, 비해안 `10065` floating-harbor 앵커는 별개 문제다. 부모 정렬과 원래 지리 결함 수선을 혼동하지 않고 독립 항목으로 남긴다. 자동 수정하거나 이번 분할로 해결됐다고 기록하지 않는다.

## 11. 후속 산출물과 완료 판단

후속 구현 기록에는 최종 state/province/name-key 대응표·새 ID 배정 근거, 선택 입력 manifest/lock·원본 및 host 해시, 파일별 통합 분류, 생성 소유자·정확한 변경 범위, 고정 총량과 의도된 슬롯/기반시설 변화, 외부 증거 경로와 시험 구성·결과·잔여 오류를 남긴다. ADR-0002의 후속 분할 결정과 새로운 지역 대응 기록, 문서 인덱스도 구현 상태에 맞춰 갱신한다. 현재 계획의 미실행 문구를 과거 완료 사실로 덮어쓰지 않는다.

완료는 주 15개 존재만으로 판정하지 않는다. 전체 참조 폐쇄, RT56 보존, 재현 가능한 생성, 필수 실행·UI·새 저장 검증과 기존 오류의 영향 판정이 필요하다. 실제 blocker로 확인하지 못한 항목은 blocker·미검증으로 명시하고 전체 완료를 주장하지 않는다. 기존 저장 마이그레이션, 커밋·푸시·태그·패키징·업로드는 별도 범위다.

**최초 문서화에서 실제 수행한 것:** Git 상태·소스·생성기·기록의 읽기 조사, 선택 파일 지문 조회, 이 계획과 문서 인덱스 편집. **최초 문서화에서 수행하지 않은 것:** 런타임/도구/잠금 파일 편집, 입력 스냅샷 복사, 테스트·validator·게임 실행, 설정 변경, 산출물 이동·삭제, Git 상태 변경 명령과 외부 게시. 이후 별도 승인된 구현·검증은 위 후속 기록에서 구분한다.
