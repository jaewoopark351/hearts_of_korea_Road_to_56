# HOK×RT56 현지화 검토

키의 존재, 플레이어에게 전달되는 의미, 실제 활성 파일을 함께 확인한다. AGENTS의 조건부 필수 읽기로 적용하며, 원본 HOK의 절차를 호환판 자체의 영어·한국어 정책과 RT56 표시 소유권에 맞춘다.

## 범위와 필요한 자료

- 먼저 [AGENTS.md](../../../AGENTS.md)의 요청 모드와 8절을 읽고 [공통 검토 절차](../../../docs/HOK_CHANGE_COVERAGE_REVIEW.md)를 적용한다. 검토·문서 전용 요청은 코드·현지화 값 수정, 테스트·진단·게임 실행이나 설정 변경을 허용하지 않는다.
- 언어 채널이나 번역 출처를 판단하기 전에 [ADR-0003](../../../docs/decisions/0003-localisation-contract.md)과 [영어 이식·주석 번역 기록](../../../docs/implementation/2026-10-20-english-localisation-import.md)을 읽는다. 날짜별 결과와 미결정 배포 의존성을 구분한다.
- HOK와 RT56가 함께 정의하는 표시를 다루면 [한국 콘텐츠 소유권 ADR-0004](../../../docs/decisions/0004-hok-korean-content-priority.md)를 읽고 한국 노선과 공용/비한국 표시의 소유권을 구분한다.
- 11월 국토개발·시민사회 표시나 연결 참조를 다루면 [ADR-0007](../../../docs/decisions/0007-november-content-integration.md)과 [후속 구현·검증 기록](../../../docs/implementation/2026-11-08-hok-upstream-content-port.md)을 읽는다. 과거 donor 화면과 후보 목록을 현재 포트 결과로 사용하지 않는다.
- 지역명·대상 코드도 바뀌면 [주 참조 스킬](../hok-rt56-state-reference-review/SKILL.md)을 함께 읽는다. 번역 저장소 편집은 별도 허용 범위와 그 저장소 지침을 확인한다.

## 표시 영향 추적

변경 키·ID에서 직접 호출부, 공용 helper, 역호출자와 대체 분기를 필요한 만큼 추적한다. 접두어 검색이나 두 채널 키 집합의 일치만으로 조사를 끝내지 않는다.

| 확인할 면 | 실제 소비 문맥 |
|---|---|
| 이름·설명 | 중점·국민정신·결정·범주·사건·선택지의 명시 키와 필요한 암시 키 |
| 조건·취소 | 가용·차단·유지·취소·제거, 공유 트리거, AND/OR/NOT와 긍정·부정 |
| 효과·선택지 | 변수 증감·현재 값·대상·공용 효과, immediate와 선택지에서의 실제 표시 |
| 해금 | 실제 여는 결정/범주의 이름과 해금 안내, 남아 있는 별도 사용 조건 |
| 동적·공유 참조 | scripted localisation, 파생 키·매개변수·scope, 같은 안내를 쓰는 다른 GUI·사건·중점 |

- 후보별 키·ID, 파일·행, 호출 경로, 영향 화면과 정의의 물리 파일을 기록한다. 고유 키 수와 사용처 수는 구분한다.
- 필요한 키는 소비자에서 도출한다. 양 채널에서 동시에 누락될 수 있으며 모든 ID에 선택적 `_desc`가 필수인 것은 아니다.
- 정규식·키 집합 비교는 후보 수집이다. 동적 키는 실제 인수와 치환 문맥을 확인하고 해석하지 못한 항목은 미확인으로 남긴다.

## 내부 표식·변수

| 경우 | 처리 방향 |
|---|---|
| 플레이어 판단에 필요한 상태·수치 | 의미 있는 이름이나 정확한 조건·효과 안내를 제공하고 저장 ID를 유지한다. |
| 사용자 지정 안내로 이미 설명된 내부 조건 | 실제 감싼 내용과 화면을 확인하며 중복 번역을 만들지 않는다. |
| 엔진이 표시하지 않는 초기화·집계·단순 설정 | 내부 용도와 비표시 근거를 기록하고 불필요한 번역·wrapper를 넣지 않는다. |

- 원시 ID 노출과 조건·효과 항목 전체의 부재는 따로 판단한다. 변수 이름 번역만으로 자동 항목도 나타난다고 가정하지 않는다.
- AI·사건 자격·대상 필터의 사용만으로 UI 결함을 확정하지 않는다. 실제 소비 화면을 찾는다.
- 표시 수리로 변수 값·범위·초기화, flag 위치·수명, 비용·보상·AI·효과 순서·완료 이력을 바꾸거나 필요한 공개 조건·수치를 숨기지 않는다.

## 호환판 언어·로드 계약

- 본체 `localisation/korean`은 한국어, `localisation/english`의 사람이 읽는 값·비활성 문구·기여 주석은 영어로 유지한다. 영어 이식에서 채택한 영국 영어와 해당 기능의 기존 용어를 따른다. 원본의 양 채널 한국어 본문 계약을 가져오지 않는다.
- 양 채널의 키·조건 의미·수치·대상·치환 토큰 대응을 확인한다. 번역 본문의 바이트 일치를 요구하거나 일반판 전용 키·옛 지명 번호를 그대로 추가하지 않는다.
- 게임 언어·물리 모드 경로·기록된 배열과 실제 유효 우선순위를 구분한다. 같은 파일명, 중복 키, `replace/`, locale header와 번역 모드의 `replace_path="localisation"`을 확인한다.
- 일반판 영어 서브모드는 호환판 영어 검증 구성에서 제외하는 기존 계약을 따른다. 설정 변경은 승인된 경우에만 수행하며 실제 활성 번역이 본체의 새 문구를 가리는지 확인한다.
- `Korean Language`와 RT56 한국어 번역의 최종 지원 조합은 최신 기록으로 확인한다. 특정 한영 화면 관측을 모든 언어 모드 조합의 지원 확정으로 확대하지 않는다.

## 승인된 구현의 편집 기준

- 생성 출력이면 먼저 관련 구현 기록에서 소유 source/lock·생성기를 찾는다. 영어 기본 계층·주석 계층과 후속 콘텐츠 계층의 순서를 보존한다. 문서 링크는 생성기 실행이나 잠금 변경의 승인이 아니다.
- 기존 원본 사본·과거 해시를 덮어쓰거나 mismatch를 면제하지 않는다. 출력만 수동 수정해서 재생성 시 사라지는 수리를 만들지 않는다.
- UTF-8 BOM, 헤더·경로·기존 줄 끝·키와 `$KEY$`, 치환·색상·아이콘 토큰, `\n`, 따옴표 escape를 보존한다. 일반 YAML formatter를 사용하지 않는다.
- 기여 주석은 AGENTS의 형식과 paired 파일의 동일 메모 규칙을 따르고 영어 채널의 주석은 영어로 유지한다. 승인된 키·값만 좁게 수정하고, 쓴 뒤 명시적 UTF-8로 다시 읽어 콘솔 디코딩 문제와 실제 파일 손상을 구분한다.
- NOT에 의한 이중 부정, 엄격 비교와 이상/이하, 증감 부호·수량·색상을 대조한다. 새 metadata/wrapper는 현행 바닐라의 같은 명령·문맥·scope를 근거로 삼는다.
- 설명은 배경·목적을 전달하고 자동 UI의 숫자 목록을 불필요하게 반복하지 않는다. 자동 UI가 설명하지 않는 환불·취소·재사용 제한은 남긴다. 긴 효과 목록이 사건 선택지를 밀어내는지도 구분해 검토한다.

## 확인과 보고

- 문구만 바꾸면 관련 키·참조·토큰·인코딩·언어 의미부터 확인한다. 신규 표시 경로나 조건/효과 metadata 변경은 해당 화면·상태의 확인 필요성을 정하고 요청 범위 안에서 수행한다.
- 실행이 허용되면 전체 프로세스 재시작과 실제 언어/로드 구성에서 가용·차단·취소·완료·숫자 경계 및 관련 선택지를 확인한다. 수정 전 시작한 프로세스와 핫 리로드를 최종 증거로 쓰지 않는다.
- 소스·실제 UI·실제 효과·저장 결과를 따로 기록한다. 강제 seed/효과, 정상 진행, 새 저장 재로드와 과거 저장 호환은 구분한다. 조용한 로그나 올바른 이름만으로 다른 층을 통과 처리하지 않는다.
- 공통 대장에 수정(제안/적용)·의도적 유지·제외·미확인과 확인·실패·미검증을 별도로 남긴다. 완료 보고는 변경 키·영향 화면·활성 파일·실제 수행한 확인·남은 필수 항목에 한정한다.
- 실제 시험·진단의 파일과 증거 사본은 먼저 정한 `C:/hoi/test/<task-or-run-id>/`에 둔다. 검토·문서 전용 작업에서 임시 helper·검사 출력 파일을 새로 만들지 않는다.
