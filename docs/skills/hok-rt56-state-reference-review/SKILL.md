# HOK×RT56 주·프로빈스 참조 검토

AGENTS의 조건부 필수 읽기로 적용하는 프로젝트 검토 스킬이다.

## 운영 모드와 필요한 자료

- 먼저 최신 요청의 운영 모드를 정하고 [프로젝트 규칙](../../../AGENTS.md)을 적용한다. 검토는 읽고 보고하며 문서 작업은 승인된 문서만 편집한다. 이 스킬은 구현·시험·게임 실행·정리 승인이 아니다.
- 조사 범위와 후보 처리 내역을 정할 때 [변경 영향 범위·누락 방지 절차](../../../docs/HOK_CHANGE_COVERAGE_REVIEW.md)를 읽고 공용 대장을 사용한다. 작은 변경에 전체 모드 감사를 자동 요구하지 않는다.
- HOK 지도 ID 또는 과거 donor 참조를 판단할 때 [ADR-0002](../../../docs/decisions/0002-map-id-migration.md)를 읽는다. donor ID와 포트 ID의 충돌 회피·이전 계약을 따른다.
- 한국 분할·영토 집합·단일 보상 위치·표시 키를 판단할 때 [ADR-0006](../../../docs/decisions/0006-korean-state-split-integration.md)과 [포트 대응표](../../../docs/data/HOK_KOREAN_STATE_SPLIT_PORT_MAPPING.json)를 읽는다. 문서가 지정한 잠금·구현 기록도 해당 입력·생성기·검증을 다룰 때 확인한다.
- 분할의 이전 적용 결과나 생성 계층을 판단할 때 [포트 구현 기록](../../../docs/implementation/2026-11-07-korean-state-split-port.md)을 읽는다. 과거 소스·실행 범위를 새 작업의 검증으로 대신하지 않는다.

## 현행 지도와 기준 소스 확인

1. 우리가 주·프로빈스를 변경했거나 RT56가 변경한 경우 모두 영향 조사를 시작한다. 지도 파일이 그대로여도 참조 코드의 지리적 불일치를 검토할 때 적용한다.
2. 기준은 **지문을 고정한 RT56 세계 지도 + 승인된 HOK 변경**으로 구성된 실제 포트 지도다. donor 지도나 바닐라 번호표를 현행 포트 지도라고 간주하지 않는다.
3. 작업 소스·브랜치/HEAD·기존 변경, 정확한 HOI4 버전, RT56 manifest·관련 해시와 donor 입력을 구분한다. 런타임 판단에는 물리 모드 경로·DLC·로드 구성·언어를 확인한다.
4. 의도된 대상 정의마다 포트 출력·HOK 의도/입력·정확한 RT56 호스트·대상 버전 바닐라 문법을 비교한다. RT56 세계·공유 시스템을 보존하고 한국 연결만 필요한 만큼 병합한다.
5. RT56 지문이 달라졌으면 변경을 확인하고 새 기준·통합 결정을 기록한다. 이전 핀을 조용히 덮거나 검사를 약화하지 않는다. 불명확한 소스에 의존하는 수정은 진행하지 않는다.
6. 참조 정렬 승인만으로 지도 정의를 바꾸지 않는다. 추가 ID 재배정·경계 변경·기존 저장 변환이 필요하면 별도 설계와 해당 범위의 승인이 필요하다.

## ID 종류와 지리 확인

- 각 숫자가 state, province, strategic region, 표시명 키 중 무엇인지 명령 문맥으로 판별한다. 존재하는 ID라는 사실만으로 지역이 올바르다고 판단하지 않는다.
- 현행 province의 부모 state, 필요한 육지·해안 속성, 전략 지역과 보급·철도 연결을 확인한다. 건물·승점·수도 명령이 기대하는 입력 종류도 구분한다.
- donor `13414–13447 → 13535–13568` 이전과 기존 state 이전은 ADR-0002, 한국 후속 주 `1148–1153`의 의미는 ADR-0006과 포트 대응표로 확인한다. 이 수치를 최신 RT56의 빈 ID라고 재해석하지 않는다.
- `HOK_KOR_STATE_<donor ID>`는 안정적인 표시 논리 키다. 숫자 접미사를 포트 state scope로 취급하거나 `STATE_<같은 숫자>`로 일괄 바꾸지 않는다. RT56 외국 주 이름을 덮지 않는다.
- 파일명·주석·번역 표시명과 실제 지리를 구분한다. state·province·현지화 키의 숫자를 서로 같게 만드는 것은 목표가 아니다.

## 사용처와 호출 경로 추적

- 변경 ID와 이전 ID, 분할 후속 ID, 지역명·목록·별칭을 함께 검색한다. 숫자 일치 후보마다 주변 명령을 읽어 관련성을 판단한다.
- 중점·결정·사건·국가/주/OOB 이력·수도·AI·on_action·scripted trigger/effect·상수·지도 배치·관련 표시 문구의 사용처와 호출자를 추적한다.
- 포트에서 재정의하지 않은 RT56·바닐라·DLC·관련 의존 모드의 상속 코드도 포함한다. 실제 파일 선택·동일 ID 등록·replace_path·대체 경로를 확인한다.
- 동적 scope, scripted parameter, 변수·event target·iterator는 고정 ID 검색으로 끝내지 않는다. 호출 인수와 ROOT/THIS/PREV/FROM을 필요한 단계까지 추적한다.
- 같은 helper라도 호출 국가·인수·scope·정치 분기·DLC 경로가 다르면 따로 판단한다. 동적 참조 자체를 오류로 세지 말고 불분명한 대상은 미확인으로 남긴다.
- 모든 옛 참조를 없애지 않는다. 단일 도시 보상, 기존 저장 분기, 다른 종류의 같은 숫자는 각각 유지 근거를 확인한다.

## 기능별 대상과 보존 계약

공용 대장에서 각 기능의 의도 지역과 현재 코드 대상을 다음 단계별로 연결한다.

| 단계 | 확인할 연결 |
|---|---|
| 진입·유지 | visible/available, 착수·유지·취소·제거 조건, bypass와 소유·통제 범위 |
| 표시·조회 | highlight, 지역 이름·설명, 건물 수준·빈 슬롯·해안·기지 수용량 |
| 지급·변경 | 보상 위치·총량·횟수·순서, 영토 이전·controller·core·claim·수도 |
| 후속·대안 | 수락/거절, 국가 존재/부재, 종속국·내전 분배, 무작위 선택·대체 건설·DLC fallback |

- 같은 지역을 뜻하는 조건·우회·강조·효과 목록의 차이를 설명한다. 옛 도 전체 조건과 단일 수혜 주 조건은 구별하고 연결자·scope를 보존한다.
- 한국 분할의 전체 소유·통제 AND, 후보 membership 확장, 부분 상실 취소 OR는 ADR-0006의 해당 기능 계약에 따라 적용한다. 모든 목록을 한국 전체로 넓히지 않는다.
- 영토 이전·통제·코어·클레임은 각각 판단한다. 현재 소유나 코어, 지역 이름 하나만으로 원래 범위를 무제한 확대하지 않는다.
- 고정 보상 총량·지급 횟수·비용·기간·AI·효과 순서·기존 ID를 보존한다. 주가 나뉘었다고 보상을 각 후속 주에 복제하지 않는다.
- fallback의 실제 대상·슬롯·수용량도 확인한다. 부모 scope만 바꾸거나 조건만 넓히고 지급 경로를 남기지 않는다. 숫자 전체 치환이나 임의 대상 교체로 통과시키지 않는다.
- 지도와 직접 보상 총량을 보존해도 영토 범위 변경은 착수 난도·인력·산업·저항에 영향을 줄 수 있다. 동작·밸런스가 완전히 같다고 단정하지 않는다.

## 구현 소유권과 후보 처리

- 구현이 승인되면 생성 파일은 문서화된 생성기·입력 대응표를 통해 변경하고 재생성한다. `tools/build_rt56_map.py`, `tools/migrate_hok_ids.py`, `tools/korean_state_split.py` 등의 실제 담당 범위는 해당 ADR·구현 기록과 현재 소스로 확인한다. 출력만 손으로 고치지 않는다.
- 문서화 요청이나 스킬 열람은 생성기 실행·입력 갱신·지도 수정 승인이 아니다. donor·설치 원본·Workshop 파일은 읽기 전용 비교 자료로 유지한다.
- 발견 후보마다 기능·위치·분기·기대 대상·현재 근거를 기록하고 다음 중 하나로 처리한다. 반복 위치 수와 고유 기능 수를 구분한다.
  - **수정**: 입증된 불일치와 필요한 수리. 제안과 실제 적용을 구분한다.
  - **의도적 유지**: 단일 수혜 주·원래 지역·저장 분기 등 유지 근거.
  - **제외**: 다른 ID 종류·무관한 기능·현재 범위 밖이라는 이유.
  - **미확인**: 부족한 의도·동적 대상·엔진 처리와 이를 구분할 관측.

## 검증과 보고

- 필요한 검증은 요청 범위·위험에 맞춰 정한다. 검토·문서 작업은 소스를 읽고 보고하며 시험·진단 스크립트나 게임을 실행하지 않는다.
- 소스에서는 ID 종류·부모 주·조건/표시/효과·분기·상속 참조와 보존 계약을 대조한다. 유효 ID·조용한 로그·파서 통과를 실제 효과의 증거로 쓰지 않는다.
- 실행이 승인되면 같은 소스·플레이셋의 RT56 대조와 포트 결과를 구분하고 전체 재시작을 사용한다. 정상 경로와 중요한 차단 경로, 부분 상실·외국 점령·내전·fallback 중 관련 사례를 선택한다.
- **소스**, **로드·UI**, **실제 효과와 정상 진행**, **저장** 증거를 분리한다. 대상·총량·순서와 필요한 지역 표시를 관측하고, 강제 효과와 정상 진행도 구분한다.
- 새 저장 왕복을 기존 저장 호환으로 확대하지 않는다. 한국 분할의 기존 정책은 새 게임 기준이며, 이전 9주 저장 변환은 별도 입증 전까지 지원을 주장하지 않는다.
- 대표 사례로 묶으면 동등성 근거와 미실행 범위를 적는다. 과거 donor·RT56 단독·이전 포트 실행은 그 소스와 조건에 한정한다.
- 승인된 시험의 새 산출물은 `C:\hoi\test\<task-or-run-id>\`에 둔다. 기존 저장소 시험 자료는 미결 정리로 보고하고 승인 없이 이동·삭제하지 않는다. 고정 source cache는 시험 폐기물과 구분한다.
- 중요한 사용처·판단·필수 검증이 남으면 미확인·미실행과 이유를 명시하고 완료 주장을 제한한다. 검색 행 수나 성공한 한 경로로 전체 지도·모든 저장·DLC·멀티플레이 호환을 선언하지 않는다.
