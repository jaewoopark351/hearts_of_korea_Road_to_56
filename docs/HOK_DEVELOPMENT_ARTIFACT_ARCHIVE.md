# HOK × RT56 개발 자료 보관·이미지 원본 탐색 안내

기록일: 2026-11-06. 별도 승인 이동·검증 기록 갱신일: 2026-11-06(KST). 이 문서는 호환판의 외부 개발 자료와 활성 소스 캐시 위치, 옛 경로의 대응 관계, 후속 이미지 작업의 자료 확인 절차를 관리한다. 이미지 제작·수정, 과거 입력·레시피 재사용, `.local-artifacts` 경로 해석 또는 기록된 자료 위치를 변경하기 전에 읽는다. 작업 권한과 공통 보존 규칙은 [AGENTS.md](../AGENTS.md)를 따른다.

사후 저장소 보존 대조에서는 이번에 유지·갱신한 문서 3개를 제외한 나머지 2,010개 파일의 목록·크기·SHA-256과 디렉터리 구조가 작업 전과 일치했고 불일치는 0건이었다. 저장소 `.local-artifacts`가 없음을 확인했으며, `git diff --check`도 통과했다. 그 이동 작업 직후의 작업 트리 변경은 기존 문서화 변경을 포함한 `AGENTS.md`, 이 안내, `docs/audits/2026-11-05-local-artifact-archive.md` 세 문서였다. 당시 이 PC의 저장소에 남은 `.local-artifacts` 자료는 없었다. 이후 두 PC 간 줄바꿈·문서 범위·원장 해시 보정은 1.3절의 별도 작업으로 구분한다.

생성기 경로는 이미 외부 `SOURCE_CACHE_ROOT`를 참조하므로 코드 변경은 필요하지 않았다. donor·게임·Workshop·사용자 데이터, 소스 lock·핀 값과 runtime 콘텐츠는 변경 대상이 아니다. 게임플레이 validator·생성기 실행·HOI4 실행·커밋·푸시·업로드는 수행하지 않는다. 파일 보관의 무결성 대조를 게임 동작이나 기존 소스 핀 전체의 검증으로 주장하지 않는다.

Git 커밋이나 다른 PC에서의 checkout은 `C:\hoi\test\` 아래 외부 자료를 복사하지 않는다. 이 안내와 원장 해시를 공유해도 다른 PC의 캐시·보관소가 자동으로 준비되거나 검증되지는 않는다. 다른 PC에서 생성·검증 작업을 이어갈 때는 해당 PC의 실제 저장 위치, `SOURCE_CACHE_ROOT`가 가리키는 세 입력의 존재와 pinned 내용부터 확인한다. 이 안내를 읽었다는 이유만으로 다른 PC의 원본을 제거하거나 경로를 바꾸지 않는다.

원장의 `AGENTS.md` 해시는 파일 내용 바이트의 SHA-256이며, PC 식별자나 캐시 경로 설정이 아니다. 해시를 갱신해도 파일을 이동하거나 `SOURCE_CACHE_ROOT`를 변경하지 않는다. [.gitattributes](../.gitattributes)의 `AGENTS.md text eol=crlf`로 checkout 줄바꿈을 고정하고 기존 CRLF 바이트를 유지한다. 원장 CSV는 기존 `text eol=lf` 규칙을 유지한다. 전역 Git 설정은 변경하지 않으며, 두 PC에서 동일한 문서·속성·원장을 함께 받아 사용해야 한다. 다른 PC의 기존 작업본이 LF로 남아 있으면 기존 변경을 보존하면서 해당 파일의 실제 줄바꿈을 확인한다.

2026-11-06 후속 보정의 범위는 이 PC 기준임을 명시하는 문서, 위 줄바꿈 규칙, 소유 생성기를 통해 재생성한 `AGENTS.md` 원장 해시다. 별도 작업 기록·검사 출력·변경 전 사본은 `C:\hoi\test\hok-rt56-cross-pc-doc-hash-20261106-01\`에 둔다. 이전 이동의 `repository-preservation.json`은 1.2절 당시 결과로 유지하며, 이 후속 변경을 포함한 새 보존 결과인 것처럼 덮어쓰지 않는다. 다른 PC에 접속하거나 외부 보관 자료·소스 캐시·게임 콘텐츠를 변경하는 작업은 포함하지 않는다.

소유 생성기 [build_integration_manifest.py](../tools/build_integration_manifest.py)에 명시적인 `--documentation-only` 모드를 두었다. `--check --documentation-only`는 현재 CSV의 바이트 형식과 유일한 `AGENTS.md` 행의 분류·상태·경로 계약을 확인하고 그 행의 `output_sha256`만 재현한다. 나머지 행은 검증하지 않는다고 출력하며, 인자를 생략한 기존 전체 검사와 `validate_port.py`의 호출은 유지한다. 이번 갱신은 소유 함수의 결과를 외부 후보 CSV에 생성하고 전체 행·필드를 비교한 뒤 최종 원장에 반영했다. 저장소에 생성기 임시 파일이나 테스트 파일을 만들지 않았다.

이번 후속 보정에서 확인한 결과는 다음과 같다.

- `AGENTS.md`는 CRLF이며 원장의 해당 해시와 일치한다. 원장 1,505행 중 변경한 값은 이 행의 `output_sha256` 한 칸뿐이다.

- `source_snapshot.py --check`와 문서 전용 원장 검사는 통과했다. 검사 전후 RT56 manifest `7553774178744855191`, 관련 RT56 파일 82개의 지문, 소스 lock과 donor 식별 정보는 유지됐다.
- 기존 전체 정적 검사 결과는 **19 PASS / 0 WARNING / 8 ERROR**다. map·건물·공유 override·동아시아·교리의 소스 지문 차이, 영어 현지화 소스 계약, second-wave descriptor 계약, 전체 원장 불일치가 남아 있다. 전체 통과나 게임 동작 검증을 주장하지 않는다.
- 전체 원장 사전 재생성에는 이번 대상 해시 외에도 기존 35개 `output_sha256` 차이가 있었다. 해당 파일을 CRLF로 해석하면 기존 원장 값과 일치함을 읽기 전용으로 확인했다. 이 작업에서는 그 파일 바이트·줄바꿈과 35개 원장 값을 변경하지 않았다.

상세 자료는 위 후속 보정 작업 경로의 `source-snapshot-check.log`, `documentation-ledger-check.log`, `ledger-row-diff.json`(이번 한 셀 변경), `full-ledger-row-diff.json`(갱신 전 전체 차이), `validate-port.log`, `source-profile-before.json`, `source-profile-after.json`을 따른다. 최종 파일 보존·줄바꿈·행 비교 결과는 같은 위치의 `final-verification.json`에 기록한다.

## 4. 과거 경로를 찾는 방법

자료의 원래 프로젝트를 출처 기록과 manifest로 먼저 확인한다. `docs/upstream/`에 복사된 donor 문서의 경로도 원래 donor를 기준으로 해석한다. 다음 표는 절대 경로와 `<PROJECT>/.local-artifacts/` 같은 과거 표기에도 동일하게 적용한다.

| 원래 프로젝트와 과거 상대 경로 | 기록된 대응 경로 |
|---|---|
| 호환판 `.local-artifacts/sources/<상대 경로>` | `C:\hoi\test\hok-rt56-source-cache\sources\<상대 경로>` |
| 호환판 `.local-artifacts/<그 밖의 상대 경로>` | `C:\hoi\test\hok-rt56-artifact-archive-20261106-01\.local-artifacts\<그 밖의 상대 경로>` |
| 호환판의 과거 `hok-rt56-artifact-archive-20261105-01/.local-artifacts/<상대 경로>` 참조 | 같은 상대 경로를 위 20261106 보관본에서 확인. 확인되지 않은 과거 외부 자료의 이동·복구를 뜻하지 않음 |
| donor `.local-artifacts/<상대 경로>` | `C:\hoi\test\archive-local-artifacts-20261106\original\.local-artifacts\<상대 경로>` |
| donor의 과거 `archive-local-artifacts-20261105/` 원본·추가 사본 참조 | 남은 상대 경로를 보존해 위 20261106 기준본에서 확인. 과거 외부 사본 자체의 이동·복구를 뜻하지 않음 |

호환판의 이 PC에서 확인한 대응은 1.2절의 실제 복사·대조 결과를 따르며, 다른 PC의 자료 위치·존재 여부는 확인하지 않았다. 과거 20261105 경로는 1.1절에서 확인되지 않았으므로 그 당시 외부 자료 자체를 이동·복구했다는 뜻으로 사용하지 않는다. donor의 새 위치는 3절의 별도 기록과 확인 범위를 따른다.

파일명 대소문자와 남은 상대 경로를 보존한다. 예를 들어 호환판의 옛 `.local-artifacts/sources/hok-icons-20260922/`는 활성 외부 캐시의 `sources/hok-icons-20260922/`에, `.local-artifacts/runtime/2026-09-22/`는 호환판 과거 보관소의 `runtime/2026-09-22/`에 대응한다. 역사적 문서·manifest·레시피의 경로를 일괄 치환하지 않고 이 대응표로 찾는다.

필요한 파일이 없거나 해시가 충돌하면 해당 자료의 파일 목록·해시 기록을 확인하고 문제 경로를 보고한다. 확인되지 않은 원본을 찾았다고 주장하거나 출처를 지어내지 않는다. 원본을 임의로 대체·재생성한 뒤 과거 자료인 것처럼 취급하지 않는다. 누락된 자료에 의존하는 작업은 멈추고, 독립적으로 가능한 승인 범위의 작업만 계속한다. 별도로 승인된 신규 이미지 제작은 그 작업의 범위와 출처 기록을 따른다.

## 5. 이미지 제작·수정 전 확인 순서

이미지 작업이 승인된 경우 다음 순서로 자료를 확인한다.

1. 현재 호환판의 완성 이미지, GFX·sprite 연결과 관련 명세·크레딧·manifest를 읽는다. 필요한 원본 이미지·프롬프트·합성 레시피·원출처·기록된 해시를 위 대응표와 현재 프로젝트 자료에서 찾는다. 대화 기억 대신 실제 파일로 작업 기준을 확인한다. 기존 신규 아이콘은 [아이콘 manifest](data/HOK_KOREAN_FOCUS_ICON_MANIFEST.json), [소재 크레딧](HOK_KOREAN_FOCUS_ICON_CREDITS.md), [색상 계획](HOK_KOREAN_FOCUS_ICON_COLOR_PLAN.md)도 대조한다.
2. 중간 출력은 새 `C:\hoi\test\<새 작업 또는 실행 ID>\`에서 만든다. 필요한 과거 입력만 새 작업 폴더에 복사하고 선택한 원래 위치와 해시를 기록한다. 역사적 보관소와 활성 소스 캐시를 새 이미지 작업 폴더로 사용하거나 덮어쓰지 않는다.
3. 과거 스크립트를 재사용하기 전에 내부에 고정된 입력·출력·보고서·미리보기·백업 경로를 읽는다. 과거 입력은 대응표로 찾고 새 출력은 현재 작업의 외부 경로로 설정한다. 저장소의 옛 `.local-artifacts`, 보관 원본·사본, 활성 캐시 또는 업로드 패키지에 이미지 작업 결과를 쓰는 스크립트를 그대로 실행하지 않는다. 레시피를 읽는 행위는 실행이나 추가 이미지 변경을 허가하지 않는다.
4. 승인 범위의 완성 런타임 이미지와 프로젝트 소유 GFX·상대 참조를 호환판에 통합한다. 필요한 선택 원본과 크레딧·manifest는 프로젝트의 관리 문서 위치에 보존하고, 실제 출처·선택한 입력·제작 또는 가공 방법·최종 해시·새 외부 작업 경로를 기록한다. HOK 내부 런타임 이미지 보관, 저작자·사용 조건, 결정적 생성, 상대 참조와 문서화된 RT56·vanilla 공유 이미지 예외를 유지한다.

## 6. 위치 변경 시 갱신

승인된 작업으로 위치가 바뀌면 이 문서의 이전·이후 경로, 원본·추가 사본·활성 캐시의 역할, manifest 위치, 경로 대응표와 실제 검증 결과를 함께 갱신한다. 기존 작업 결과와 새 확인 결과를 구분한다. 상세 실행 이력은 관련 감사 문서에 남긴다.

이 문서 자체의 위치를 바꾸면 [AGENTS.md](../AGENTS.md)의 상대 링크와 필수 열람 조건을 같은 문서 변경에서 갱신한다. 실제 테스트·중간 출력은 외부 작업 경로에 두고, 프로젝트에는 유지할 위치·출처 안내만 둔다. 이 안내는 Workshop 배포 허용 목록에 자동으로 포함되는 파일이나 이미지·게임 코드 변경 권한이 아니다.

## 7. 실제 이동이 별도로 요청된 경우의 절차

이 절은 앞선 문서화 요청에서 정한 일반 절차다. 이후 사용자가 호환판 폴더의 실제 이동을 별도로 요청했으며 그 수행 상태는 1.2절에 기록한다. 절차 문서를 읽는 행위 자체가 다른 자료의 이동이나 정리를 승인하지 않는다. donor와 호환판 중 실제 대상, 이동할 하위 범위, 목적지를 먼저 구분하며, 이미 외부 보관된 donor 자료는 호환판 정리 대상으로 포함하지 않는다.

1. **원본과 목적지 확정:** 절대 경로와 자료 역할을 기록한다. 호환판 `sources/`의 목적지는 코드가 참조하는 `C:\hoi\test\hok-rt56-source-cache\sources\`와 일치해야 하며, 일반 산출물은 별도 외부 archive로 구분한다. 목적지에 기존 자료가 있으면 덮어쓰거나 합치지 말고 기존 목록·출처와 비교한다. helper·목록·보고서·백업은 `C:\hoi\test\<해당 이동 작업 ID>\`에 두고 실제 실행 전 모든 출력 경로를 확인한다.
2. **원본 목록과 복사:** 파일별 상대 경로·대소문자·크기·SHA-256·기존 수정 시각, 빈 디렉터리를 포함한 디렉터리 목록과 합계를 외부 manifest에 기록한다. 원본을 유지한 채 상대 경로와 구조를 보존해 복사한다. 기존 그림 원본·레시피·크레딧·소스 입력·고유 증거를 제외하거나 재생성하지 않는다.
3. **원본·사본 대조:** 파일 목록·수·개별 크기·합계·SHA-256과 디렉터리 구조를 대조하고, 제거 직전 원본 변경 여부도 재확인한다. 이름·수량·총바이트만 같은 상태를 내용 일치로 처리하지 않는다. 불일치 또는 누락이 있으면 원본을 보존하고 원인과 미완료 항목을 기록한다.
4. **제거 전 문서 갱신:** 이전·이후 경로, 원본·보관본·활성 캐시 역할, manifest와 비교 기록 위치, 실제 확인 범위를 기록한다. 이때 상태는 **복사·대조 완료 / 원본 제거 대기**이며, 이동 완료로 쓰지 않는다. 과거 문서·레시피·manifest의 경로는 중앙 대응표로 해석하고 일괄 치환하지 않는다.
5. **지정 원본 제거:** 실제 이동 요청에 포함된 원본만 제거한다. 재귀 제거 전 최종 절대 경로가 확정된 대상 내부인지 확인하고, 대조가 끝난 보관본·활성 캐시나 다른 프로젝트를 제거하지 않는다.
6. **제거 후 확인과 완료 기록:** 목적지의 파일·해시와 지정 원본의 부재를 확인한 뒤 문서 상태를 완료로 갱신한다. 실제 시각·수량·바이트·검증 범위와 미해결 사항을 과거 결과와 구분해 남긴다. 원본이 남았거나 재확인하지 못했다면 미완료로 기록한다.

과거 이미지 제작 스크립트는 옛 절대 경로와 저장소 기준 상대 경로를 가질 수 있다. 예를 들어 donor의 `korean-focus-icon-colors/build-colors.ps1`은 옛 `.local-artifacts/korean-focus-icons/` 입력을 절대 경로로 참조하고, `korean-second-wave-icons/build-icons.ps1`은 저장소 기준 입력을 사용했다. 보관본의 원문은 유지하고, 재사용이 별도로 요청되면 새 외부 작업 폴더의 복사본에서 입력·출력 경로를 조정한다. 이동 문서화만으로 제작 스크립트를 실행하거나 변경하지 않는다.

파일 보관 무결성, 생성기의 입력 접근 여부, HOI4 게임 동작은 서로 다른 확인이다. 앞선 문서화 단계의 미수행 범위와 이후 실제 파일 대조는 1.1절·1.2절로 구분하며, 파일 이동의 완료 여부를 게임 검증 통과와 동일시하지 않는다.
