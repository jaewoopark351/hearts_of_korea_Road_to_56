# HOK×RT56 변경 영향 범위와 누락 방지 절차

현지화·표식/변수 표시·주/프로빈스 참조를 검토하거나 변경할 때 적용한다. 변경과 연결된 사용처를 추적하고 각 항목의 처리와 확인 범위를 남긴다. 이 절차의 도입은 기존 콘텐츠의 전수 감사나 오류 해소 판정이 아니다.

## 적용과 자료의 역할

- 먼저 [AGENTS.md](../AGENTS.md)의 최신 요청·작업 모드·읽기 전용 입력·외부 산출물 규칙을 적용한다. 검토는 응답으로 보고하고 문서 전용은 요청된 지침·기록만 수정한다. 이 문서는 코드 변경·테스트·게임 실행·정리·Git 변경·업로드를 승인하지 않는다.
- 표시 내용이나 현지화 사용처를 다루기 전에 [호환판 현지화 스킬](skills/hok-rt56-localisation-review/SKILL.md)을 읽는다. 이름·설명 외의 조건·효과·취소·선택지·해금 안내와 활성 번역도 포함한다.
- 주·프로빈스 대상이나 지역 범위를 다루기 전에 [호환판 주 참조 스킬](skills/hok-rt56-state-reference-review/SKILL.md)을 읽는다. 우리가 바꾼 지도, RT56 갱신, 지도는 유지하는 코드 정렬 모두 해당한다. 지역 설명과 코드가 함께 관련되면 두 스킬을 적용한다.
- 소유권·지도/언어 계약·원본/호스트 핀을 판단할 때는 [문서 인덱스](README.md)에서 관련 최신 ADR·구현 기록을 먼저 찾는다. `docs/upstream/`의 donor 문서·스킬은 보관된 출처이며 활성 로컬 지침을 대신하지 않는다. 원본에서 새 지침을 가져올 때는 차이와 출처를 별도로 기록한다.

`AGENTS.md`는 적용 조건과 공통 의무, 두 스킬은 분야별 절차, 기존 ADR·대응표·구현 기록은 확정된 의도와 검증 이력을 맡는다. 스킬의 정본은 Git 추적 대상인 `docs/skills/`에 두고 AGENTS의 조건부 필수 읽기로 적용한다. 이 저장소에서 제외하는 `/.agents/`의 자동 탐색이나 사용자 전역 스킬 설치를 전제로 삼지 않는다. ID 표·번역 원문·과거 검사 수치를 스킬에 중복 고정하지 않는다. 실제 오류 로그 검토에는 AGENTS의 로그·증거 계층 규칙을 추가로 적용하며 donor 로그 스킬의 자동 적용을 가정하지 않는다.

## 1. 작업 기준과 조사 범위

요청 범위·금지 사항, 호환판 브랜치/HEAD·기존 변경, 영향 기능과 ID를 정한다. 구현·호환성 판정 시에는 정확한 HOI4·HOK donor·RT56 manifest/해시·물리 모드 경로·로드 순서·언어·DLC를 기록하고 작업 후 드리프트를 확인한다. 문서 전용으로 기존 기록을 읽었다면 현재 설치나 런타임을 새로 검증한 것으로 쓰지 않는다.

호환판 출력, HOK 의도, 정확한 현재 RT56 정의, 대상 바닐라 schema를 구분해 비교한다. RT56 world/shared content를 보존하고 승인된 HOK delta를 병합한다. 관련 원본 정의는 ADD·USE_RT56·THREE_WAY_MERGE·OVERRIDE·BINARY_MERGE·ASSET_COPY 중 기존 분류와 provenance를 확인한다. 생성 출력의 수정이 승인되면 해당 계층의 source/lock·생성기와 후속 덮어쓰기 순서까지 범위에 포함한다. 과거 입력을 현재 출력에 맞춰 덮어쓰거나 검사 핀을 느슨하게 하지 않는다.

조사 단위는 기능·호출부·분기다. 변경 키와 이전/현재/후속 지리 ID에서 공용 helper·역호출자·관련 대체 분기와 상속되는 RT56/바닐라/DLC 코드로 추적한다. 동적 키·scope·매개변수·지역 그룹은 실제 인수와 확장된 문맥을 확인한다. 숫자 검색 결과나 검색 부재만으로 범위를 닫지 않는다.

범위는 변경 위험에 맞춘다. 문구 한 키의 축약은 해당 호출자·언어별 덮어쓰기·문자열 보존을 확인하고, 주 분할/호스트 지도 갱신은 옛/새 ID·province 부모 주·조건과 보상·영토/코어·외국 연결·대체 경로를 함께 다룬다. 모든 문구 변경에 전체 지도 감사나 장기 실행을 요구하지 않는다.

## 2. 의도와 현재 참조의 대조

먼저 기대하는 표시·지역·동작과 근거를 정한다. 현재 코드의 숫자를 그대로 기대값으로 삼지 않는다. 이름·주석·주 파일명과 실제 지리는 다를 수 있다.

- 현지화는 **필요한 공개 정보 / 이미 안내된 내부 처리 / 확인된 비표시 내부 처리**를 구분한다. 원시 ID 노출과 항목 전체의 부재도 따로 판단한다. 양 채널에 같은 키가 있어도 필요한 키가 함께 빠질 수 있다.
- 호환판 한국어/영어의 키·수치·대상·토큰과 의미를 대조한다. 원본의 양 채널 한국어 본문 정책을 가져오거나 실제 번역 본문의 동일 바이트를 요구하지 않는다. 활성 번역·파일 교체·`replace_path`가 최종 정의에 주는 영향도 확인한다.
- 지도 기준은 **현재 RT56 + 승인된 HOK 지도 변경**이다. state·province·strategic region·표시명 키를 구분하고 실제 부모 주와 의도 지역을 대조한다. 주가 존재해도 다른 지역일 수 있다. 이전·통제·코어·보상은 별도로 판단한다.
- 기존 ID 이관·분할 대응표와 기능별 예외를 따른다. 주 분할 후 고정 보상을 후속 주마다 복제하지 않는다. 영토 범위를 바꾼 경우 단순 참조 수리라도 행동·균형 영향은 별도로 기록한다.
- 같은 helper라도 호출국·scope·인수·DLC/국가 존재 분기가 다르면 따로 검토한다. 동등 경로로 묶을 때는 근거와 포함 ID를 남긴다.

## 3. 항목별 처리 대장

| 처리 | 필요한 근거 |
|---|---|
| 수정 | 입증된 불일치·수리 범위·실제 위치. 제안과 적용을 구분한다. |
| 의도적 유지 | 원래 의도·현행 정상 동작·기존 저장 분기 등의 유지 근거. 미확인을 정상으로 표시하지 않는다. |
| 제외 | 이번 범위에서 제외하는 이유와 알려진 결함/정상/미확인 상태. |
| 미확인 | 부족한 근거·남은 결정·다음에 필요한 관측. 추측으로 대상을 바꾸거나 조건을 숨기지 않는다. |

기존 관련 ADR·계획·구현 기록의 대장을 필요한 만큼 갱신한다. 검토 전용이면 파일을 만들지 않고 응답으로 보고한다. 역사적 결과를 새 소스에서 재확인한 것으로 고치지 않고 날짜·소스·후속 결과를 구분한다.

| 기능·ID/키 | 파일·호출부·분기 | 기대 표시·지역·규칙 | 현재 참조·출처·생성 소유권 | 처리·근거 | 확인 단계·결과·증거 | 남은 항목 |
|---|---|---|---|---|---|---|
| 관련 사용처 | 실제 위치 | 근거 있는 기대값 | 원본/호스트/포트 구분 | 수정·유지·제외·미확인 | 확인·실패·미검증 | 필요한 후속 작업 |

키 수·사용처 수·기능 수·검색 행 수·검사 항목 수는 별도로 보고한다. 하나의 키가 여러 곳에서 쓰이는 사실을 여러 고유 결함으로 합산하지 않는다.

## 4. 확인 단계와 완료 판단

| 단계 | 입증하는 범위와 한계 |
|---|---|
| 소스 | 참조·scope·언어·토큰·인코딩·분기·의도 대응. 실제 등록·UI·효과 실행을 대신하지 않는다. |
| 로드·UI | 해당 구성의 유효 파일·언어·표시·치환·색상·접근 가능 여부. 효과 지급을 대신하지 않는다. |
| 실제 효과 | 해당 조건에서의 대상·비용·보상·취소. 강제 효과·합성 seed와 정상 진행을 구분한다. |
| 저장 | 관측한 값·표식·타이머의 보존 범위. 새 저장 재로드와 변경 전 저장 호환·실제 기간 경과를 구분한다. |

필수 확인은 요청과 변경 위험에 맞춰 미리 정한다. 지역 조건이면 부분 소유/통제·후속 주 미보유, 표시면 숫자 경계·가용/취소·각 선택지, 영속 데이터면 관련 저장 값을 다룬다. 실행이 승인되면 전체 프로세스 재시작과 실제 구성에서 확인하고, RT56 호환성 주장은 해당 RT56 대조군과 비교한다. 언어/DLC/장기 AI/멀티플레이의 미검증을 해당 호환성 보장으로 바꾸지 않는다.

범위 내 사용처마다 처리 근거와 필수 확인의 실제 결과가 있어야 한다. 준비된 검사·종료 코드·조용한 로그·원본 실행 결과만으로 포트 완료를 선언하지 않는다. 최초 실패와 후속 통제 결과를 보존하며 필수 항목이 남으면 **구현 반영 / 검증 대기**, 의도가 미해결이면 **판단 대기**로 한정한다. 범위 밖 미검증과 이번 작업의 미완료를 구분한다.

실제 시험·진단을 수행할 때만 먼저 `C:\hoi\test\<task-or-run-id>\`를 정하고 모든 helper·보고서·증거 사본을 그곳에 둔다. 활성 source cache와 보관된 재현 입력은 시험 출력이 아니다. 발견한 저장소 시험 자료는 위치·유형·대략 크기를 미결 정리로 보고하며, 정리 승인 없이 옮기거나 지우지 않는다.
