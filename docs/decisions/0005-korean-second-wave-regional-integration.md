# ADR-0005: 2차 한국 업데이트의 만주 지역과 환제국 거점

날짜: 2026-09-23. 상태: **채택 — 결정론적 변환 구현 및 한정된 정적 검사 완료, 엔진 실행 미검증**.

## 범위와 기준선

사용자가 [2차 이식 계획](../plans/2026-09-23-korean-second-wave-port-plan.md)을 인용하고 `AGENTS.md`, `/docs`를 읽어 구현하도록 지시한 범위의 지역 대응 결정이다. HOK `be5fb40dbd8de33e5adbf65e808bcb0e8c283560`의 만주 M1–M4 20개 중점·사업 4개와 환제국 H1–H4 14개 중점 조건에 한정한다. 기존 만주 통합, 지도, 주 역사, 국가 소유권, province/state ID를 변경하지 않는다.

계획의 대상은 HOI4 `1.19.3.0.c01a`와 RT56 manifest `7475007536894105204`이다. 정확한 이번 구현 배치의 실행 환경·Git 상태는 별도 구현 기록에서 다루며, 이 문서는 소스 지리에 대한 결정을 기록한다. 설치된 vanilla의 해당 8개 주는 donor에 별도 정의가 없고, 호환판에도 이 문서의 만주 15개 주에 대한 별도 state 정의가 없다. 따라서 donor 환경의 vanilla 주와 RT56 host 주를 직접 비교했다.

분류는 한국 중점 파일의 기존 `OVERRIDE` 내부 호환 변환, 새 만주 결정 파일의 `ADD`에 적용하는 호환 변환, 기존 ID를 보존한 새 한영 현지화 파일의 `ADD`이다. 새 지역 modifier 12개는 주 자체의 소유·완전 통제·항복·M2 정부 조건을 검사하므로 donor bytes를 그대로 사용한다.

## 확인된 문제

`CONFIRMED`: donor의 원본 주 `328`은 39개 province, RT56의 같은 ID는 16개이다. 원본 `714`는 28개, RT56은 4개이고, 원본 `717`은 30개, RT56은 21개이다. 같은 숫자를 유지하면 정책의 수혜 지역과 거점 조건이 축소되거나 다른 지역으로 바뀐다. 단순히 모든 정책에 기존 만주 15개 주를 넣으면 보상 지역·요구 영토가 확대된다.

`CONFIRMED`: RT56 경계는 원본 주의 단순 분할이 아니다. 주 사이의 province 이동도 있다. 따라서 지도 자체를 고치지 않는 한 원본의 경계를 주 단위 효과로 정확하게 복원할 수 없다. 아래 선택은 **RT56 행정 경계에 맞춘 명시적 근사 대응**이며 원본 영토의 완전한 보존이라는 주장은 하지 않는다.

## 결정

기존 포트가 통합하는 만주 15개 주를 8개 원본 지역에 한 번씩 배정한다. 각 RT56 주의 기존 province 중 어느 원본 지역의 province가 가장 많은지를 기준으로 하고, 정책 설명·행정 중심지·실제 비트맵 중첩을 함께 확인한다. 모든 행에서 최다 province 대응이 유일하므로 임의 동률 해소는 없다. 신규 RT56 province는 해당 host 주에 남는다. province 개수 기준을 면적 기준·인구 기준·산업 생산 비율과 동일시하지 않는다.

| 원본 지역 | 채택한 RT56 대응 주 | 사용 |
|---|---|---|
| 716 | 716 | 환제국 거점 |
| 745 | 745 | 환제국 거점 |

M1/M2/M4는 **328·941 두 주 전부**, M3는 **328·941·714·944·945·717·942·943 여덟 주 전부**를 소유하고 완전히 통제해야 한다. M3는 위 순서로 원본의 328 → 714 → 717 효과 순서를 확장한다. 비용, 기간, modifier 값, 연구 보상, 정치력, 안정도, AI 값은 유지한다.

환제국 조건은 원본의 여덟 대안을 그대로 유지하는 `OR`이며 각 대안 안에서 해당 대응 주 **전부**의 소유·완전 통제를 `AND`로 검사한다. 예를 들어 `328` 대안에는 `328`과 `941`이 모두 필요하고 `717` 대안에는 `717·942·943`이 모두 필요하다. `941`만 확보한 상태는 거점이 아니다. 원래 단독 지역인 `745`는 계속 단독 대안이다. 전체 15개 주를 모두 요구하거나 15개 중 하나만 있으면 되는 조건으로 바꾸지 않는다.

H의 거점 상실은 중점의 기존 `cancel_if_invalid`·`continue_if_invalid` 조건을 통해 진입·진행에 영향을 준다. H 국민정신의 제거 조건은 이 결정으로 바꾸지 않는다. M 사업의 일일 제거·정부 상실 규칙을 H 정신에 추가하지 않는다.

실제 면적은 donor `map/provinces.bmp`·`definition.csv`와 RT56의 해당 파일을 같은 픽셀 좌표에서 비교한 것이다. 좌표계·bitmap 크기는 동일했다. 이 면적은 실제 게임 관측이 아닌 파일 분석이다. 파일의 province 번호 중첩과 물리 경계 중첩은 다르며 3913 사례가 그 차이를 보여준다.

- **국내성 9803**은 원본 328에서 RT56 941로 옮겨졌다. M4의 중심지를 잃지 않으려면 941이 필요하다. 941은 17개 중 9개가 원본 328이고 실제 면적도 51.82%로 가장 많이 중첩한다. 기존 `KOR_rebuild_guknaeseong_as_new_city`에 대한 별도의 포트 처리는 변경하지 않는다.
- 원본 328의 승점 **4572**는 RT56 328에 남는다. 다른 원본 승점 **하얼빈 10433**은 RT56 943에 있다. 943을 도시 하나 때문에 M1/M2/M4에도 포함하면 23개 중 19개는 원본 328 밖인 주 전체로 제도가 확대된다. 하얼빈은 여러 지역을 통합한 M3에 포함된다. 따라서 328의 새 지방·도시 제도는 328·941로 고정하고 이 경계 차이를 기록한다.
- 943은 원본 717의 province가 11개로 가장 많으나, 면적은 원본 714가 39.47%, 원본 717이 37.20%, 원본 328이 17.80%이다. **province 기준의 717 배정**을 채택한다. 면적 기준 714 배정과 달리 환제국의 714/717 대안 묶음이 달라지지만 M3의 전체 여덟 주 집합은 동일하다. 어느 기준이 역사적으로 유일한 답이라는 주장은 하지 않는다.
- 원본 714의 중심지 12485는 944, 1693·7848은 945이고 세 주를 함께 포함한다. 원본 717의 10463은 717에 남는다. 원본 716의 11771·11764는 716, 원본 715의 11836은 715, 원본 610의 11801은 610에 남는다. 761의 네 승점 10612·1776·13150·12690은 761에 남는다.

M1/M2/M4의 최종 33개 province 중 원본 328과 같은 ID는 25개, 다른 원본 지역에서 추가되는 ID는 `836, 3839, 3970, 6860, 6910, 6918, 6981, 9854` 여덟 개다. 원본 328 중 제외되는 14개는 `887, 927, 3888, 3913, 3929, 4503, 6868, 6905, 7591, 9782, 9866, 10433, 11781, 12412`다. 이 차이는 고정된 host 주 경계를 따른 결과이며 숨기지 않는다.

M3는 원본 97개 province 중 87개 ID가 유지되고, 대상은 RT56 총 105개 province다. 제외되는 원본 10개는 `887, 1502, 3888, 4503, 4876, 6868, 6905, 7894, 9866, 11781`; 추가되는 18개는 `836, 3815, 3839, 3970, 5427, 6860, 6910, 6918, 6981, 9854, 10541, 12537, 13273, 13274, 13275, 13276, 13279, 13280`이다. 숫자 일치 개수는 같은 픽셀·인구·공장 가치의 보존을 뜻하지 않는다.

## 수명과 범위 변환

[지역 변환 모듈](../../tools/korean_second_wave_geography.py)은 기존 ID 및 국경 통합 변환 뒤에 실행된다. 텍스트 전체를 파싱 후 재출력하지 않고, 다음 허용 블록만 원문 형태로 복제한다.

1. M 20개 중점의 `available` 및 I 지급·II 교체 보상에서 지정된 주 범위를 확장한다. 원본 효과의 순서와 각 주 안의 `ROOT` 의미를 유지한다.
2. M 4개 결정의 가용 조건, `highlight_state_targets`, 시작 시 II 복구·90일 효과, `cancel_trigger`, 취소·정상 종료 제거에 같은 지역 집합을 사용한다. 어느 한 target 주의 소유 또는 통제를 잃으면 원본 OR 취소 조건의 해당 항이 참이 되어 사업 전체를 취소한다.
3. M3 취소·종료는 여덟 주 전체의 기간제 효과만 제거한다. 각 주의 유효한 영구 제도는 donor의 기존 자체 수명 규칙에 맡긴다. 소유/통제를 잃은 주의 제도는 기존 `remove_trigger`가 제거하며, 다른 유효한 주의 영구 제도까지 지우는 효과를 추가하지 않는다. 재착수는 모든 대상 주를 다시 확보한 뒤 그 대상의 II를 복구한다.
4. H 14개 중점의 원본 거점 OR만 대응 그룹별 AND로 확장한다. 원본의 독립·항복·내전·세계질서·평시·서울 등 나머지 조건과 국민정신은 유지한다.
5. 한영 `HOK_KOR_manchurian_followup`의 M 중점 설명 20개와 결정 설명 4개에 `$STATE_<ID>$`로 최종 대상 및 전 지역 소유·완전 통제 조건을 덧붙인다. 기존 영어 파일 본문이 한국어인 원본 계약을 유지하며 BOM·locale header·기존 키·기존 설명을 보존한다. 두 파일의 새 contributor note는 header 바로 뒤에서 동일하다.

일괄 모든 주 순회, 새 `on_action`, 새 persistent ID, 새 지도 정의는 추가하지 않는다. 주에 적용되는 비율 modifier의 값도 분할 수만큼 더해 조정하지 않는다. 각 대응 주에 원본과 같은 비율을 적용한다. 실제 총생산·인구·공장 효과는 RT56 host의 구성 차이에 영향을 받으며 별도 임의 재조정은 하지 않는다.

## 거절한 대안

- **같은 state 숫자 유지:** RT56 분할 이후 정책 범위와 국내성 중심지가 누락된다.
- **정책마다 만주 15개 주 전부:** 원본의 지방 정책이 전체 만주 정책으로 확대된다.
- **H에서 15개 중 하나만 소유:** 기존 원본 지역의 일부 조각만으로 해당 지역 전체 조건을 충족한다.
- **H에서 15개 모두 소유:** 원본의 대안 OR를 전체 AND로 바꾼다.
- **작은 중첩까지 모두 포함한 원본별 AND:** 여러 원본 지역에 걸친 광범위한 요구가 발생하고 원본 610의 두 province 때문에 기존 통합 밖의 609까지 요구한다. 현행 host 지역을 기준으로 새 콘텐츠를 이식하는 범위를 넘는 보수적 재설계가 된다.
- **지도 경계·state ID 재작성:** 이 작업의 범위 밖이며 RT56 세계를 훼손할 수 있다.

## 고정 입력과 검사

입력 28개의 파일별 SHA-256은 모듈의 `GEOGRAPHY_HASHES`에 고정했다. vanilla 주 8개, RT56 주 16개(제외 근거 609 포함), donor·RT56 bitmap 및 definition 4개다. donor에 같은 ID의 새 state override가 추가되어도 검사가 실패한다. 원본 중점·결정·현지화 입력 자체는 상위 second-wave source lock에서 고정한다.

핵심 바이너리 입력:

| 파일 | SHA-256 |
|---|---|
| donor `map/provinces.bmp` | `A00EC0E8C18E9F405FC7E7EA59A77848870F03C79E9E5F78CF6E12272D867600` |
| donor `map/definition.csv` | `0DD53CE40928593FA59C4661863EA4257BDC1E3EC8FDA6D3F790C319A2F8F228` |
| RT56 `map/provinces.bmp` | `B41B67B844407C70EB393E6979DCB8EE718BA76596ECEB2A9CCD38171156580F` |
| RT56 `map/definition.csv` | `005BB6052AEDBAA85FFE4607B21398A33055624A78C2F822F116AE895B58393E` |

전체 province 목록·승점·교차 목록·면적 행렬의 작업 증거는 배포하지 않는 `.local-artifacts/2026-09-23-second-wave-geography/province-overlap.json`에 저장했다. 위 표는 핵심 결정 근거를 영구 문서로 남긴 것이며 로컬 원시 자료가 없어도 선택을 읽을 수 있다.

실제로 실행한 한정 검사:
